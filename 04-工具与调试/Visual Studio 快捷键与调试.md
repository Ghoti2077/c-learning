# Visual Studio 快捷键与调试

- 日期：2026-09-13
- 标签：`#VisualStudio` `#调试`

> **一句话总结**：`F5` 是"直接跑"，`F11` 是"一行一行跑（遇到函数会钻进去）"，`F10` 是"一行一行跑（不进函数）"，`F9` 是"在这儿停一下"。

## 快捷键表（先用熟这几个就够）

| 快捷键 | 名字 | 干啥的 |
|---|---|---|
| **F5** | 开始调试 | 直接跑到结束；有断点就在断点停 |
| **Ctrl+F5** | 开始执行(不调试) | 直接跑完，**控制台窗口不会自动关**，看结果用它 |
| **F9** | 切换断点 | 光标那行打/取消一个红点，程序跑到红点会停下来 |
| **F11** | 逐语句 | 一次走一行，**遇到函数会跳进函数内部** |
| **F10** | 逐过程 | 一次走一行，**不跳进函数**，把它当成一行走完 |
| **Shift+F5** | 停止调试 | 跑飞了/卡住了就按它 |

## 笔记修正：F11 不是"逐行运行程序"

我原来记的是「F11 可以逐行运行程序」。准确说法是：

- **F11 叫"逐语句"（Step Into）**：它确实是一行一行走，但它是**调试**用的，而且遇到函数调用会钻进去。
- 想单纯"把程序跑起来看结果"，应该用 **Ctrl+F5**（跑完窗口留着）或 **F5**（调试模式跑）。
- 想一行一行看代码怎么走、但不想钻进 `printf` 那些库函数里，用 **F10**。

> 比方：F11 是"连别人家里也进去看一圈"，F10 是"站在门口看这家人干完事就往下走"。刚开始调自己写的代码，F10 更省心——不然会一头钻进 printf 里出不来（按 Shift+F5 可以逃出来）。

## 调试基本动作（三连）

1. 在可疑的那一行按 **F9** 打红点（断点）
2. 按 **F5** 跑，程序会在红点停住
3. 停住后按 **F10** 一行一行看，鼠标悬停在变量上就能看到它当时的值

> 嵌入式提醒：调试（断点 + 单步 + 看变量）是嵌入式工程师吃饭的家伙。单片机上没法随便 printf，全靠调试器和示波器看内部状态，所以这个习惯现在就要练。

## 看函数长什么样（新手超好用的一招）

- **F12**（或按住 **Ctrl** 用鼠标点函数名）：跳到它的**定义/声明**。想看 `printf` 到底咋声明的，光标放 `printf` 上按 **F12** 直接跳进 `stdio.h`，看完按 **Alt+←** 跳回来。
- **Shift+F12**：反过来，看"谁用了这个函数"（找引用）。
- 好处：不用背、不用猜，**不确定某函数要几个参数，直接跳进去看**。以后看单片机的库（比如 HAL_GPIO_Init）全靠这一招。
