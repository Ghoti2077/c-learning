# 📝 代码版本账（每版记一笔）

> [!quote] 为什么要记这个（2026-11-19 他自己的原话）
> 「我最后我东补补，西补补，把它补回来了……我觉得以后我每一次写完代码自检的时候都要记录一次，这样就能知道我每一版到底错在哪里，改了哪里。不然就像现在，我只记得我比较大的错误，小的错误我都已经记不太清了。」

道理跟 `git log` 一样：**只记大错 = 下次还会掉进同一个坑，因为你想不起它是怎么来的。**
记的代价是每版两行；不记的代价是每次重来一遍。

## 模板（复制这几行，改了就填，没改就写「没改」）

```text
### 题目 PXXXX  标题  （日期）
| 版本 | 这版我改了什么 | 跑出来什么 | 真因（一句话） |
|---|---|---|---|
| v1 |  |  |  |
| v2 |  |  |  |
| v3 |  |  |  |
```

**规矩三条：**
1. **提交前先写 vN 那一行**，别等 AC 了再补 —— AC 之后人的记忆会自动把过程抹平。
2. 「真因」写不出来就先空着，标 `?`，等我或者明天自己补 —— 空着也比不写强。
3. 只错一次的小错也要记（一个字母、一个下标），小错才是反复出问题的那些。

## 范例：P5732 杨辉三角（2026-11-19，他本人三版经历）

| 版本 | 这版我改了什么 | 跑出来什么 | 真因（一句话） |
|---|---|---|---|
| v1 | `int a[10000][10000]` | 根本输出不来 | 1 亿个 int = **381 MB**，全塞在栈上，栈装不下 |
| v2 | 改写成 `int a[n][n]`（变长数组） | 输出能出，但从某一行开始**全是错的数** | VLA **不能初始化**，`a[i-1][i]` 那格没被清过 → 读到垃圾值，一代错、代代错 |
| v3 | 换成 `int a[1000][1000] = {0}` | AC | 空格子被清成 0，跨行读到的那个「不存在的列」也成了 0 |

> [!warning] v3 还留着一个坑（已实测，2026-11-19）
> `int a[1000][1000]` = **3.8 MB** 的局部数组。Windows 栈默认 1MB，原样编译跑起来是
> `rc=-1073741571`（`0xC00000FD`，栈溢出），连第一个 `printf` 都没到。洛谷是 Linux、栈 8MB 才过。
> 本题 n ≤ 20，**正解是 `int a[21][21] = {0}`** —— 或者把它挪到 `main` 外面（全局的不占栈，这块等讲到存储区再细说）。

## 记在哪
- 一题一个 `### 题目` 小节，全放这一个文件里，按日期往下加（最新的在最下面）。
- 写完顺手把这题「真因」里值得长期记的知识点，抄一行进 `📌 抽查池（间隔复习）.md`。
