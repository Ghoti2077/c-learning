### P1425 小鱼的游泳时间 ✅（他自己写出来的，不是抄的）

### P1085 不高兴的津津 ✅（AC，但有越界）
- 他的代码：`int num1[7], num2[7];` + `for(i=1;i<8;i++) scanf("%d %d",&num1[i],&num2[i]);`
- **真 bug：越界写**。`int a[7]` 合法下标 0..6，他写到 `num1[7]`/`num2[7]`（第 8 格，不存在）。洛谷照样 AC。
- 实测证据：`scratch/oob.c` 在他代码后面加 `canary1=1111, canary2=2222`，跑完 `canary2` 变成 **2** → 越界写真的砸到旁边变量。`sizeof(num1)=28`，`&num1[7]-&num1[0]=28`（正好越出去一格）。
- 三处可瘦：① 数组完全没必要（读完当场用掉，从不回查）② `t>8` 被 `t-8>max` 包住了，多余 ③ `num1[i]+num2[i]` 算了三次。
- 瘦身版（他自己选的，仅供参考）：
  `int max=0, date=0; for(int i=1;i<=7;i++){ int s,e; scanf("%d %d",&s,&e); int t=s+e-8; if(t>max){max=t;date=i;} } printf("%d", date);`
- **教学点**：`max` 初值 0 同时兼了"默认答案"，所以最后的 `if(max==0)` 可以彻底不要，直接打印 `date`。

### P5720 一尺之棰 ✅（2026-11-11 20:2x）
- 官方题面（已核，`luogu.com.cn/problem/P5720` + 镜像）：第一天长 a，**从第二天开始**每天除 2 向下取整，问第几天变 **1**；样例 `100 → 7`；数据 `1 ≤ a ≤ 10^9`。
- 他的代码：`int num=1; while(length>1){ length/=2; num++; }` —— **完全正确**，本地 `100 → 7` 与官方样例一致，`-Wall -Wextra` 0 警告。
  - `num=1` 从 1 起正好对上"第一天就算一天"这个坑。
  - `10^9 < 2^31-1 = 2147483647` → **int 够用**，不用 long long。
- 只提风格：① `int length = 0;` 的 0 是废初值 → 直接 `int length;` ② `num` 改 `day` ③ `length = length/2` → `length /= 2` ④ 缩进统一。
- 教学点：**初值要么有意义（如 P1085 的 max=0 兼默认答案），要么别给**。

### P5727 冰雹猜想 ✅（2026-11-11 20:5x）
- 题面核对（官方）：n≤100，奇数 ×3+1、偶数 ÷2 到 1，**从最后的 1 开始倒序输出**；样例 `20 → 1 2 4 8 16 5 10 20`。
- 他的做法：`num[200]`，`i=0` 起，先 `i++; num[i]=n;`（所以数据占 1..i，`num[0]` 空着）；循环里 odd/even 各自 `i++; num[i]=n;`；最后 `printf("1")` 手动打序列尾巴，再 `for(;i>1;i--) printf(" %d",num[i-1]);`。
- **对拍结论：n=1..100 全部与"标准解"逐字符一致（100/100，0 处不同）**。n=1 也对（只输出 `1`）。
- 可改（都不影响正确性）：① `i` 改名 `cnt`/`len` ② 两处 `i++; num[i]=n;` 重复 → 把 if/else 只用来"变 n"，统一写成 `num[++i] = n;` ③ `num[0]` 空着没问题，但要知道这是"下标从 1 起"带来的 ④ `printf("1")` 是硬编码（靠"序列末尾必是 1"），通用写法是 `for (i = cnt-1; i >= 0; i--)`。

### P5732 杨辉三角 ✅（2026-11-19 18:0x）

- 链接已实测打开：`https://www.luogu.com.cn/problem/P5732`，标题「P5732 【深基5.习7】杨辉三角」，n(1≤n≤20)。
- **一版过**。他的思路：先把每行 `a[i][0]=1`、`a[i][1]=i` 预填好，再 `a[i][j]=a[i-1][j-1]+a[i-1][j]`（j 从 1 到 i）。
- **隐患（已讲）**：`int a[1000][1000]={0}` 是 3.8MB 的局部数组 → Windows 实测 `rc=-1073741571`（`0xC00000FD` 栈溢出），洛谷 Linux 栈 8MB 才勉强过；改 `int a[21][21]={0}` 输出正常。
- **隐藏依赖（已讲）**：`j` 最大取 `i`，会读 `a[i-1][i]`，上一行没这一列；它能算出 1 全靠开头 `={0}` 把那片格子清成 0。
- 实测留档：`scratch/yh.c`（原版）、`yh21.c`（改小）、`runyh.bat`。
- **他自曝「提交过很多次」**：v1 `int a[10000][10000]`（381MB，跑不起来）→ v2 `int a[n][n]` VLA（不能初始化，`a[i-1][i]` 取垃圾值，后面全错）→ v3 `int a[1000][1000]={0}` AC。三版账见 [[📝 代码版本账（每版记一笔）]]。
