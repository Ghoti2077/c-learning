## 1. ⚠️ 这次暴露的三个薄弱点（最重要的一节）

| 薄弱点 | 我当时的错误 | 正解 |
|---|---|---|
| **宏是文本替换**，不是"先算好再替换" | `F(5+1)` 算成 `4×(5+1)=24`，外层括号又提前拆 → 得 **30** | `F(5+1)` 原文贴进去 = `((3+1)*5+1)` = **21**（`n` 没有括号保护，`+1` 在乘号**外面**）→ `z = 2*(3+21) = 48` |
| **位号从 0 数**，不是"第一个比特" | 以为"第一个比特"叫 bit1 | **最右边那格 = bit0**（权重 2⁰=1），最左边 = bit7（2⁷=128）。8 位就是 **bit0 ~ bit7**。位号 = 「2 的几次方」 |
| **`1 << n` 没有直觉** | 看不懂 `1<<4` 为什么是 `0x10` | `<<` = "**在 1 后面添 n 个 0**"。十进制添一个 0 ×10，二进制添一个 0 ×2 → `1<<4` = `1 0000` = 16 = `0x10`。**`1<<n` 里的 n 就是位号** |

**还卡过一次的**：二进制 → 十六进制的换算。规矩只有一条：**4 个二进制位 = 1 个十六进制位**（从右往左每 4 位划一刀）。
`1<<4` = `0001 0000` → `0001`=1、`0000`=0 → `0x10`。

## 2. ★ 位操作三件套（单片机全靠它）

> 正式课程《位运算》那一章还没学到（L33 时我"先欠着"），这里先存着。

### 2.1 四种常用操作

| 想干什么 | 写法 | 口诀 |
|---|---|---|
| 第 n 位置 **1** | `reg \|= (1 << n)` | 或等于，上 1 |
| 第 n 位清 **0** | `reg &= ~(1 << n)` | 与反，抹 0 |
| 第 n 位**翻转** | `reg ^= (1 << n)` | 异或，反一下 |
| **读**第 n 位 | `if (reg & (1 << n))` | 与一下，非零即 1 |

**为什么不能用 `=`**：`reg = (1<<2)` 会把其他位全清掉，只剩 bit2。`|=` 是"只动我要动的位"——单片机里这个差别是致命的（你只想开一个 LED，`=` 会把整个端口的其他引脚全拉低）。

### 2.2 `1 << n` 全表（背下来，以后不用算）

```
表达式    十进制   十六进制   8位二进制
1 << 0      1      0x01      00000001
1 << 1      2      0x02      00000010
1 << 2      4      0x04      00000100
1 << 3      8      0x08      00001000
1 << 4     16      0x10      00010000
1 << 5     32      0x20      00100000
1 << 6     64      0x40      01000000
1 << 7    128      0x80      10000000
```

规律：**每往上一行，1 往左挪一格，值翻一倍**。

### 2.3 位号与权重对照（0x52 实测）

```
位号:  bit7  bit6  bit5  bit4  bit3  bit2  bit1  bit0
权重:   128    64    32    16     8     4     2     1
取值:     0     1     0     1     0     0     1     0

哪些位是 1：bit6(权重64)  bit4(权重16)  bit1(权重2)
验算：64 + 16 + 2 = 82 = 0x52  ✅
```

十进制对照（说明"从 0 数"一点都不神秘）：**个位 = 10⁰（编号 0）、十位 = 10¹（编号 1）、百位 = 10²（编号 2）**——二进制同理，bit0 就是那个"个位"。

### 2.4 造"连续几位"的掩码（最地道的写法）

| 要置几位 | 用哪个数 | 写法 |
|---|---|---|
| 2 位 | `3` = `0b11` | `3 << 起始位` |
| 3 位 | `7` = `0b111` | `7 << 起始位` |
| 4 位 | `0xF` = `0b1111` | `0xF << 起始位` |

实测：`0xF << 2` = `0011 1100` = `0x3C`（一次盖住 bit2~bit5）。
实战典型组合（**先清再置**）：`reg &= ~(0x3 << 4);  reg |= (0b10 << 4);`

### 2.5 三个坑

1. **`|` 和 `|=` 别混**：`|`（单竖线）在中间那步是**造模板/合并**，`|=` 在最前面是**把模板盖到 reg 上**。
2. **`~(1<<4)` 其实是个负数**：`1` 是 int（32 位），所以 `~(1<<4)` = `0xFFFFFFEF`（= -17），**不是** 8 位的 `0xEF`。执行 `reg &= 0xFFFFFFEF` 时 reg 先被**整型提升**成 int 算完再截断回 8 位，**结果照样对**，但规范写法是 `~(1u << 4)`。
3. **位号只按 0 数**：答题写「**bit3:2 置 1，掩码 0x0C**」，别写"第 2、3 位"——中文"第几位"有人从 0 数有人从 1 数，是出争议的地方。数据手册（STM32 也是）全写 `bit 0`、`bits 7:4`。

### 2.6 那次考试的位操作题（实测输出）

```c
unsigned char reg = 0x52;
reg |= (1 << 0);      // → 0x53  0101 0011  bit0 置 1
reg &= ~(1 << 4);     // → 0x43  0100 0011  bit4 清 0
reg ^= (1 << 6);      // → 0x03  0000 0011  bit6 翻转(1→0)
```

**第 2、3 位同时置 1（三种写法，结果都是 `0x5E` = `0101 1110`）**：

```c
reg |= (1 << 2) | (1 << 3);   // 一个孔一个孔打，再合并（最直观）
reg |= 0x0C;                  // 直接算好（最短，记得写注释）
reg |= (3 << 2);              // 连续两位一起挪（最地道）
```

## 3. 宏 `#define`（正式课程还"封存"着，考试先撞上了）

- **本质 = 文本替换**，发生在**编译之前**（预处理阶段）。不是函数、不是变量：没有类型、不占内存。
- **铁证**：让 gcc 输出"预处理之后编译器真正看到的东西"——
  ```c
  int z = 2*(N+F(5+1));        // 我写的
  int z = 2*(3 +((3 +1)*5+1)); // 预处理后（gcc -E 实测）
  ```
- **带参数的宏 ≠ 函数**：一模一样的式子，结果不同（实测）
  ```c
  #define F(n) ((N+1)*n)             /* 带参数的宏 */
  int f(int n) { return (N+1)*n; }    /* 真函数 */
  F(5+1) → 21     // 参数是"文本"：((3+1)*5+1)，乘号只抓得到 5
  f(5+1) → 24     // 参数是"值"：先把 5+1 算成 6
  ```
- **写宏要全加括号**：`#define F(n) ((N+1)*(n))` —— 参数整体加括号，否则就出现上面那种坑。
- **运算符优先级**：括号 > 乘除 > 加减；`2*(3+21)` 的 2 要乘**整个括号**。（我算成 30 就是把它写成了 `2*3+24`。）

## 4. 指针与数组（正式课程还没到）

- **`const unsigned char *data`**：`const` 锁的是**内容**（`*data`），**指针本身是普通变量**。
  - `data++` ✅ 合法
  - `data = NULL;` ✅ 合法（改指针本身）
  - `data[0] = 0;` ❌ 报错 `assignment of read-only location '*data'`
  - 三种写法记住：`const T *p`（内容只读）／`T * const p`（指针只读）／`const T * const p`（都只读）
- **`*(p+i)` ≡ `p[i]`**；若 `p = a + 1`，则 `*(p+i)` 访问的是 **`a[i+1]`**（比 `a[i]` 偏后一位）。
- 指针 **+1 = 跳一个元素**（不是一字节）。
- 数组名当指针用时指向**首元素**。

## 5. 两个程序模板（将来写代码可以直接抄）

### 5.1 最长连续严格递增片段（一遍扫描 O(n)）

```c
int longest_slice(int a[], int n, int *start)
{
    if (n <= 0) { *start = 0; return 0; }
    int best = 1, best_start = 0;
    int cur = 1, cur_start = 0;
    for (int i = 1; i < n; i++) {
        if (a[i] > a[i-1]) {
            cur++;
            if (cur > best) { best = cur; best_start = cur_start; }  /* 严格> : 并列时取起始下标最小 */
        } else { cur = 1; cur_start = i; }
    }
    *start = best_start;
    return best;
}
```
*实测：9 组手选用例 + 10 万组随机对拍，0 不一致。*

### 5.1.1 我自己手写这题时踩的坑（2026-10-05 订正）

| # | 我写的 | 正确 | 后果 |
|---|---|---|---|
| ① | `if (a==0)` | `if (n==0)` | **比错对象**：`a` 是数组、`n` 才是个数。**编译器一点不报错**——只有"n=0 且指针有效"时才出错（返回 1，应该 0）；从 main 传真实数组**永远蒙对**，最难查 |
| ② | `for (i=1; i<=n; i++)` | `i < n` | 越界读 `a[n]`。实测起点跑出 **6、8** 这种数组外下标 |
| ③ | `if (this_start > max_start)` | `if (this_len > max_len)` | **比错变量**：`max_len` 从头到尾没被改过 → **函数永远返回 1**。编译器早就警告 `this_len set but not used` + `max_len unused` |
| ④ | `return best_len;` | `return max_len;` | 命名中途换词，变量不存在 → 编译错 `'best_len' undeclared` |

> [!important] 通用判别法（背下来）
> **先问"最大合法下标是几"，循环条件就刚好停在下一个数上。**
> n 个元素 → 最大下标 `n-1` → 写 **`i < n`**；要碰 `a[0]…a[n]` 共 n+1 个数 → 写 `i <= n`。
> 下标的范围**只跟"有几个元素"有关**，跟元素是正数还是负数毫无关系。

**警告不是噪音**：`set but not used`（算了没用）/ `unused variable`（定义了没动）—— 这两条一起出现，几乎就是"更新条件比错了变量"的铁证。

### 5.2 数据帧校验（守护式写法 = 逐条失败就 return 0）

```c
int validate_frame(const unsigned char buf[], int n)
{
    if (n < 3) return 0;                 /* 先守边界，之后读 buf[0]/buf[1] 才安全 */
    if (buf[0] != 0xAA) return 0;        /* 帧头 */
    int L = buf[1];
    if (n != L + 3) return 0;            /* 总长度 */
    int sum = 0;
    for (int i = 0; i < L; i++) sum += buf[2 + i];
    if (buf[L + 2] != (unsigned char)(sum % 256)) return 0;   /* 校验和 */
    return 1;
}
```
**要点**：① 守卫顺序很重要（先 `n < 3`，否则读 `buf[1]` 就越界）；② `n == L+3` 通过后，数据区最高下标 `n-2`、校验和 `n-1`，全程在界内；③ `sum` 用 int，最坏 255×255=65025 不溢出。

## 6. STM32 / 控制 常识（考试里考过的，先记结论）

### 6.1 STM32 四句常识（都是"错在哪"型考点）
| 错误说法 | 纠正 |
|---|---|
| CPU = MCU | CPU 只是运算核心；**MCU = CPU + 存储器（Flash/SRAM）+ 片上外设**集成一芯片 |
| 程序断电后存 SRAM | SRAM **易失**、断电丢；程序固化在 **Flash**（非易失） |
| 开发板只是把引脚引出 | 还有电源稳压、复位、晶振、SWD 下载口、USB 转串口、去耦电容 |
| 上电直接进 `main()` | 先跑**启动代码**（Reset_Handler：设堆栈指针、初始化 .data/.bss、SystemInit 配时钟）**再**调用 main |

### 6.2 外设选型
| 功能 | 外设 | 方向 |
|---|---|---|
| 读按键电平 | **GPIO**（数字输入，读 IDR） | 输入 |
| 测电池电压 | **ADC**（模拟输入） | 输入 |
| 输出 PWM | **定时器 TIM**（PWM 模式） | 输出 |
| USB 转串口调试 | **USART/UART** | 发=输出，收=输入 |

### 6.3 看门狗
- **硬件**：独立时钟（LSI）驱动的递减计数器 → 程序定期"喂狗"重装计数 → 跑飞没人喂 → 减到 0 → **复位**。
- **软件任务看门狗**：每个任务维护刷新标志（时间戳），监控任务定时检查，超阈值未刷新 → 判卡死 → 报警/复位。
- **最本质局限**：软件看门狗**依赖 CPU 本身正常**（整体跑飞时监控任务自己也不跑）；硬件看门狗用独立时钟，CPU 死了照样复位。

### 6.4 串级 PID（平衡车）
```
外环 直立环(角度环,慢)  : err_angle = 0 - angle
                          target_speed = Kp·err_angle + Kd·(err_angle - last)   // PD，D 提供阻尼
内环 速度环(快)          : err_speed = target_speed - speed(编码器)
                          current_cmd = Kp·err_speed + Ki·∫err                  // PI，I 消稳态误差
最内环 电流环(最快,驱动器): current_cmd → 力矩 → 车体 → 倾角变化 → IMU 再测（闭环闭合）
```
核心：**外环的输出 = 内环的期望值**。

### 6.5 循迹车（比例控制 + 死区）
- 目标：偏差 `e → 0`；反馈 = 灰度传感器偏差；执行 = 左右轮差速。
- 死区：`|e| ≤ 2` 时 `u = 0`（滤掉中心附近的传感器噪声，防轮速高频抖动）；死区过大 → 偏差积累、蛇形漂移、出界。

## 7. 速查题（下次复习用，先自己答）

> [!question]- Q1：`1 << 5` 等于多少？（十进制、十六进制、二进制各说一个）
>
> **答**：32 = `0x20` = `0010 0000`。（"1 后面添 5 个 0"）

> [!question]- Q2：把 `reg` 的 bit7 清 0，怎么写？
>
> **答**：`reg &= ~(1 << 7);`

> [!question]- Q3：`#define F(n) ((N+1)*n)`，`N=3`，那 `F(2+3)` 等于多少？为什么？
>
> **答**：`(3+1)*2+3 = 11`。参数是**文本**"2+3"，贴进去后乘号只抓得到 2 → `((3+1)*2+3)`。（若想得到 `4*5=20`，宏要写成 `((N+1)*(n))`。）

> [!question]- Q4：`const unsigned char *p`，下面哪些合法？`p++` / `p[0] = 5` / `p = NULL`
>
> **答**：`p++` ✅、`p = NULL` ✅（改指针本身）；`p[0] = 5` ❌（改 const 内容，编译报 `assignment of read-only location`）。

> [!question]- Q5：位号从哪一端开始数？`0x01` 里是第几号位？
>
> **答**：从**最右边（最低位）**开始，称为 bit0。`0x01` 就是 bit0（权重 2⁰=1）。
