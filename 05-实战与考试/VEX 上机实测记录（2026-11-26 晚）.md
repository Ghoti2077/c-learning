## 二、转向符号（现场定案）

现象：Axis1 往左拨，车往右偏。

倒推：原式 `left = straight - turn; right = straight + turn;`。若左拨 turn 为正 → 左轮减、右轮加 → 车头左偏（与现象相反）。能同时满足“左拨出来的数是负”和“车右偏”的只有一种解释：**Axis1 左拨读数为负**。

改法（60~66 行附近）：

```cpp
float left_output  = straight + turn;
float right_output = straight - turn;
```

物理含义：左转 = 左轮走得少、右轮走得多。

## 三、中桥卡球的修法

现象：球走到最后一步卡住。

改法：`mid_bridge()` 里 `intake3` 由 `stop()` 改成 `spin(fwd,100,pct)`，让上通道帮着往下推。

副作用（要记）：吐中桥时上通道也在正转，如果上通道里还存着球，会跟着一起下来 → 连续操作可能出现“吐一个掉两个”。

## 四、低桥 = 原路返回（怎么进来怎么出去）

原代码是按“从输出口吐”写的，跟原路返回不是一条路。改成：

```cpp
void low_bridge(){
    intake_motor.spin(reverse,100,pct);   // 前吸反转，把球送出来
    intake1.spin(reverse,100,pct);        // 下通道反向，退回去
    intake2.stop();
    intake3.stop();
    outputmotor.stop();                   // 输出通道不参与
}
```

实测通过。原来 `intake_motor.stop()` 会让球卡在嘴边出不来。

## 五、里程：带符号 vs 路程（两种口径）

- 他最初写法（带符号）：`dist_in += ((l-last_l)+(r-last_r))/2.0 * IN_PER_DEG;` → 前进加、倒车减、原地转不动。
- 我建议过 `fabs` 版（`fabs` 套最外层 = 先平均再取绝对值）→ 倒车也加、原地转仍不加。
- **问了学长：第一版（带符号）是对的** → 已改回。
- 差别本质：带符号 = 车相对起点在哪（定位用）；fabs 套外层 = 底盘中心走过的路径长度；fabs 分别套左右轮 = “轮子碾了多少路”（真车里程表），是第三种。

## 六、IMU：端口号数错 + 重建工程

- 考核文档写 `inertial(PORT11)`，实际**插在 1 号 smart port**（数错一位）→ 定义改成 `PORT1`。
- 诊断靠临时加的一行：`Brain.Screen.print("IMU %d %d %.1f %.1f", imu.installed(), imu.isCalibrating(), imu.rotation(), imu.heading());` → 四个全 0 = 设备整个不存在，不是“数值算错”。
- 改端口后仍是 0，**重新建了一次 VEX 工程**才认到（机制不明，疑似工程配置缓存，不编）。
- SDK 核对：`vex_imu.h:46 installed()`、`:146 isCalibrating()`、`:213 heading()`（0~360）、`:220 rotation()`。

## 七、吸球方向：改哪里才对

现象：前吸正常，下通道把球往外顶。

改法：**改定义那行的第三个参数**（`motor intake1 = motor(PORT4, ratio6_1, false);`，原文档是 `true`），一处改完全局生效——`intake_ball()` 用 fwd、`low_bridge()` 用 reverse，两边同时跟着翻正。

反面教材：在 `intake_ball()` 里把 `fwd` 改成 `reverse`，吐低桥会跟着反，球往车里送。
