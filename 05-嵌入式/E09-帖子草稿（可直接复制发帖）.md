## 正文

昨晚到今晚，被 STM32 的烧录问题折腾了一晚上，最后发现硬件一点毛病都没有。写下来省得别人再踩。

**先说现象。**

Keil 里点下载，弹窗报 `No target connected`。打开 `Options for Target → Debug → ST-Link Settings`，右边 SW Device 那一栏就三个字：`Error`，下面 `ID CODE:` 是空的。

先分清两个报错，别搞混：

- `No ST-LINK detected` —— 电脑没认出下载器（驱动、线、口的问题）
- `No target connected` —— 下载器认到了，但它摸不到芯片

我遇到的是第二种。下载器在 Keil 里显示得好好的：`HW: V2 / FW: V2J37S7`。

**然后我开始瞎折腾。**

先是怀疑线。四根杜邦线通断档一根根量：0.6Ω、0.6Ω、0.6Ω、0.9Ω，全通。

再怀疑板子。只给板子供电、把下载器拔掉，万用表量 SWD 排针：`3.3V` 针 = 3.3V，`SWD` 针 = **3.3V**，`SWC` 针 = 0V。

这两个数其实已经把答案写出来了 —— ST 官方文档（AN2586）写着：复位后 `JTMS/SWDIO` 内部上拉、`TCK/SWCLK` 内部下拉。所以 **SWD 针有 3.3V、SWC 针是 0V，正好是芯片正常待机的样子**。要是这个 IO 口真烧了，内部上下拉会失效，量出来就是 0V 或者乱飘。

我还问了商家，商家一句“你开发板的 SW IO 口坏掉了”。但他说不出任何测量数据，纯经验判断。

**真凶：程序把 SWD 引脚占用了。**

`SWDIO` / `SWCLK` 这两根调试线，**同时就是 PA13 / PA14 两根普通 GPIO**。

芯片一上电就跑去执行 Flash 里的程序。程序里只要有下面任意一种写法，那两根脚就被它抢走了，下载器从此握不上手：

- 把 PA13/PA14 当普通 GPIO 配置（点灯、驱动继电器之类）
- 调了 `GPIO_PinRemapConfig(GPIO_Remap_SWJ_Disable, ENABLE)`（这是“把 PA13/14/15 释放成普通 IO”的标准写法）
- 程序进了 `Stop` / `Standby` 低功耗模式

这也解释了为什么“以前明明能烧，现在突然连不上”—— 硬件没变，是**新烧进去的那个程序**把调试口占了。

（顺便说，这个坑是我自己挖的：之前跑过一段实验代码，很可能动了这几根脚。所以以后我给自己立个规矩：**不拿 PA13/PA14 做实验**。）

**救命一招：把 BOOT0 拨到 1。**

`BOOT0 = 1` 的时候，芯片从系统 bootloader 启动，**根本不运行你的程序**。那两根脚没人抢，SWD 立刻敞开。

我实测：跳线帽拨过去的瞬间，一打开 Settings 就直接出来了：

```
IDCODE 0x1BA01477
Device Name: ARM CoreSight SW-DP (ARM Core)
```

`0x1BA01477` 是 ARM 内核 SW-DP 的标准 ID，看到它 = 调试器已经和芯片握上手。

连上以后擦一次全片、或者重新下一个干净的程序，再把 BOOT0 拨回 0，就彻底恢复了。我现在 BOOT0=0 也能正常连、正常调试。

**兜底：串口 ISP。**

万一 BOOT0 也救不回来，或者下载器真坏了，还能走芯片自带的串口 bootloader，用 USB-TTL 下载，走 PA9/PA10，完全绕开 SWD：

- 接线：`TXD → PA10(A10)`、`RXD → PA9(A9)`、`GND → GND`（模块的电源别接，板子自己供电）
- `BOOT0 = 1`、`BOOT1 = 0`，按一下板子的 RESET
- FlyMcu 里选 COM 口、76800bps、选 hex 文件、勾“校验”和“编程后执行”、点开始编程
- 烧完把 BOOT0 拨回 0，再按 RESET

**顺手记几个坑：**

- FlyMcu 选文件时 **路径别带中文**，不然会报“文件不存在”（我一开始就栽在这）
- 克隆 ST-Link 弹“固件升级”**永远点 No**，十几块的山寨板刷官方新固件有变砖风险
- Keil 里改完代码记得 **Ctrl+S 保存再 F7 编译** —— 它编译读的是磁盘文件，编辑器里没保存的改动不算数。看文件名后面有没有 `*` 就知道
- 想用 Keil 的 `Connect under Reset`，得给下载器接一根 RST 线到板子的 RESET，不然那个设置是空转的

**一句话总结：**

> `No target connected` 九成不是硬件坏了，是芯片里的程序把 SWD 脚占了。第一招 `BOOT0` 拨到 1，兜底走串口 ISP。

（板子和芯片最后都没换，全是好的。商家那句“IO 口坏了”，纯属经验判断。）
