# E08 串口 ISP 下载（绕开 ST-Link）

> **2026-10-28 23:07 实测成功**：`COM5 @76800bps`，FlyMcu V0.188，写 2KB，进度 100%，**PC13 绿灯正常闪烁**。
> 背景：ST-Link 一直报 `No target connected`，SWD 走不通 → 改用串口 ISP，**一次成功**。

## 为什么要有这条路

- SWD 调试器坏了/连不上时，**串口 ISP 是芯片出厂自带的"后门"**（ST 官方 bootloader 固化在系统存储区，烧不掉）
- 缺点：**只能下载，不能在线调试**

## 需要的东西

| 件 | 说明 |
|---|---|
| **CH340 USB-TTL 模块** | 十几块那种；插上后设备管理器应出现 `USB-SERIAL CH340 (COMx)` |
| **FlyMcu V0.188** | `D:\work\STM32\tools\FlyMcu\FlyMcu.exe`（官网 mcuisp.com，免安装）|
| 4 根杜邦线 | 母对母 |

## 接线（只有 3 根信号 + 板子自己供电）

| CH340 | → | 蓝板 | 说明 |
|---|---|---|---|
| `TXD` | → | **`A10`（PA10）** | 模块发 → 板子收 |
| `RXD` | → | **`A9`（PA9）** | 模块收 ← 板子发 |
| `GND` | → | `GND` | 必须共地 |
| `5V` / `3V3` | ✗ | — | **不接**，板子用自己 USB 供电 |

⚠️ **TX↔RX 交叉接**（TX 接板子的 A10，不是 A9）
⚠️ **串口 ISP 只能用 USART1 = PA9/PA10**，别的串口不行

CH340 模块上的电压跳帽（`3V3 — TTL — 5V`）：盖在 **3V3 + TTL** = 3.3V 电平，保持即可（反正不用它的电源脚）。

## 进下载模式（BOOT0 = 1）

蓝板跳线块：**两排各 3 针，左边列=0，中间列=BOOT，右边列=1**

| 排 | 跳帽盖 | 结果 |
|---|---|---|
| 上排 `BOOT0` | **中间 + 右边(1)** | 1 → 进下载模式 |
| 下排 `BOOT1` | 中间 + 左边(0) | 0 |

接好跳帽后 **按一下板子的 `RESET` 键**。

## FlyMcu 配置（照抄）

1. **「搜索串口」** → `端口Port` 选 `COM5`
2. `bps` → **`76800`**（不超过 115200）
3. **「选择要下载的文件」** → `D:\work\STM32\blink.hex`
   ⚠️ **hex 路径不要带中文**（`D:\work\STM32\山羊模板\...` 这种老软件可能读不到，复制成纯英文名再选）
4. 勾 ☑ **「校验」**、☑ **「编程后执行」**
5. **「开始编程」**

⚠️ **不要勾「编程到 FLASH 时写选项字节」**（会改芯片配置，有锁片风险）

## 常见失败

| 现象 | 处理 |
|---|---|
| `连接失败` / 卡在"开始连接" | **先按板子 `RESET`，再点「开始编程」**（时序问题）；还不行查 TX/RX 是否接反 |
| FlyMcu 搜不到 COM 口 | CH340 驱动没装：设备管理器 → `USB Serial`(错误码 28) → 更新驱动程序 → 自动搜索 |
| 提示"文件不存在" | hex 路径含中文，换成纯英文路径 |
| 烧完不跑 | 忘了把 `BOOT0` 拨回 0，或者忘了按 RESET |

- 芯片 **PID 00000410 = STM32F10xx Medium-density**、**FLASH 64KB** → 确认是正品 C8T6 规格

## ⭐ 最后追加：SWD 其实也没坏（2026-10-28 定案）

把 **`BOOT0` 拨到 1**（芯片不跑用户程序）后再开 Keil 的 `Settings`：

```
SW Device
  IDCODE 0x1BA01477
  Device Name: ARM CoreSight SW-DP (ARM Core)
```

**连上了。** 这说明：

| 判断 | 结论 |
|---|---|
| ST-Link 的 SWD 输出 | ✅ 好的 |
| 板子的 SWD 通路 / 焊点 | ✅ 好的 |
| 芯片的 SWD 模块 | ✅ 好的 |
| **之前连不上的真因** | **芯片在跑旧程序，把 SWD 脚占住了**（旧程序可能把 PA13/PA14 当 GPIO 或进了低功耗）|
| 商家"SW IO 口坏了" | ❌ **错了** |

**`0x1BA01477` 是什么**：ARM CoreSight SW-DP 的标准 ID（所有 Cortex-M 芯片的 SW-DP 都是这个），看到它就代表"调试器已经和内核的调试接口握上手"。

**以后遇到连不上，第一招永远是：`BOOT0` 拨到 1 再连。** 芯片在跑用户程序时调试器可能抓不住它，`BOOT0=1` 让它根本不跑程序，SWD 必定敞开。

### ⚠️ 教训（2026-10-28 他提醒后补记）

**那个"占住 SWD 的旧程序"很可能就是以前某次会话里我给烧的实验代码**（那些会话记录已被清空，我查不到，这也导致本次排查一开始漏掉了这个可能性 —— 我的疏忽）。

**以后我方示例代码的红线**：
1. **不要拿 PA13 / PA14 做 GPIO 实验**（那是 SWDIO / SWCLK）
2. **不要写 `GPIO_PinRemapConfig(GPIO_Remap_SWJ_Disable, ENABLE)`**，除非当场教他"怎么用 BOOT0=1 救回来"
3. 万一非要演示这类代码，**必须在同一段里写明恢复步骤**，并提醒他先记下 BOOT0 的位置
4. 涉及低功耗（Stop/Standby）的实验同样如此

**他 2026-10-28 的结论（可以告诉他）**：只要程序不碰 PA13/PA14、不关 SWJ、不进 Standby，**ST-Link 以后都能正常连、正常下载调试**；真踩坑了，`BOOT0=1` + 串口随时能救。
