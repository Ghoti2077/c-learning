# E09 ST-Link「No target connected」排查全过程

> 结论先行：**ST-Link 没坏、开发板没坏、芯片没坏。** 真因是**芯片里跑的旧程序占用了 SWD 引脚（PA13/PA14）**，`BOOT0` 拨到 1 立刻就能连上。
> 相关实操流程见 [[E08 串口ISP下载（FlyMcu保姆流程·已实测）]]。

---

## 一、给商家的话（可直接复制）

> 你好，这块 STM32F103C8T6 最小系统板的 SWD 问题我已经排查完了，想跟你反馈一下结论：
>
> **板子的 SWD 口没有坏，之前连不上是因为芯片里跑的旧程序占用了 SWD 引脚。**
>
> 我做的测量和验证：
>
> 1. **只给板子供电、断开下载器**，用万用表量 SWD 排针：`3.3V` 针 = 3.3V，**`SWD` 针 = 3.3V**，`SWC` 针 = 0V。
>    这正是 STM32 复位后的标准状态 —— ST 官方文档 AN2586 写明 `JTMS/SWDIO` 内部上拉、`TCK/SWCLK` 内部下拉。如果 IO 口损坏，这两个内部上下拉会失效，量出来应该是 0V 或悬空。
> 2. 四根连接线用通断档量过：0.6Ω / 0.9Ω，**全部导通**；板子供电正常。
> 3. 下载器电脑能正常识别：`HW V2 / FW V2J37S7`。
> 4. **关键一步**：把 `BOOT0` 跳线拨到 1（让芯片不运行用户程序），Keil 立刻连上 —— **`IDCODE 0x1BA01477`，Device Name: ARM CoreSight SW-DP**。
> 5. 用串口 ISP（CH340，PA9/PA10）下载也成功：`BootLoader 2.2`、`PID 00000410`、`FLASH 64KB`、写入 2KB 100% 完成，程序正常运行。
> 6. 把旧程序覆盖成新程序（新程序不碰 PA13/PA14）后，`BOOT0` 拨回 0 也能正常连上。
>
> 所以问题不是“SW IO 口坏了”，而是**芯片里的程序把调试引脚占用了**。板子和芯片本身都是好的，不用更换。谢谢。

## 二、给新手的提醒（可直接复制发帖）

### STM32 烧录报 `No target connected`？先别换调试器、别换板！

我这两天被这个问题折腾了一晚上，最后发现**硬件一点毛病都没有**，坑在软件上。把过程写出来，省得别人再踩。

#### 报错长什么样

Keil 里 `Options for Target → Debug → ST-Link Settings`：

```
SW Device
  Error
  No target connected
  ID CODE:            ← 空的
```

注意区分：`No ST-LINK detected` 是**电脑没认出下载器**；`No target connected` 是**下载器认到了、但摸不到芯片**。

#### 真凶：程序把 SWD 引脚占用了

`SWDIO` / `SWCLK` 这两个调试引脚，**同时就是 PA13 / PA14 两根普通 GPIO**。

只要程序里出现下面任一情况，调试器就抓不住芯片：

```c
// ① 把 PA13/PA14 当普通 GPIO 用
GPIO_InitStruct.GPIO_Pin  = GPIO_Pin_13 | GPIO_Pin_14;
GPIO_InitStruct.GPIO_Mode = GPIO_Mode_Out_PP;

// ② 显式关掉 SWJ 复用（把 PA13/14/15 释放成 GPIO）
GPIO_PinRemapConfig(GPIO_Remap_SWJ_Disable, ENABLE);
```

③ 程序进了 `Stop` / `Standby` 低功耗模式，调试接口也会被关掉。

**芯片在上电后会立刻跑 Flash 里的程序** —— 程序一抢走那两根脚，下载器就再也握不上手。这就是“明明以前能烧，现在突然连不上”的典型原因。

#### 一分钟自查

| 操作 | 正常结果 |
|---|---|
| 只给板子供电（拔掉下载器），量 `SWD` 针对 GND | **约 3.3V**（芯片内部上拉）|
| 量 `SWC` 针对 GND | **0V**（芯片内部下拉，正常）|
| 量下载器和板子之间的四根线 | 通断都响 |
| 下载器在电脑上能识别（Keil 里能看到 HW/FW 版本）| 能看到 |

**四条都正常 = 硬件没问题，问题在芯片里的程序。**

#### 救命一招：把 BOOT0 拨到 1

`BOOT0 = 1` 时，芯片从**系统 bootloader** 启动，**根本不运行你的程序** —— 那两根脚没人抢，SWD 立刻敞开。

我实测：拨到 1 之后，一打开 Settings 就直接出现

```
IDCODE 0x1BA01477    Device Name: ARM CoreSight SW-DP (ARM Core)
```

连上之后在 Keil 里**全片擦除**或者重新下载一个干净的程序，再把 `BOOT0` 拨回 0，就恢复正常了。

#### 兜底：串口 ISP（芯片烧不坏的后门）

如果连 BOOT0 也救不了，或者下载器真坏了，用 **USB-TTL（CH340）+ FlyMcu** 走串口下载，走的是 PA9/PA10，完全绕开 SWD：

- 接线：`TXD→PA10(A10)`、`RXD→PA9(A9)`、`GND→GND`，**模块电源不接**
- `BOOT0=1`、`BOOT1=0`，按一下 RESET
- FlyMcu：选 COM 口、76800bps、选 hex、勾“校验”和“编程后执行”、开始编程
- 烧完把 `BOOT0` 拨回 0，按 RESET

我用这条路把程序烧进去并跑起来的，日志：`BootLoader 2.2`、`PID 00000410`、`FLASH 64KB`、写 2KB 100%。

#### 三条预防

1. **别拿 PA13/PA14 做 GPIO 实验**，也别随便用 `SWJ_Disable`
2. **给下载器接一根 RST 线**（`RST → 板子 RESET`），这样 Keil 的 `Connect under Reset` 才真的能按住复位键
3. **克隆 ST-Link 弹“固件升级”永远点 No** —— 十几块的克隆板刷官方新固件有变砖风险

#### 一句话总结

> **`No target connected` 九成不是硬件坏了，是芯片里的程序把 SWD 脚占了。第一招：`BOOT0` 拨到 1；兜底：串口 ISP。**

## 三、排查顺序（从便宜到贵 —— 昨晚我们绕远路，就是想错了顺序）

> **2026-10-30 追加**：朋友那块板出现一模一样的 `No target connected`，最后发现**就是杜邦线插错了**。这类问题**九成出在最便宜的那几步**，别一上来就怀疑硬件。

| 顺序 | 查什么 | 成本 | 怎么判 |
|---|---|---|---|
| **1** | **接线**（最容易被跳过）| 0 | `3.3V / GND / SWDIO / SWCLK` **逐根对丝印**；**SWDIO↔SWCLK 对调是高频错误**；插头有没有插到底 |
| **2** | **板子有没有电** | 0 | PWR 灯亮；量 `3.3V` 针 = 3.3V |
| **3** | **Keil 设置** | 0 | `Port = SW`（不是 JTAG）；`Connect` 试 `Normal` / `under Reset` |
| **4** | **`BOOT0 = 1`** | 0 | 能连 → 是程序占了 SWD 脚，不是硬件 |
| **5** | **交叉替换** | 借一个 | 只换一个变量：换调试器 or 换板 |
| **6** | **串口 ISP 兜底** | 有个 CH340 就行 | 能烧就说明芯片没问题，先学习要紧 |

**教训一句话：先怀疑线，再怀疑设置，最后才怀疑芯片 —— 顺序反了就要多花几个小时。**
