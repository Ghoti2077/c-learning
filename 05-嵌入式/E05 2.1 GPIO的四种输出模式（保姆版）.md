## 1. 打比方：一个引脚 = 一扇只有两档的门

每个 GPIO 引脚，门只有两种状态：**开（高电平 3.3V）/ 关（低电平 0V）**。

门怎么动，看两个"开关"：

| 开关 | 接哪儿 | 作用 |
|---|---|---|
| 上面那个 | 接 **3.3V** | 一合上，就把引脚"**推**"到 3.3V |
| 下面那个 | 接 **0V（地）** | 一合上，就把引脚"**拉**"到 0V |

- **推挽**：上下两个开关都装着 → 高低都能自己实实在在顶出来，**很硬气**。
- **开漏**：**上面那个开关拆掉了**，只剩下面的 → 只会往下拉（拉低），想输出高电平就**松手**（引脚变"悬空"），得靠外面接一个**上拉电阻**（像弹簧）把它拉回 3.3V。

> 推挽 = 门有推有拉，两头都使劲。
> 开漏 = 只会往下拉（接地），往上得靠外面的弹簧。

---

## 2. 第二个问题：这扇门**谁在管**

| 谁管 | 名字 | 意思 |
|---|---|---|
| **我的代码（CPU）** | **通用** | 我写 1 就是 1，写 0 就是 0 |
| **别的片上外设**（串口 / 定时器 / SPI） | **复用** | 门借给外设了，外设自己去推，我写代码它不听 |

> [!warning] 两个容易混的词（我 2026-10-23 差点搞混）
> - **复用** = **同一扇门，换人开**（外设来开）
> - **重映射** = **换一扇门**（把某个功能挪到别的引脚上）
>
> 判断"要不要复用"只问一句：**这扇门后面是谁在推它？**
> 点灯是我自己写 0/1 → **通用**，跟复用没关系。

## 3. 两个开关 × 两个人管 = 四种模式

| | **推挽**（上下两个开关） | **开漏**（只有下面一个） |
|---|---|---|
| **通用**（代码管） | 点灯、驱动别的芯片输入 | 点 PC13 板载灯、多机共享一根线 |
| **复用**（外设管） | 串口 TX、SPI 的 SCK/MOSI、定时器 PWM | **I²C 的 SDA/SCL** |

标准库里这四个名字（2.2 开始就会见到）：

```
GPIO_Mode_Out_PP   ← 通用推挽
GPIO_Mode_Out_OD   ← 通用开漏
GPIO_Mode_AF_PP    ← 复用推挽
GPIO_Mode_AF_OD    ← 复用开漏
```

---

## 4. 什么时候用哪个（这节的真正考点）

1. **普通点灯 / 输出信号给别的芯片** → **通用推挽**（要的就是硬高低）
2. **PC13 那颗板载灯** → **通用开漏**（原因见第 5 节，这是重点）
3. **串口 / SPI / PWM** → **复用推挽**（信号由外设产生，高低都得硬）
4. **I²C** → **复用开漏**（总线上挂好几个设备，谁都能往下拉表示 0，**谁都不许硬顶 3.3V**，高电平统一交给上拉电阻）

---

## 5. 重点：PC13 为什么必须用开漏（我一开始想错了）

**蓝板上这颗灯的接法**：`3.3V → 限流电阻 → LED → PC13`（**低电平点亮**）。

| 我写什么 | 推挽会怎样 | 开漏会怎样 |
|---|---|---|
| 写 **0** | 引脚接地 → 灯亮 ✅ | 引脚接地 → 灯亮 ✅（**同一个动作**） |
| 写 **1** | 引脚被顶到 3.3V，**等于往外供电** | 松手，高阻，灯灭 |

> [!important] 结论：推挽"写 0"和开漏"写 0"物理上是同一件事
> 区别只在**写 1** 的时候。所以"能用推挽写 0 点灯"这句话没错，但**是给自己埋雷**。

**数据手册的限制**（DS5319 原文要点，PC13/PC14/PC15 这组）：
- 它们是经芯片内部一个**小电源开关**供电的，**这个开关只能过 3mA**；
- 所以这组引脚**在输出模式下：不能当电流源使用（比如驱动 LED）**；
- **速度不得超过 2MHz**，负载不超过 30pF。

**我当时的错误理由**：「配成通用推挽，可能会**高电压打坏这个小板灯**」→ **方向对、对象错**
- 这个电路里写 1 时，灯两端**都是 3.3V**，没电压差 → **灯既不亮也不会被"打坏"**；
- 真正受伤的是**芯片内部那个只能过 3mA 的小开关**；
- 更现实的风险：**万一灯接反了**（PC13 → 灯 → GND），写 1 就得从那个小开关往外供电 → 真会伤片子。

**以后就这么记**：

> PC13 用开漏，不是因为"怕烧灯"，而是因为**开漏天生只会往下拉、永远不会主动往外供电** —— 这颗小引脚承受不了"往外送电"这件事。

## 6. 最大输出速度（"波形"到底是什么）

**波形 = 电压随时间画出来的一条线**；方波就是一条**方方正正的台阶**（上面=3.3V，下面=0V，中间是两级之间的竖线）。

**"最大输出速度" = 我画那条竖线能画多陡。**

- 档位**低**（2MHz）：竖线变成**斜坡**，爬坡那段时间电压"半高不高、半低不低"；
- 档位**高**（50MHz）：竖线笔直，说上就上。

**什么时候出事**：跳变得比"画线速度"还快 → 台阶变**三角波** → 对方读错（这叫**输出失真**）。
例：串口 115200，每一位只有约 8.7 微秒，还没爬到 3.3V 就得降下来。

**F103 只有三档**：

| 场景 | 选哪档 |
|---|---|
| 点灯、按钮、慢变的东西 | **2MHz**（够用、省电、干扰小） |
| 一般串口、几 MHz 的 SPI | 10MHz |
| 高速 SPI（十几 MHz 以上） | 50MHz |

> 越快≠越好：快 = 耗电大、对外辐射大。**够用就行**。
> 另外 PC13 那颗灯，数据手册**直接规定不得超过 2MHz**。

## 7.5 补讲：「挽」为什么不算输入（输出 ≠ 电流方向）

> [!note] 他发来的原图（2026-10-23，已归档）
> `_附件/E05-推挽CMOS输出级原理图.png` —— CMOS 推挽输出级：`Vdd`（上）、`Vss`（下）、`P-MOS` / `N-MOS`、“输出控制”模块，图上写着 **“推”=向外推电流、“挽”=从外边向里拉电流**。
> 下图左侧是输出低（N-MOS 把引脚拉到 Vss），右侧是输出高（P-MOS 向外“推”）。
>
> ![[E05-推挽CMOS输出级原理图.png]]

**他的原问（2026-10-23，看图后自己发现的）**：

> 「推挽的话，不能同时进行，只能交替进行。如果同时进行的话，VDD 是高电压，VSS 是低电压，它们中间导通的话会直接短路。推的时候 N-MOS 管关闭，引脚和 VDD 连接，所以电流从 VDD 流向引脚。然后挽的时候是 P-MOS 管关闭、N-MOS 管打开，引脚和 VSS 连接……**但是我觉得有一个问题，它这个不是输出吗？那从外向里面拉电流，这不应该是输入吗？**」

**判定**：前面四个判断（交替 / 同时导通=短路 / 推=P-MOS 开 / 挽=N-MOS 开）**全对**；最后那一问的误解点 = **把"电流方向"和"数据方向"当成一回事**。

| 说的是什么 | 谁决定 |
|---|---|
| **输出 / 输入** | 这个脚的电平**谁说了算**（芯片自己定 = 输出；外面电路定、芯片只能读 = 输入） |
| **推 / 挽** | **电流往哪个方向走**（往外送 = 推 = source；从外往里收、灌到地 = 挽 = sink） |

**比喻（泵站）**：引脚 = 出水口，后面两根管 —— 一根通供水塔（VDD），一根通下水道（VSS）。
接供水塔 → 水往外流 = **推**；接下水道 → 外面的水被抽回来排掉 = **挽**。
**放水和抽水都是泵站在干活、都是它说了算 → 两个都是输出。** 真的输入是"别人的管子接到你墙上往你家灌水，你只能看着"。

**铁证（他自己板子上的灯）**：`3.3V → 电阻 → LED → PC13`。
灯**亮**时 PC13 = 0，电流从 3.3V 流进 PC13 再到地 —— **灯明明是输出，电流却"流进来"**。这就是挽（灌电流）。

> [!tip] 口诀
> **输出/输入 看「谁说了算」，推/挽 看「电流往哪走」。**

**又问「灯翻过来接成 `PC13→电阻→LED→GND`、写 1 点亮，是推还是挽」** → 他答「**是推，电流从芯片往外**」**✅ 全对**。
⚠️ 但现实中**不能这么接 PC13**：那样写 1 就得由内部那只 3mA 小开关往外供电 —— 正好接回第 5 节「不是怕灯疼，是怕这只手出力」。

（他把"推挽"打成"推晚"、"VSS"打成"BSS"、"引脚"打成"阴角"，是他**语音输入**的识别错误，不是知识点错，不记错题。）
