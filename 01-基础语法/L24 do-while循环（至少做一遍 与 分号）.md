# L24 `do-while` 循环

- 日期：2026-09-21
- 来源：翁恺《C语言程序设计》do-while 循环（课件截图 2 张）
- 我的理解（原话）：「do-while 先循环一遍，while 先判断再决定是否进入循环」「while 结尾一定要有分号」
- 标签：`#C语言` `#基础语法` `#循环` `#do-while`

> **一句话总结**：
> **`do { 循环体 } while (条件);`** —— **先无条件做一遍**，再回头看条件：**成立就再来一轮，不成立就走人**。
> 所以它和 `while` 只差一件事：**do-while 至少做一遍，while 可能一遍都不做**。

## 1. 结构与流程图（翁恺课件）

![[L24-课件 do-while 循环结构与流程图.png]]

```c
do
{
    <循环体语句>
} while (<循环条件>);
```

![[L24-课件 两种循环的区别.png]]

流程图上的顺序是**倒过来**的：

```
   ┌──────────────┐
   ↓              │
 循环体 → 条件满足？ ──是──┘
            │
            否
            ↓
         后续语句
```

对比 `while`：`while` 是**先进岔路口问一次**，条件不成立就**一次都不做**。

## 2. 我的理解核对

| 我的原话 | 判定 | 精确说法 |
|---|---|---|
| 「do-while 先循环一遍，while 先判断再决定是否进入循环」 | ✅ **完全正确** | do-while 的第一遍**是无条件的**；条件只决定"**要不要有第二遍**" |
| 「while 结尾一定要有分号」 | ⚠️ **只对一半，这是关键的一半** | **do-while 的 `while (条件)` 后面必须有分号**；**普通 `while` 的条件后面绝不能加分号** —— 加了就变"空循环体"，直接死循环（见第 5 节实测） |

## 3. 实测：两个循环对着跑

| 情况 | `while` 做了几遍循环体 | `do-while` 做了几遍 |
|---|---|---|
| `x = 0`（条件一上来就不成立） | **0 遍** | **1 遍** |
| `x = 3`（条件成立） | 3 遍 | 3 遍 |

**结论**：**条件成立时两者完全一样；只有"一上来就不成立"时才分道扬镳。**

**打比方**：`while` = **先扫码再进门**（码不合法就不让进，一次都进不去）；
`do-while` = **先进门办事，出门再扫码**（无论如何先办一次）；后面要不要再来，看码合不合法。

## 4. do-while 的经典用途：输入检查（实测）

**"必须先要一个输入，才能判断它合不合法"** —— 这正是 do-while 的主场：

```c
do {
    printf("请输入 0~100 的分数: ");
    scanf("%d", &score);
} while (score < 0 || score > 100);   /* 不合法 → 再来一遍 */
```

**实测**（依次喂 `200`、`-5`、`50`）：

```
请输入 0~100 的分数: 请输入 0~100 的分数: 请输入 0~100 的分数: 收到合法分数：50
```

→ 前两次不合法**自动重问**，第三次合法才往下走 ✅

**换成 `while` 写就得多写一遍**（先读一次，再进循环里判断），这就是 do-while 存在的意义。

**嵌入式里同样常见**：等某个硬件状态稳定（先读一次，之后再反复读）、串口收一包数据（至少收一个字节再判断）、按键消抖（先采一次样）。

## 5. 分号的坑（实测，这条最值钱）

### ① do-while **必须有**结尾分号

写漏了（`} while (i < 3)` 后面直接下一句）：

```
error: expected ';' before 'printf'
    9 |     } while (i < 3)
      |                    ^
      |                    ;
10 |     printf("%d\n", i);
```

编译器会**明确指出位置**，还提示你补分号 ✅ 好抓。

### ② 普通 `while` 的条件后面**绝对不能**加分号

```c
int i = 0;
while (i < 3)     /* ← 多了个分号！ */
    ;
i++;
```

**实测**：**死循环**（限时 2 秒被砍，退出码 124）。原因：**分号本身就是一条"空语句"**，成了循环体 → 循环体里什么都没干 → `i` 永远是 0 → 条件永远成立。

> ⚠️ **更阴的是**：`gcc -Wall` 和 `gcc -Wall -Wextra` **都不提醒**（我实测过，输出是空的）。
> 所以这个错**只能靠自己看**——写完 `while (条件)` 后面**不该有分号**，直接跟 `{` 或者语句。

**记法**：

| 写法 | 对错 |
|---|---|
| `while (条件) { ... }` | ✅ 正常 |
| `while (条件);` | ❌ 空循环体 → 大概率死循环 |
| `do { ... } while (条件);` | ✅ 必须有分号 |
| `do { ... } while (条件)` | ❌ 编译报错 |

**为什么 do-while 要多一个分号**：因为 `do { ... } while (条件)` 整体是**一条语句**，`while(条件)` 是它的"尾巴"，整句得用 `;` 收尾（跟 `int x;` 一个道理）。

## 6. 回望 L23：do-while 就是那两行的"正规写法"

L23 课件里那两行 `n++; x /= 10;`（"先手动做一遍再进循环"）——**它就是 do-while 的手工版**：

```c
/* L23 的写法：手动先做一遍 */                /* L24 的写法：do-while 天然先做一遍 */
n++;                                         do {
x /= 10;                                         n++;
while (x > 0) {                                  x /= 10;
    n++;                                     } while (x > 0);
    x /= 10;
}
```

**实测 do-while 版**（AI 跑过）：

| 输入 | 输出 |
|---|---|
| **0** | **1** ✅ |
| 5 | 1 |
| 123 | 3 |
| 10000 | 5 |

→ **输入 0 也能得到正确答案 1**，跟 L23 那两行效果**完全一样**。这也是 do-while 的主要用武之地：**"至少得算一次"的场合。**

3. 下面这句为什么是死循环？
   ```c
   int i = 0;
   while (i < 5);
       i++;
   ```
4. 什么时候**必须**用 do-while（用 while 会变麻烦或写错）？举一个从今天课程里学到的例子。
5. `do { ... } while (条件)` 结尾漏分号，编译器报什么类型的错？

> [!question]- 参考答案（先自己答完再点开）
>
> 1. **do-while 至少执行一遍循环体，while 可能一遍都不执行**（条件成立时两者行为相同）。
> 2. 循环体做 **3 遍**（i=1、2、3），`i` 最后是 **3**。（第 3 遍做完 i=3，条件 `3<3` 不成立 → 退出）
> 3. 因为 `while (i < 5)` 后面那个**分号本身就是"空语句"**，被当成了循环体；循环体里什么都没改 `i`，条件永远成立 → 死循环。而且 gcc `-Wall/-Wextra` **都不会提醒**。
> 4. **"必须先要一个输入/先做一次动作才能判断"**的场合，比如输入检查（先读入分数，再判断是否 0~100，不合法就重问）、数位数（至少算一位，这样输入 0 也对）、单片机上"先读一次传感器再判断状态"。
> 5. **编译错误**（`error: expected ';' before ...`），gcc 会指出位置并提示补分号。

## 8. 嵌入式视角

- **`do { ... } while (0)` 是 C 里的一个著名技巧**：它能把"多条语句"打包成"一条语句"，让宏定义在 `if/else` 里不会被拆散（以后学宏定义时会看到）。
- **硬件初始化**天然适合 do-while：先发一次命令，再看状态位是否就绪，没好就再发（至少发一次）。
- **串口/网络收包**：先收第一个字节，再循环收剩下的（先做一次再判断，比 while 少写一遍代码）。
- **看门狗喂狗循环**：很多主循环用 `while (1)`（永不退出）；而"先做一次初始化，再进入主循环"的结构，正是 do-while 的语义。

## 9. 复习题作答与讲评（2026-09-21）

| 题 | 我的答案 | 判定 |
|---|---|---|
| 1. `do { i++; } while (i < 3);` 做几遍？`i` 最后是几？ | 「两遍，3」 | ⚠️ **`i = 3` 对；遍数错了——是 3 遍**（见下面逐轮表） |
| 2. 为什么 `while (i < 5);` 会死循环？ | 「因为 while 后面的 `;` 把语句截断了，程序只能一直在 while 循环里」 | ✅ **对**（措辞补精确：那个 `;` 不是"截断"，它**本身就是一条"空语句"，被当成了循环体**；循环体里没人改 `i` → 条件永远成立） |
| 3. 什么时候必须用 do-while？ | 「循环体里的任务必须至少完成一次的时候，比如计算数字是多少位数」 | ✅ **完全正确**，例子也举得准（数位数必须至少算一位，这样输入 0 也得 1） |

### 第 1 题为什么是 3 遍（AI 实测逐轮打印）

```
第 1 遍循环体结束后：i = 1，条件 i < 3 成立 → 还要再来一遍
第 2 遍循环体结束后：i = 2，条件 i < 3 成立 → 还要再来一遍
第 3 遍循环体结束后：i = 3，条件 i < 3 不成立 → 退出循环

结论：循环体做了 3 遍，i 最后 = 3
```

**数遍数的办法（以后固定这么数）**：把**每一轮结束后**关键变量的值**写出来**，一个个往下推 ——
`i` 从 0 开始 → 第 1 遍变 1、第 2 遍变 2、**第 3 遍变 3**（这时条件才不成立）。
**注意最后一轮"做完了才退出"**：第 3 遍是**真做了**的，只是做完后条件检查才失败——所以是 3 遍不是 2 遍。

> 小陷阱：容易把"条件不成立的那一次"当成"没做"。**条件是"做完之后再问的"**，问的时候这一遍已经做完了。
