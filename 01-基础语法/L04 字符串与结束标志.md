# L04 字符串与 \0（字符串结束标志）

- 日期：2026-09-15
- 来源：我自己用 Visual Studio 学 C 的笔记 + 鹏哥课上的"乱码"演示截图
- 标签：`#C语言` `#基础语法` `#字符串` `#数组`

> **一句话总结**：双引号 `"abc"` 是**字符串**，它的末尾**偷偷藏了一个 `\0`**（值 0），`\0` 就是字符串的**句号**。`printf("%s")` 只能靠这个句号知道"念到哪儿停"——**没有它，就会一直往后念别人的内存，念出一堆乱码。**

---

## 0. 原始笔记逐句核对（✅对 / ⚠️要改 / ❌错）

| 我原本写的 | 判定 | 修正后 |
|---|---|---|
| `""` 中间放东西，整体叫字符串 | ✅ 对 | 补：**单引号 = 字符（一个），双引号 = 字符串（一串）**。字符串末尾自动带一个 `\0`，所以你写 3 个字符，内存里其实占 **4 格** |
| 字符串的末尾隐藏了一个 `\0` | ✅ 对 | 说得很准。`\0` 的值就是 **0**（ASCII 表 0 号） |

| `\0` 是字符串结束的标志 | ✅ 对 | 这就是本课的核心，记住它 |

## 1. 我发的那张截图（课上的乱码演示）

![[L04-乱码对比.png]]

课上那段代码：

```c
int main()
{
    char arr1[] = "abc";                 // ← 双引号
    char arr2[] = {'a', 'b', 'c'};       // ← 花括号，一个一个写

    printf("%s\n", arr1);
    printf("%s\n", arr2);

    return 0;
}
```

两次运行的输出：

```
abc                          ← arr1 正常
abc烫烫烫烫烫烫烫烫烫烫烫烫烫烫烫烫烫烫烫?    ← arr2 乱码
```

## 2. 乱码到底是怎么来的（逐步拆解）

`printf("%s")` 打印字符串时，**它并不知道这个字符串有多长**。它的做法很笨：

> **从第一个字符开始，一个一个字往外念，念到一个 `\0` 就停。**

所以：

| 数组 | 内存里实际有什么 | `printf("%s")` 念的过程 | 结果 |
|---|---|---|---|
| `"abc"` | `a` `b` `c` **`\0`** | 念 a b c，碰到 `\0` → **停** | `abc` ✅ |
| `{'a','b','c'}` | `a` `b` `c` …（没有句号） | 念 a b c，**没找到 `\0`** → 只能继续往后念 | `abc` + 后面的垃圾 ✅❌ |

**它没停，就只能一直往后读**——读到的是别人（别的变量、没用的内存）留下的垃圾数据，念出来就是乱码。这叫**越界读取**，是 C 语言里最经典的一类 bug。

### 为什么是"烫"这个字？（有趣的一点）

VS 在**调试模式**下，会把**还没用过的内存全填成一个固定的值：`0xCC`**。

我刚才验证了：把两个字节 `0xCC 0xCC` 按 GBK 中文编码去解，解出来正是 **"烫"** 这个字 👇

```
字节 0xCC 0xCC  →  GBK 解码  →  烫
```

所以"烫烫烫烫烫"不是随便的乱码，它是**"这块内存我还没初始化过"的报警器**。你截图顶部的监视窗口里那一排 `?? ?? ?? ??` 是同一件事的另一种显示方式——**问号 = 没赋值的内存**。

> 换句话说：看到"烫"，就等于看到 VS 在喊 **"你读到了没写过的内存！"**

## 3. 关键纠正：决定一切的是 `\0`，不是双引号

我把三种写法放在一起真跑了一遍：

```c
char arr1[] = "abc";                  // 双引号：编译器偷偷补 \0
char arr2[] = {'a', 'b', 'c'};        // 花括号：没有 \0
char arr3[] = {'a', 'b', 'c', '\0'};  // 花括号 + 手动 \0：也没用双引号
```

**实测输出**：

| 数组 | 占几字节 | 每个字节的值 | 打印结果 |
|---|---|---|---|
| `arr1` | **4** | `97 98 99 0` | `[abc]` ✅ |
| `arr2` | **3** | `97 98 99` ← **没有 0** | `[abcabc]` ❌（念到别人的内存里去了） |
| `arr3` | **4** | `97 98 99 0` | `[abc]` ✅ |

**结论（重要）**：

- `arr3` **没有用双引号**，但因为它有 `\0`，打印**完全正常**。
- `arr2` 只是**缺了 `\0`**，就乱码。

> 所以正确的说法是：**乱码的原因 = 字符串没有 `\0` 结尾**。
> 双引号的作用只是**自动帮你补上 `\0`**（这就是它比手写花括号省事的地方）。
> 记忆法：`\0` 是**句号**。写文章不点句号，别人就会把你的文章和下一篇连起来念。

## 4. 数组大小为什么要多 1

```c
char arr1[] = "abc";   // [] 里不写数字 → 编译器自己数：a b c \0 = 4 格
```

| 写法 | 占几字节 | 说明 |
|---|---|---|
| `"abc"` | **4** | 3 个字符 + 1 个 `\0` |
| `"ab"` | 3 | 2 个字符 + 1 个 `\0` |
| `""`（空字符串） | **1** | 0 个字符 + 1 个 `\0`（空的也占一格放句号） |

> **字符串长度 = 能看到几个字符 + 1（给 `\0` 留位）**。
> 嵌入式里这条特别要命：给串口缓冲区开数组时忘了加 1，就会出现"莫名其妙的错误"。

2. 下面哪个会打出乱码？为什么？
   ```c
   char a[] = "hi";
   char b[] = {'h', 'i'};
   char c[] = {'h', 'i', '\0'};
   ```
3. `printf("%s")` 是**怎么知道**字符串念到哪儿该停的？
4. VS 控制台出现"烫烫烫烫"，说明发生了什么？

> [!question]- 参考答案（先自己答完再点开）
>
> 1. **4 字节**。`a` `b` `c` 三个字符 + **1 个 `\0`**（双引号自动补的）。字符串长度永远 = 字符数 + 1。
> 2. **只有 `b` 会乱码**。`a` 有双引号补的 `\0`；`c` 虽然用花括号，但**手动写了 `\0`**，所以正常。可见关键是 `\0`，不是双引号。
> 3. 它**不知道长度**，只能一个字符一个字符往外念，**碰到 `\0` 就停**。所以没有 `\0` 就会一直往后越界读。
> 4. 说明程序**读到了还没有初始化的内存**。VS 调试模式下把没用的内存填成 `0xCC`，两个 `0xCC` 按 GBK 中文解码就是"烫"字——它是"未初始化"的报警器。

## 7. 复习题讲评（2026-09-15 我的作答）

**我的答案**：Q1 数组还没学（没答）　Q2 第二个会乱码（没用 `""` 也没加 `\0`）　Q3 `""` 里包含 `\0`，电脑知道停在那里　Q4 程序把读到的垃圾内存填成 0xCC，GBK 解成"烫"

**评分：2 对、1 半对、1 搁置**

| 题 | 判定 | 讲评 |
|---|---|---|
| 1 几个字节 | ⏸ 搁置（不计分） | 数组还没学，跳过合理。结论先记住：`"abc"` 占 **4 字节**（3 个字符 + 1 个 `\0`） |
| 2 哪个乱码 | ✅ 对 | 结论正确（只有 `{'h','i'}` 乱码）。理由里"没有 `\0`"抓对了；但**双引号不是必须的**——`{'h','i','\0'}` 没用双引号也正常。**唯一标准是：有没有 `\0`** |
| 3 怎么知道停 | ✅ 对 | "电脑知道停在那里"——说法到位。补完整：`printf` **不知道字符串长度**，只能一个字一个字念，**念到 `\0` 就停**。所以没 `\0` 就冲出边界一直念 |
| 4 "烫"是怎么回事 | ❌ 因果反了 | 见下 |

### 重点纠正：0xCC 不是程序填的，是 **VS 预先填好的**

❌ 我写的："程序把读到的垃圾内存**填成了** 0xCC"
✅ 正确顺序（**填 → 读 → 显示**）：

```
① VS 调试模式启动程序时 → 把没用过的栈内存【预先】全填成 0xCC
        ↓
② 我的数组没有 \0，printf 停不下来
        ↓
③ 程序【读到】了这些 0xCC（不是程序去填的！）
        ↓
④ 控制台按 GBK 解码 0xCCCC → 显示成"烫"
```

> 记住这三步的**主次**：**VS 负责填，程序负责读，控制台负责显示**。
> 我把"填"的责任按到了程序头上——程序从头到尾只是在**乱读**，它没往内存里写过任何东西。

这也是为什么**只有在 VS 里调试（F5）才看到"烫"**：别的环境下未初始化内存填的是别的值，可能啥都不显示。看到"烫"= **"我读到没写过的内存了"**。
