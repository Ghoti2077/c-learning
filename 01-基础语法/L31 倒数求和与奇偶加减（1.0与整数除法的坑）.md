# L31 倒数求和 / 奇偶加减

- 日期：2026-09-21
- 来源：翁恺《C语言程序设计》求和练习，我自己写的两个程序
- 标签：`#C语言` `#基础语法` `#循环` `#浮点数`

> **一句话总结**：
> `f(n) = 1 + 1/2 + 1/3 + … + 1/n` 就是**从 1 到 n 循环累加 `1.0 / i`**；
> 奇偶加减多一个**符号翻转**（`sign = 1; … sign = -sign;`）。
> ⚠️ **最容易踩的坑：写成 `1 / i` 就全废了** —— 两个 `int` 相除是**整数除法**（`1/2 = 0`），必须写成 **`1.0 / i`**。

---

## 1. 我写的两个程序

**① 倒数求和**

```c
int main() {
    int n;
    int i;
    double sum = 0.0;
    scanf("%d", &n);
    for (i = 1;i <= n;i++) {
        sum += 1.0 / i;
    }
    printf("f(%d)=%f\n", n, sum);
    return 0;
}
```

**② 倒数求和 · 奇偶加减**

```c
//倒数求和 • 奇偶加减
int main() {
    int n;
    int i;
    int sign = 1;
    double sum = 0.0;
    scanf("%d", &n);
    for (i = 1;i <= n;i++) {
        sum += sign * 1.0 / i;
        sign = -sign;
    }
    printf("f(%d)=%f\n", n, sum);
    return 0;
}
```

**两个程序的区别只有一个**：`sum += 1.0 / i;` → `sum += sign * 1.0 / i;`，再加一行 `sign = -sign;`。

**逐轮推演**（奇偶加减版，`n = 4`）：

| 轮次 | `i` | `sign` | 这一轮加的 | `sum` | 轮末 `sign = -sign` |
|---|---|---|---|---|---|
| 1 | 1 | 1 | `+1.0/1` = +1 | 1 | −1 |
| 2 | 2 | −1 | `−1.0/2` = −0.5 | 0.5 | +1 |
| 3 | 3 | +1 | `+1.0/3` ≈ +0.333333 | 0.833333 | −1 |
| 4 | 4 | −1 | `−1.0/4` = −0.25 | 0.583333 | +1 |

→ 实测 `f(4)=0.583333` ✅

## 2. ⚠️ 最大的坑：`1.0 / i` 不能写成 `1 / i`

**实测对照**（同一个 `n = 5`）：

| 写法 | 输出 |
|---|---|
| **`sum += 1 / i;`**（错） | `f(5)=1.000000` ❌ |
| **`sum += 1.0 / i;`**（对） | `f(5)=2.283333` ✅ |

**为什么**：`1` 和 `i` 都是 `int` → **整数除法**（只保留商，小数直接丢掉）：

```
i=1：1/1 = 1 ，1.0/1 = 1.000000
i=2：1/2 = 0 ，1.0/2 = 0.500000     ← 整数除法把它变成 0 了
i=3：1/3 = 0 ，1.0/3 = 0.333333
i=4：1/4 = 0 ，1.0/4 = 0.250000
i=5：1/5 = 0 ，1.0/5 = 0.200000
```

→ 累加起来就只剩 `1 + 0 + 0 + 0 + 0 = 1`。

**规则（记住这句）**：**除法里只要有一个是小数（`1.0` / `1.` / `(double)`），就是浮点除法**；两边都是整数就是整数除法。
**我这次写对了** ✅（两个程序都用了 `1.0`）。

**顺带看优先级**：`sign * 1.0 / i` 里，`*` 和 `/` **同级、从左往右**算 → 先 `sign * 1.0` 得到 ±1.0，再 `/ i` 得到浮点数 ✅ 结果正确。

## 3. 实测核对（AI 逐项跑过）

| 输入 | ① 倒数求和 | ② 奇偶加减 |
|---|---|---|
| 1 | `f(1)=1.000000` | `f(1)=1.000000` |
| 2 | `f(2)=1.500000` | `f(2)=0.500000` |
| 3 | `f(3)=1.833333` | `f(3)=0.833333` |
| 4 | — | `f(4)=0.583333` |
| 5 | `f(5)=2.283333` | `f(5)=0.783333` |
| 10 | `f(10)=2.928968` | `f(10)=0.645635` |
| **0** | `f(0)=0.000000` | `f(0)=0.000000` |
| 负数 | `f(-3)=0.000000` | — |

**严谨核对**：把 `n = 1~20` 全部跑一遍，用**分数精确计算**做参考 → **不一致 0 处** ✅

**边界情况**：`n = 0` 或负数时循环一次都不进，`sum` 保持初始值 `0.0` → 输出 `0.000000`（题目一般不会这么出）。

## 4. `%f` 默认打印 6 位小数（想改就写 `%.2f`）

**实测**：

| 写法 | 输出 |
|---|---|
| `%f` | `2.283333`（默认 6 位） |
| `%.2f` | `2.28` |
| `%.10f` | `2.2833333333` |
| `%e` | `2.283333e+00`（科学计数） |

**注意**：交 OJ 时**题目要几位就写几位**（比如要求 2 位小数就要写 `%.2f`，只写 `%f` 会 WA —— 跟 L22"没按题目要求输出"是同一类错）。

## 5. 数学彩蛋（不用管，看着玩）

- **倒数求和**：`n` 很大时约等于 `ln(n) + 0.5772`。实测 `n = 10000` → `9.787606`，而 `ln(10000) + 0.5772 ≈ 9.7876` ✅ 对得上。
- **奇偶加减**：`n` 越大越接近 `ln2 ≈ 0.693147`（实测 `n=10` 已经到 `0.645635`，很接近了）。
- 这两个极限**以后学数学分析再深究**，现在只要知道"**程序跑出来的数符合数学预期**"就够了。

## 6. 复习题（先自己答；**这两题我承认不会，先欠着**）

1. `sum += 1 / i;` 为什么结果是错的？错在哪一步？
2. 想把结果打印成 2 位小数，`printf` 该写成什么？
3. 奇偶加减里 `sign = -sign;` 这一行去掉会怎样？
4. `sign * 1.0 / i` 和 `1.0 * sign / i`、`1.0 / i * sign` 结果一样吗？为什么？

> [!question]- 参考答案（先自己答完再点开）
>
> 1. 因为 `1` 和 `i` 都是 `int`，`1 / i` 是**整数除法**：`i=1` 得 1，`i≥2` 全得 **0**（小数被丢掉），所以累加出来几乎只有 1。必须写成 `1.0 / i`（有一边是小数 → 浮点除法）。
> 2. `printf("f(%d)=%.2f\n", n, sum);` —— 在 `%` 和 `f` 之间加 `.<位数>`。
> 3. 去掉之后 `sign` 永远是 1，式子变成 `1 + 1/2 + 1/3 + …`（也就是第一个程序的**倒数求和**），不再是奇偶加减。
> 4. **一样**。`*` 和 `/` 同级、从左往右算，但**三种写法里都有 `1.0` 这个浮点数参与乘法**，运算过程会提升成浮点，结果相同。（真正的坑只在于"两边都是整数"那一种情况。）

## 7. 嵌入式视角

- **浮点在单片机上很贵**：很多 Cortex-M0/M3 只有**软件浮点**（编译器用整数模拟），一次 `double` 除法可能要几十上百个时钟周期。所以嵌入式里：
  - 能用 **`float`** 就用 `float`（4 字节，比 `double` 快）；
  - 有硬件 FPU 的芯片（Cortex-M4F/M7）才敢放心用 `float`/`double`；
  - **性能敏感的场合改成"定点数"**：把 `1/i` 这类运算放大成整数运算（比如放大 1000 倍当整千分之一算），最后打印时再插小数点。
- **求和顺序会影响结果**：浮点加法**不满足结合律**（`(a+b)+c` 和 `a+(b+c)` 可能差最后几位）。大量求和时嵌入式常用 **Kahan 求和**（补偿求和）来减小误差 —— 以后遇到再说。
- **"倒数求和"这类公式在硬件标定里很常见**：比如把 ADC 读数做多段平均、把定时器计数换算成频率（`1/t`），都是这个套路 —— 只是**在单片机上要小心除零**（`i` 或 `t` 为 0 时先判断再接）。
- **打印小数在嵌入式里一般是禁用的**：`printf("%f")` 会牵进一大坨浮点格式化代码（几 KB ROM），所以嵌入式常用**定点凑整 + 手工插小数点**的方式显示数值。
