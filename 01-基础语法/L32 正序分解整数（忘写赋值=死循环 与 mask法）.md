# L32 正序分解正整数（我这次的错）

- 日期：2026-09-21
- 来源：翁恺《C语言程序设计》"整数分解"练习，我自己写的"正序分解正整数（中间留空格）"
- 标签：`#C语言` `#基础语法` `#整数分解` `#调试`

> **一句话总结**：
> 我这次写错的地方是 **两处"算了但没赋值"**：`x / 10` 应该写 **`x /= 10`**、`r / 10` 应该写 **`r /= 10`**。
> 少了那个 `=`，等于**什么都没做** → `x` 和 `r` 永远不变 → **死循环**（实测被强制砍掉）。
> 另外**"先逆序再拆位"这个思路本身也不牢靠**（尾部有 0 的数会丢位），正解是 **mask 法**。

---

## 1. 我写的代码

```c
//正序分解正整数（中间留空格）
int main() {
    int x;
    int r;
    scanf("%d",&x);
    for (r=0;x > 0;x/10) {          /* ← 问题① */
        r = r * 10 + x % 10;
    }
    do {
        int b = r % 10;
        printf("%d",b);
        r / 10;if (r > 9) {         /* ← 问题①（又一次）+ 问题② */
            printf(" ");
        }
    } while (r>0);
    return 0;
}
```

## 2. ⚠️ 编译器其实喊了**两次**（我又没看警告）

gcc 编译这段代码，直接给了两条**一模一样的警告**：

```
a_his.c:10:26: warning: statement with no effect [-Wunused-value]
   10 |     for (r = 0; x > 0; x / 10) {
      |                        ~~^~~~
a_his.c:17:11: warning: statement with no effect [-Wunused-value]
   17 |         r / 10;if (r > 9) {
      |         ~~^~~~
```

**`statement with no effect` = "这条语句没有任何效果"** —— 编译器一眼就看出问题：**表达式算完了，结果没人要**。
**我又没看警告**（L25 的 C4244 也是这么被放过的）。**这条已经升级成纪律：编译完先看"警告"数量，非 0 就点开。**

## 3. 三个问题（实测证据）

### 问题① 两处"算了没赋值" → 死循环

| 我写的 | 应该是 | 后果 |
|---|---|---|
| `for (r=0; x>0; **x/10**)` | `x /= 10;` | `x` 永远不变 → 外层循环**永不结束** |
| `**r / 10;**` | `r /= 10;` | `r` 永远不变 → do-while 也**永不结束**，还一直打印同一个数字 |

**实测**：输入 `123`，限时 3 秒 → **被强制砍掉**（退出码 124），一个字符都没输出。**这就是死循环。**

> **`x / 10` 和 `x /= 10` 的区别**：前者只是"算了一下商"，算完就丢了；后者才是"**把商存回 x**"。
> 这个坑的正式名字叫 **"表达式没有副作用"**（算出来的值被丢弃，变量没变）。

### 问题② 空格条件写错：`r > 9` 应该是 `r > 0`

**只把上面两处赋值补上**，实测输出：

| 输入 | 我的输出 | 正确 |
|---|---|---|
| 123 | `1 23` ❌ | `1 2 3` |
| 105 | `1 05` ❌ | `1 0 5` |
| 100 | `1` ❌ | `1 0 0` |

**为什么少一个空格**：`if (r > 9)` 的意思是"**还剩两位以上**才补空格"。可当只剩**一位**要继续打印时（`r = 5`），条件不成立 → 空格被吞掉。
**正确的想法是"后面还有下一位就补空格"** → 条件写 **`r > 0`**。

### 问题③ 思路本身的缺陷：先逆序再拆位会丢尾部的 0

**输入 `100` → 输出 `1`**（应该 `1 0 0`）。

**为什么**：逆序时 `100` 变成 `001`，而**整数不保存前导零** → `r` 实际就是 `1` → 那两个 0 **根本没进到 r 里**，后面当然打印不出来。
（跟 L26 的 `1000 → 1`、L23 的 `120 → 21` 是**同一个病根**：整数记不住"两边多的 0"。）

**结论**：**正序分解不要走"先逆序"这条路** —— 绕远而且会丢位。

## 4. 正解：mask 法（先找到最高位权重，再一位位取）

```c
int main() {
    int x;
    scanf("%d", &x);

    /* ① 找最高位权重：123 -> mask = 100 */
    int mask = 1;
    int t = x;
    while (t > 9) {
        t /= 10;                  /* 一边缩短 t */
        mask *= 10;               /* 一边把 mask 乘起来 */
    }

    /* ② 从最高位开始，一位一位取出来 */
    do {
        int b = x / mask;         /* 取"当前最高位" */
        printf("%d", b);
        x = x % mask;             /* 把这一位去掉（保留后面几位） */
        mask /= 10;               /* 权重降一级 */
        if (mask > 0) {
            printf(" ");          /* 后面还有位 → 补空格 */
        }
    } while (mask > 0);

    printf("\n");
    return 0;
}
```

**实测**：

| 输入 | 输出 | |
|---|---|---|
| 5 | `5` | ✅ 一位数 |
| 123 | `1 2 3` | ✅ |
| 105 | `1 0 5` | ✅ 中间的 0 保住了 |
| **100** | **`1 0 0`** | ✅ **尾部的 0 也保住了** |

**逐轮推演**（`x = 123`，`mask = 100`）：

| 轮次 | `x` | `mask` | `b = x / mask` | 打印 | `x = x % mask` | `mask /= 10` |
|---|---|---|---|---|---|---|
| 1 | 123 | 100 | **1** | `1` | 23 | 10 |
| 2 | 23 | 10 | **2** | `2` | 3 | 1 |
| 3 | 3 | 1 | **3** | `3` | 0 | 0 → 退出 |

→ 输出 `1 2 3` ✅

**mask 法的思路**（打比方）：**先量出这个数有多高**（最高位是百位还是千位），然后**拿着尺子从最高位一格一格往下量**：量一位、把这一位从数里割掉、尺子缩短一格。

**两个细节**：

1. **`x` 被 `%` 改掉了**（循环结束时变 0）—— 如果后面还要用原数，**开头先备份**（我在找 mask 时就是拿 `t` 去缩，没动 `x`；但第二段循环里 `x` 还是被改掉了）。
2. `mask > 0` 判断"后面还有没有位" —— 也可以用 `while (mask > 0)` 改写。

## 5. 复习题（先自己答；**可以欠着**）

1. `x / 10` 和 `x /= 10` 有什么区别？为什么前者会导致死循环？
2. gcc 那句 `statement with no effect` 警告是什么意思？它在提醒我什么？
3. 为什么"先逆序再拆位"处理 `100` 会输出 `1`？（提示：跟 L26 的 `1000 → 1` 是一回事）
4. mask 法里 `x = x % mask` 这一句是干什么的？（拿 `x = 123`、`mask = 100` 举例）
5. mask 法里 `x` 最后变成了几？如果要保留原数，该怎么改？

> [!question]- 参考答案（先自己答完再点开）
>
> 1. `x / 10` 只是**算出商然后丢掉**（变量 `x` 没变）；`x /= 10` 是**把商存回 `x`**。前者等于什么都没做 → 循环条件 `x > 0` 永远成立 → 死循环。
> 2. "**这条语句没有任何效果**"——算出来的值没人接收、变量没被改变。编译器在提醒："你这里大概忘了写 `=`（或者忘了接收返回值）"。
> 3. 因为 `100` 逆序是 `001`，而**整数不保存前导零** → `r` 实际是 `1`，后面那两个 0 从一开始就没进到 `r` 里，自然打印不出来。（跟 `1000 → 1`、`120 → 21` 同一个原因。）
> 4. **把刚打印掉的这一位从数里去掉，保留后面的位**。`123 % 100 = 23` —— 前面那位 1 被丢掉了，剩下 23 交给下一轮。
> 5. 最后变成 **0**（每一位都被 `%` 割走了）。要保留原数就在开头 `int t = x;`，后面用 `t` 参与运算、把 `x` 留着。

## 6. 嵌入式视角

- **"逐位取数"在嵌入式里天天用**：把数值逐位送到**数码管 / LCD / OLED**、把 ADC 读数变成显示字符串、定点数打印时手工插小数点 —— mask 法（先量最高位）就是标准套路，**比"先逆序"更安全**（不会丢位）。
- **`statement with no effect` 这类 bug 在硬件代码里很致命**：比如你写了 `PORTB &= 0xFE;` 想清一位，手一滑写成 `PORTB & 0xFE;` —— **语句合法、编译只有警告、板子行为完全不对**。嵌入式调试中"**代码明明写了但 IO 没变**"，第一件事就是查有没有忘写 `=`。
- **死循环在单片机上不是"卡住"这么简单**：主循环卡死 → **看门狗复位** → 设备反复重启（表现成"开机就重启"）。所以死循环是嵌入式最凶的 bug 之一。
- **mask 的位宽要小心**：`mask *= 10` 到一定程度会接近 `int` 上限（L28 的溢出）。工业代码里会先限制输入范围（比如"最多 9 位数字"），或者用 `long long` 算 mask。
- **`if (后面还有没有位) 补分隔符`** 这个模式，在嵌入式打印/协议组包时到处都是（逗号、空格、换行不能多也不能少）——**判断条件写错一个边界，输出就多一个或少一个分隔符**，跟我这次的 `r > 9` 一样。

## 7. 追问：「最后 `while (mask > 0)` 改成 `x > 0` 为什么会丢 0？」

**实测对照**（同一个程序，只改最后的循环条件）：

| 输入 | 用 **`mask > 0`** | 改成 **`x > 0`** |
|---|---|---|
| 1 | `1` | `1` ✅ |
| **10** | `1 0` | `1 ` ❌ 丢了 0 |
| **100** | `1 0 0` | `1 ` ❌ 丢了两个 0 |
| **1000** | `1 0 0 0` | `1 ` ❌ |
| 105 | `1 0 5` | `1 0 5` ✅ |
| 123 | `1 2 3` | `1 2 3` ✅ |
| **120** | `1 2 0` | `1 2 ` ❌ 丢了尾部的 0 |
| **1200** | `1 2 0 0` | `1 2 ` ❌ |
| **10000** | `1 0 0 0 0` | `1 ` ❌ |

**规律**：**只要"取完最高位之后剩下的都是 0"，用 `x > 0` 就提前退出了。**（105、123 不丢，是因为它们的 `x` 要到最后一轮才变成 0。）

### 为什么（核心：`x` 不是"还剩几位"，`mask` 才是）

| 变量 | 它代表什么 |
|---|---|
| **`x`** | **"剩下的那个数"**（值） |
| **`mask`** | **"还剩几位"**（计数器：100 → 10 → 1 → 0） |

拿 `100` 推一遍：

| 轮次 | `b = x/mask` | 打印 | `x = x % mask` | `mask /= 10` |
|---|---|---|---|---|
| 1 | 100/100 = **1** | `1` | **0**（1 前面没了，100 % 100 就是 0） | 10 |

→ 这时 `x = 0`。**但后面明明还有两位 0 要打！**
`while (x > 0)` 一看 `x = 0` → 以为"没数了" → **提前退出** → 只输出 `1`。

**根子还是那句话**：**整数不保存前导零** ——
"**还剩两位 0**" 和 "**一个数都不剩**"，在 `x` 里长得**一模一样**（都是 `0`），数值上分不出来。

**打比方**：
- `mask` 像**带刻度的尺子**（100、10、1，每量一格缩一格，**明明白白还剩几格**）；
- `x` 像**一截没刻度的胶带**（只剩空白的时候，你根本分不清它还有多长——**长度信息丢了**）。

### 所以

**判断"还有没有位"要用 `mask`（计数器），不能用 `x`（数值）。**
想换别的写法也行，比如另外记一个"位数"变量数着走 —— 关键是**别拿"数值是不是 0"当"还有没有位"**。
