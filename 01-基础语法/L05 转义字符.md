> **一句话总结**：反斜杠 `\` 是一个**开关**，它说"后面这个字符别按它本来的意思理解"。`\n` 不是"反斜杠+n"，而是**换行**。本课最要命的两个：`\0`（字符串的句号，值 0）和 `'0'`（字符零，值 48）。

## 1. 什么是转义字符

**转义 = 改意思**。`\` 一出现，就是告诉编译器：

> **"我后面这个字符，你别按它本来的意思理解。"**

| 写法 | 你以为 | 编译器理解成 |
|---|---|---|
| `n` | 字母 n | 字母 n（97 号字符） |
| `\n` | 反斜杠 + 字母 n（两个字符？） | **一个**字符：换行（值 10） |
| `0` | 数字零 | 数字 0 |
| `\0` | 反斜杠 + 数字零 | **一个**字符：空字符（值 0），字符串的句号 |

> 比方：`\` 就像一个**方言开关**。同一句话，开关一按，意思全变。

## 2. 转义字符表（鹏哥课件这张表，我实跑验证过）

![[L05-转义字符表.png]]

| 转义字符 | 含义 | 我实测的结果 |
|---|---|---|
| `\?` | 书写连续多个问号时使用，防止被解析成三字母词（**新编译器上验证不出来了**） | — |
| `\'` | 用于表示字符常量 `'` | ✅ |
| `\"` | 用于表示字符串内部的双引号 | ✅ 打印出 `"` |
| `\\` | 表示一个反斜杠，防止它被解释为转义序列符 | ✅ 打印出 `\` |
| `\a` | 警报：终端响铃或闪烁 | ✅ 输出里出现 BEL 字节（0x07） |
| `\b` | 退格：光标回退一个字符，**但不删除**字符 | ✅ 输出 `abc` + 退格 + `X` |
| `\f` | 换页。现代系统已反映不出来，行为类似 `\v` | — |
| `\n` | 换行符 | ✅ 值 **10** |
| `\r` | 回车：光标移到**同一行的开头** | ✅ 值 **13** |
| `\t` | 制表符：光标移到下一个水平制表位（通常是 4/8 的倍数） | ✅ 值 **9**，输出里是真正的制表字节 |
| `\v` | 垂直分隔符：光标移到下一行的同一列 | — |
| `\ddd` | ddd 是 **1~3 个八进制**数字。如 `\130` → 字符 `X` | ✅ `\130` 实测 = `X`，十进制 **88** |
| `\xdd` | dd 是 **2 个十六进制**数字。如 `\x30` → 字符 `0` | ✅ `\x30` 实测 = `0`，十进制 **48** |
| `\0` | **null 字符**，表示"没有内容"。它是 `\ddd` 这类转义的一种（八进制的 0），**ASCII 值 = 0**，用于**字符串结束标志** | ✅ 值 **0** |

**实测输出摘要**：

```
\130 = 字符[X]  十进制值[88]
\x30 = 字符[0]  十进制值[48]
\0 的十进制值 = [0]
\0 和 '0' 的值分别是 [0] 和 [48]
连续八进制转义 \101\102\103 = [ABC]
\t \r \n 的值: 9 13 10
sizeof("") = 1, sizeof("a") = 2
```

## 3. 八进制 / 十六进制转义：`\ddd` vs `\xdd`

| 写法 | 进制 | 数字几位 | 例子 | 算给你看 |
|---|---|---|---|---|
| `\ddd` | **八**进制 | 1~3 位 | `\130` = `X` | 1×64 + 3×8 + 0×1 = **88** → ASCII 88 就是 `X` |
| `\xdd` | **十六**进制 | 2 位（前缀 `x`） | `\x30` = `0` | 3×16 + 0 = **48** → ASCII 48 就是字符 `0` |

⚠️ 别混：**`\` 后面直接跟数字 = 八进制**（老式写法），**`\x` 开头 = 十六进制**。

## 4. 乱码的完整因果链（这一版顺序是准的）

```
① VS 调试模式启动程序
   → 把还没用过的栈内存全部预先填成 0xCC
        ↓
② 我的数组 char arr2[] = {'a','b','c'}; 里没有 \0
        ↓
③ printf("%s") 找不到句号，只能往后一直读
   → 读到 ①②③ 后面的 0xCC 0xCC 0xCC...
        ↓
④ 控制台按 GBK 中文编码去解释这些字节
   → 0xCCCC 解出来 = "烫"
```

**验证**：`b"\xcc\xcc"` 按 GBK 解码 = **烫**（我用 Python 亲手验的）。

> 所以"烫"**不是随机乱码**，它是 VS 的"未初始化内存"报警器。看到它就说明：**程序读到了没写过的内存**。（只有在**调试模式 F5** 下才这样，Release 下填的是别的值，可能啥都不显示）

5. VS 控制台出现"烫烫烫"，是**谁**把内存填成 0xCC 的？程序干了什么？

> [!question]- 参考答案（先自己答完再点开）
>
> 1. **八进制**（`\` 后面直接跟数字就是八进制，1~3 位）。= 1×64+3×8+0 = **88** → 字符 **`X`**。
> 2. `\0` = **0**；`'0'` = **48**。一个值是 0，一个值是 48，别混。
> 3. **3 字节**：`h`、`i`、`\0`（末尾那个是双引号自动补的）。字符数 2 + 1 = 3。
> 4. 第一句打印 `反斜杠: \`（`\\` 是一个反斜杠）；第二句打印 `引号: "`（`\"` 是一个双引号）。
> 5. 是 **VS（调试模式的运行时）在程序跑之前**把未初始化内存填成 0xCC 的。程序干的事是：**在内存里乱读，读到了这些 0xCC**（因为字符串没有 `\0` 结尾，`printf` 停不下来）。

## 7. 嵌入式视角

- 单片机发串口数据，`printf("OK\r\n")` 里的 **`\r\n` 是硬性要求**：`\r` 让光标回到行首、`\n` 才换行。只发 `\n`，串口助手上会出现阶梯状的错位显示——这是每个嵌入式入门者都会踩一次的坑。
- 协议解析里 **`\0` 就是"数据到这儿为止"**。接收缓冲区忘了留 `\0` 的位置，就会像今天的乱码一样越界读——在单片机上这不叫乱码，叫**死机/重启**。
- `\0` 的位置决定了缓冲区要开多大：**收 10 个字节的字符串，数组至少要开 11 格**。

## 7. 补充：同一个字符有好几种写法（我 VS 里实测的）

![[L05-四种写法打印Q.png]]

我在 VS 里试了 4 种写法，输出**全是 `Q`**：

```c
printf("%c\n", 'Q');      // 直接写字符
printf("%c\n", '\x51');   // 十六进制转义：51(H) = 81(D)
printf("%c\n", '\121');   // 八进制转义：121(O) = 81(D)
printf("%c\n", 81);       // 直接写 ASCII 码值（数字！）
```

**实测四种全是同一个字符，值都是 81**：

| 写法 | 进制 | 值 | 打印 |
|---|---|---|---|
| `'Q'` | —（字符常量） | 81 | `Q` |
| `'\x51'` | 十六进制 | 81 | `Q` |
| `'\121'` | 八进制 | 81 | `Q` |
| `81` | 十进制数字 | 81 | `Q` |

> **说明**：字符、转义字符、数字，在内存里**都是同一个数字**，只是写法和"身份"不同。这再次印证了 L03 那句话：**字符就是数字**。

### ❌ 但我说错了一处：`'x'` 和 `'\130'` **不相等**

我写的："`printf("%c\n",'x');` 和 `printf("%c\n",'\130')` 输出的结果相同"——**不一样！**

我把两个都跑出来了：

| 写法 | 打印 | 十进制值 |
|---|---|---|
| `'x'` | **`x`**（小写） | **120** |
| `'\130'` | **`X`**（大写！） | **88** |

**`'x' == '\130'` 的实测结果是：不相等。**

错在哪：
1. `'x'` 是**字符 x 本身**，值 120（不是 130——**字母 x 不等于数字 130**）
2. `'\130'` 里 `130` 是**八进制**：1×64 + 3×8 + 0×1 = **88** → 88 号是**大写 `X`**
3. 所以它俩差了一个大小写字母（120 vs 88），**根本不是一个字符**

我大概是想说"同一个字符可以用不同写法表示"，这个方向没错——但**举例必须选真正等值的**。要举例子就用截图里那组：`'Q'` = `'\x51'` = `'\121'` = `81`（四个全等于 81，全打 `Q`）。
