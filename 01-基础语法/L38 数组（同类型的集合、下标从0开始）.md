## 2. 命门：下标从 0 开始（个数 ≠ 最大下标）

**比喻（一排连号的储物柜）**：`int a[3];` = 租了 **3 个**柜子，柜门号码是 **0 号、1 号、2 号** —— 不是 1、2、3 号。

- **总个数 = 3**（柜子有几个）
- **最大号码 = 2**（最后一个柜子的门牌）

两个数**永远差 1**。口诀：**「个数 N，号码 0 到 N-1」**。

### 顺手还清一条旧账：`[ ]` 到底啥意思？

`[ ]` 叫**下标运算符**。同一个方括号，两种场合放两个不同的数：

| 场合 | 写法 | 括号里的数是 | 例子 |
|---|---|---|---|
| **声明**时 | `int a[3];` | **个数** | 租 3 个柜子 |
| **使用**时 | `a[0]` | **门牌号** | 0 号柜子里的东西 |

## 3. 课件（2.1 数组创建）+ 实测证据

课件给的语法：

```c
type arr_name[常量值];
```

三个零件（课件原话）：

- `type` —— 指定数组里存放数据的**类型**（`char`、`short`、`int`、`float` …，也可以自定义类型）
- `arr_name` —— **数组名**，起个有意义的名字就行
- `[]` 中的**常量值** —— 指定数组的**大小**（个数），按实际需求定

> 课件那句话也是"相同类型"四个字的出处：**"存放在数组的值被称为数组的元素，数组在创建的时候可以指定数组的大小和数组的元素类型。"**

### AI 实测（gcc 16.2.0 + MSVC 14.51 双编译器真跑，源码原样）

**① 个数不能是 0（我第 2 句话的实证）**

```c
/* z.c */
#include <stdio.h>
int main(void){
    int a[0];                       /* 想租 0 个柜子 */
    printf("sizeof(a)=%zu\n", sizeof(a));
    return 0;
}
```
```
MSVC:  z.c(3): error C2466: 不能分配常量大小为 0 的数组
       z.c(3): error C2133: “a”: 未知的大小
gcc :  z.c:3:9: error: ISO C forbids zero-size array 'a'    ← 加 -std=c11 -pedantic-errors
```
> ⚠️ 坑：gcc **不加**那个开关时居然放行（`sizeof(a)=0`）—— 那是 GNU 自己的扩展，**不是标准**；VS 更严。

**② 个数必须是"写死的"常量**

```c
/* v.c */
int main(void){
    int n = 3;
    int a[n];      /* 用变量当个数 */
    ...
}
```
```
MSVC: v.c(4): error C2057: 应输入常量表达式
```
> gcc 支持这种写法，叫 **VLA（变长数组）** → 已记进待学，**先别展开**。

**③ 负数个数**

```c
int s[-5];
```
```
MSVC: error C2118: 负下标
gcc : size of array 's' is negative
```

**④ 越界读：不报错、值不可信（本课最重要的一条）**

```c
/* idx2.c */
#include <stdio.h>
int main(void){
    int before = 111;
    int a[3] = {10, 20, 30};
    int after  = 222;
    printf("before=%d after=%d\n", before, after);
    printf("a[0]=%d a[1]=%d a[2]=%d\n", a[0], a[1], a[2]);
    printf("越界读 a[3]=%d   a[-1]=%d\n", a[3], a[-1]);
    return 0;
}
```
```
gcc : 越界读 a[3]=222   a[-1]=-1889535968
MSVC: 越界读 a[3]=222   a[-1]=1694498144
```
两个结论：
1. **`a[3]` 不报错、也不是 0** —— 它读到了隔壁变量 `after` 的值 222（我在数组旁边特意放的）。**这是"别人家的柜子"。**
2. **`a[-1]` 两个编译器打出完全不同的垃圾值**（同一台机器！）→ **越界读到的数没有确定值，不能信、不能拿去写程序。**

**⑤ 常用招：数组有几个人**

```c
sizeof(a) / sizeof(a[0])     /* 实测 12 / 4 = 3，正好是元素个数 */
```

## 4. 复习题 + 我的答案 + 讲评（2026-10-16）

> [!question]- 题目（先自己答完再点开）
>
> 1. `int score[5];` 一共有几个柜子？**最后一个柜子的门牌号是几**？
> 2. 想存 100 个成绩，哪个写法对：`int s[100];` / `int s[0];` / `int s[-5];` —— 另两个为什么不行？
> 3. `int a[3] = {1, 2, 3}; printf("%d\n", a[3]);` 会打出什么？**这个数为什么不能信？**

> [!success]- 讲评
>
> **Q1** 我答「5 个，4」→ ✅ **满分**。个数 5、最大门牌 4，"个数 N，号码 0 到 N-1" 记住了。
>
> **Q2** 我答「`int s[100];`，首先数组的个数不能为 0，其次不能为负」→ ✅ **满分**，两个理由都对。
>
> **Q3** 我答「会越界打出下一个数，但是这个数你没有给我」→ ⚠️ **半对**。
>
> - **对的部分**：`a[3]` 确实越界去读"下一格"了。
> - **要收紧的地方（这条比答案本身重要）**：那个数**不是"应该拿到的数"**，它是**别人家的内存** —— 值取决于当时谁住在数组后面。我实测：`a[3]` 恰好读到 222，是因为我特意在数组旁边放了 `after = 222`；`a[-1]` 在两个编译器上分别是 `-1889535968` 和 `1694498144`（同一台机器）。
> - **最危险的地方**：**编译器不报错、也不警告、程序不崩** —— 静默地给你一个垃圾值。所以"这个数你没给我"这句话刚好点中要害：**它本来就没有确定的值，谁也提前给不了。**
> - **正确回答模板**：「会越界读到数组外面的内存，那个数是什么取决于内存里当时有什么（不可预测、不可依赖）；而且编译器不会报错，这是最坑的地方。」

## 5. 一句话总结

**数组 = 一排连号的柜子，类型全一样、个数写死且 ≥1；柜号从 0 数起，最右边的合法柜号是「个数 − 1」；翻到柜子外面去读，编译器不拦你，但拿到的是别人家的东西。**

## 7. 嵌入式钩子 🔌

数组是单片机里的**货运集装箱**：
- ADC 采样要**连采一串**存起来求平均 → `int adc_buf[32];` 就是那排柜子；
- 串口收数据 → `char rx_buf[64];`，**收多长、别越界**是上板第一天就会咬人的事（L32/悍匠笔试那次 `i <= n` 的越界，根子就在这节课）；
- 以后学指针时会发现 `a[i]` 和 `*(a+i)` 是同一件事 —— 那是数组和指针握手的时刻。
