# L13 时间差计算器（我第一次用 scanf 写实用程序）

- 日期：2026-09-17
- 来源：我在 VS 里自己写的 `day1.c` + 撞到 C4996 报错
- 标签：`#C语言` `#输入输出` `#scanf` `#报错排查`

> **一句话总结**：**代码本身完全正确**——两处报错是 VS 嫌 `scanf` 不安全（`C4996`），**在文件第一行加 `#define _CRT_SECURE_NO_WARNINGS 1` 就能解决**（必须写在所有 `#include` **之前**）。

---

## 1. 我的程序（`day1.c`）

```c
#include <stdio.h>
#include <string.h>
#include <stdbool.h>

int main()
{
    int hour1, minute1;
    int hour2, minute2;
    scanf("%d %d", &hour1, &minute1);
    scanf("%d %d", &hour2, &minute2);

    int ih = hour2 - hour1;
    int im = minute2 - minute1;
    if (im < 0) {
        im = 60 + im;
        ih--;
    }
    printf("时间差是%d小时%d分。\n", ih, im);
    return 0;
}
```

**程序功能**：输入两个时间（先输入开始时间，再输入结束时间），算它们差几个小时几分钟。

## 2. 报错：C4996（两条，都在 `scanf` 那两行）

```
C4996 'scanf': This function or variable may be unsafe.
       Consider using scanf_s instead.
       To disable deprecation, use _CRT_SECURE_NO_WARNINGS.
```

### 错误列表里的行号是 8 和 9 —— 正好就是两行 `scanf`

### 这不是我写错了

VS 认为 `scanf` **不安全**：它读字符串时不知道自己能读多少，用户输入太长就可能冲出边界、踩坏内存（**缓冲区溢出**）。所以 VS 直接把它当**错误**拦住，逼你用微软自己的 `scanf_s`。

**我在 gcc 上编了同一份代码——一个错都没有**，说明**这是 VS 的额外规矩，不是 C 语言的问题**。

## 3. 修法：第一行加宏

```c
#define _CRT_SECURE_NO_WARNINGS 1     // ← 加到【所有 #include 的前面】
#include <stdio.h>
#include <string.h>
#include <stdbool.h>

int main()
{
    int hour1, minute1;
    scanf("%d %d", &hour1, &minute1);     // 现在不报错了
    ...
}
```

⚠️ **唯一的坑：这行必须是文件的第一个东西**，写在 `#include` 后面**不生效**。

**为什么？** 因为 `stdio.h` 一开头就有段"检查这个宏有没有定义"的代码：**宏先定义好，头文件就不报警；写在后面，头文件检查时还看不到它。**

### 我用实验证明了这个道理（原理演示）

我造了一个"迷你头文件"，模仿 `stdio.h` 的做法——一进来就检查某个宏：

```c
/* mylib.h */
#ifdef MYFLAG
#define SCANF_IS_OK 1
#else
#error "MYFLAG 没定义！"
#endif
```

| 写法 | 结果 |
|---|---|
| `#define MYFLAG 1` 写在 `#include "mylib.h"` **之前** | ✅ 编译通过 |
| `#include "mylib.h"` 写在 `#define MYFLAG 1` **之前** | ❌ 报 `error: #error "MYFLAG 没定义！"` |

**实测原文**：

```
bad.c:1: In file included from bad.c:1:
mylib.h:5:2: error: #error "MYFLAG 没定义！这就是 scanf 报 C4996 的根本原因"
```

> 📌 **这就是为什么修 `scanf` 的那行宏必须写在最上面**——不是"随便找个地方写"，是**顺序决定成败**。
> **规律**：`#define` 这类宏，**必须在"要用到它的头文件"之前定义**。

### 另外两种修法

| 方法 | 做法 | 评价 |
|---|---|---|
| ② 项目属性 | 项目 → 属性 → C/C++ → 预处理器 → 预处理器定义 → 加 `_CRT_SECURE_NO_WARNINGS` | 整个项目一次搞定，不用每个文件加 |
| ③ 用 `scanf_s` | 把 `scanf` 全改成 `scanf_s` | ❌ **不推荐**：微软专用，gcc/单片机编译器不认，以后转嵌入式白学 |

## 4. 我的程序逻辑——我实测跑通了 ✅

我把原代码用 gcc 编译（gcc 没这个报错），然后**喂数据进去测**：

| 我输入 | 输出 | 对不对 |
|---|---|---|
| `1 20` + `2 30`（1点20 → 2点30） | `时间差是1小时10分。` | ✅ |
| `1 50` + `2 10`（1点50 → 2点10） | `时间差是0小时20分。` | ✅ |

**连借位那段都是对的**：

```c
if (im < 0) {          // 分钟是负数，说明"退位"了
    im = 60 + im;      // 借 1 小时当 60 分钟：-40 + 60 = 20
    ih--;              // 小时还回去 1
}
```

**1点50 → 2点10**：`ih = 2-1 = 1`，`im = 10-50 = -40` → 进 if → `im = 60 + (-40) = 20`、`ih` 从 1 减成 0 → 输出 **0小时20分** ✔
（这个"借位"思路和小学做减法退位一模一样）

## 7. 嵌入式视角

- **这是你的第一个"真实小程序"**：输入 → 计算 → 输出 → 带条件判断（借位）。**这个结构和单片机的程序完全一样**，只是输入从键盘换成传感器、输出从屏幕换成串口/LCD。
- **`scanf` 在单片机上基本不用**（没有键盘），但**它背后的思路你要记住**：`%d %d` 表示"我要两个整数"。以后从串口收数据、从按键读值，本质是一回事。
- **"借位"这种思路在嵌入式里到处是**：处理时间的时分秒、定时器的分频、把毫秒拆成时分秒——**都是同一套进退位逻辑**。
- **`scanf` 的不安全问题在嵌入式里是真实的大事故来源**：单片机收到串口数据往缓冲区里塞，**不检查长度**就是经典的缓冲区溢出漏洞。VS 拦你是"唠叨"，但这是有道理的唠叨——以后你要自己写"检查长度"的代码。
