# L18 缩进是什么 + if 的花括号什么时候能省

- 日期：2026-09-21
- 来源：我的提问 —— ①「缩进是什么意思」②「有 else 的时候，前面的 `printf()` 后面为什么不接 `{}`」
- 素材：翁恺《C语言程序设计》if 语句那节课件 + 我在 VS 里写的工资程序、成绩程序
- 标签：`#C语言` `#基础语法` `#分支` `#缩进` `#花括号`

> **一句话总结**：
> **缩进是给人看的（C 编译器完全不看它）**；真正决定"哪句归谁管"的是 **`{}` 和 `;`**。
> `if` 只管**紧跟它的那一条语句**（一条 = 到 `;` 为止）。想让 `if` 一次管好几句，就用 `{}` 把它们**打包成一句**。
> 所以单个 `printf(...);` 后面可以不带 `{}`——翁恺课件和你写的就是这种。

---

## 1. 缩进是什么

**缩进 = 每行开头的空格**（或 Tab），把代码往里推几格，看起来有层次。

打个比方：**像写信时的分层列举**——「1. 第一点」下面缩进去写的是它的细节。**读的人一眼就知道"哪条属于哪条"**。但纸张本身、文字本身并不在乎你缩没缩。

```
没有缩进（能跑，但看着累）        有缩进（一眼看出层次）
int score = 77;                  int score = 77;
if (score > 60) {                if (score > 60) {
printf("及格\n");                    printf("及格\n");
}                                }
else {                           else {
printf("不及格\n");                  printf("不及格\n");
}                                }
```

### ⚠️ 关键：**C 语言完全不看缩进**

- **Python 才靠缩进决定逻辑**（缩错会报错）；
- **C 的缩进只是"排版"，删光也照样跑**——我在本机实测：

```c
int main(void)
{
int score = 77;
if (score > 60) {
printf("及格\n");
}
else {
printf("不及格\n");
}
return 0;
}
```

```
实测输出：及格        ← 缩进全删，结果一模一样 ✅
```

**结论**：缩进不影响结果，但**必须写**——因为你要靠它读代码，VS 也靠它帮你判断"这句归谁"（下一节的那个警告就和缩进有关）。

> 🛠️ **VS 里怎么让缩进自动长出来**：打 `{` 后回车，VS 会自动缩进；打 `}` 会自动往外退。要是乱了，全选（`Ctrl+A`）→  `Ctrl+K` 再按 `Ctrl+D`（中文菜单：**编辑 → 高级 → 设置文档的格式**）一键重排。

## 2. C 到底看什么：`;` 和 `{}`

| 符号 | 作用 | 比方 |
|---|---|---|
| `;` | **一句话说完** | 句号 |
| `{ }` | 把里面**几句打包成"一句"**（复合语句） | 用夹子把几张纸夹成一叠 |

`if` 的语法格式其实就一行：

```
if (条件)  语句        ← 注意：这里是"一条语句"，不是"必须是大括号"
else       语句
```

**"一条语句"的定义**：要么是**以 `;` 结尾的单句**，要么是 **`{ }` 包起来的一整块**。
两种都叫"一条"，所以**两种写法都合法**。

## 3. 所以两种写法都行（这就是你问题的答案）

### 写法A：单句 —— 花括号可省（翁恺课件 / 你写的）

```c
if (score > PASS)
    printf("恭喜你通过了考试！\n");
else
    printf("很遗憾，你并没有通过考试\n");
```

**怎么读**：

```c
if (score > PASS)                    /* 条件成立吗？ */
    printf("恭喜你通过了考试！\n");   /* ← 这一条（到 ; 结束）归 if 管 */
else                                 /* 条件不成立 → 跳到这儿 */
    printf("很遗憾，你并没有通过考试\n"); /* ← 这一条归 else 管 */
```

- 每一边只有**一条语句** → 可以不带 `{}`；
- 缩进只是**帮你看出**"这一条归 if"（编译器不看）；
- **实测**（gcc，score = 77）：输出 `恭喜你通过了考试！` ✅

### 写法B：加花括号 —— 更保险（工程上的推荐）

```c
if (score > PASS)
{
    printf("恭喜你通过了考试！\n");
}
else
{
    printf("很遗憾，你并没有通过考试\n");
}
```

结果**完全一样**，但以后要往里加语句时不用再补括号。

## 4. ⚠️ 省花括号的代价（两个坑，都实测过）

### 坑①：想执行两句却不写 `{}` → 第二句永远执行

```c
if (score > PASS)
    printf("第1句：恭喜你通过了考试！\n");
    printf("第2句：这行永远会执行\n");     /* ← 它不属于 if！ */
```

**实测输出**（score = 30，不及格）：

```
第2句：这行永远会执行
--- 分隔线 ---
```

**第1句没打印**（因为不及格，归 `if` 管、被跳过），**第2句照样打印**（它是独立语句）。
gcc 还会当场警告：

```
warning: this 'if' clause does not guard... [-Wmisleading-indentation]
note: ...this statement, but the latter is misleadingly indented as if it were guarded by the 'if'
```

> **警告的意思**：你缩进得像归 `if` 管，其实不归。**加上 `{}` 就对了**。

### 坑②：`if (...)` 后面多写一个分号（翁恺课件里强调的那条）

```c
if (score > PASS);                    /* ← 这个 ; 把 if 管的对象变成"空语句" */
{
    printf("这行和 if 没关系，永远执行\n");
}
```

**"圆括号后面不能加 `;`"**——加了，`if` 管的就是那句"空话"，后面的 `{}` 变成独立的一块。

## 5. 顺手抓到你代码里的一个真 bug 🐛

![[L18-成绩程序（printf漏了格式符）.png]]

第 77 行：

```c
printf("你输入的成绩是：", score);      /* ← 格式串里少了 %d */
```

**后果**：`score` 这个值根本**没被打印出来**。看你自己那张调试截图：

```
请输入成绩：77
你输入的成绩是： 恭喜你通过了考试！        ← "成绩是："后面啥都没有，分数丢了
```

**正确写法**：

```c
printf("你输入的成绩是：%d\n", score);
```

**AI 实测对比**（gcc）：

| 写法 | 输出 |
|---|---|
| `printf("你输入的成绩是：", score);` | `你输入的成绩是：` ← 分数没出来 |
| `printf("你输入的成绩是：%d\n", score);` | `你输入的成绩是：77` ✅ |

gcc 还会警告：`warning: too many arguments for format [-Wformat-extra-args]`（格式串里没有占位符，却多给了一个参数）。

> **规则**：`printf` 里**要打印的值，必须在格式串里有一个对应的 `%d` / `%f` / `%c` / `%s` 占位**。
> 参数给了、占位符忘了写 → **编译不报错，值就是不显示**（最容易漏看的坑）。

## 6. 顺便：你的工资程序是对的 ✅

![[L18-工资程序（单句不写花括号）实测.png]]

```c
const double RATE = 8.25;
const int STANDARD = 40;
int hours;
double pay = 0.0;

printf("请输入工作的小时数：");
scanf("%d", &hours);
printf("\n");
if (hours >= STANDARD)
    pay = STANDARD * RATE + (hours - STANDARD) * (RATE * 1.5);
else
    pay = hours * RATE;
printf("应付工资：%f\n", pay);
```

- **AI 独立验算**（同样参数、自己重新编译跑一遍）：`55 小时 → 应付工资：515.625000`，**和你截图一模一样** ✅
- 逐句核对：

| 检查点 | 判定 |
|---|---|
| `const double RATE = 8.25;` 常量写法 | ✅ |
| `if / else` 单句不写 `{}` | ✅ 合法（翁恺课件同风格） |
| 加班公式 `STANDARD*RATE + 超出部分*1.5倍` | ✅ 正确 |
| `scanf("%d", &hours);` 有 `&` | ✅ |
| `printf("%f")` 打印 `double` | ✅ 对（小知识：`printf` 里 `double` 用 `%f`；`%lf` 也能用） |
| 提示语结尾没有 `\n`（"请输入工作的小时数：55"黏在一行） | ⚠️ 小瑕疵，靠下一行 `printf("\n")` 补了回来 |

## 7. 复习题（先自己答）

1. 把一段代码的缩进全部删掉，程序结果会变吗？为什么？
2. `if (a > b) printf("X\n"); printf("Y\n");` 里，哪一句归 `if` 管？`a <= b` 时会打印什么？
3. 想让 `if` 一次管住两条 `printf`，必须做什么？
4. `if (a > b);` 后面那个分号会带来什么后果？
5. `printf("成绩是：", score);` 会输出什么？错在哪？

> [!question]- 参考答案（先自己答完再点开）
>
> 1. **不会变。** C 语言**不看缩进**（只有 Python 那类语言才看）。缩进是给人读的排版；决定逻辑的是 `;` 和 `{}`。
> 2. **只有 `printf("X\n");` 归 `if` 管**（`if` 只管紧跟的一条语句）。`a <= b` 时：X 不打印，**Y 照样打印**（它是独立语句）。
> 3. **用 `{}` 把这两条包成一块**（复合语句），`if` 就管这一整块了。
> 4. 那个 `;` 是**空语句**：`if` 只"管住"这句空话，后面的语句跟 `if` 无关、**永远执行**。（翁恺课件里强调的"圆括号后面不能加分号"就是这个）
> 5. 输出只有 `成绩是：`，**分数不显示**。因为格式串里**少了 `%d`**——参数给了、占位符没写。正确：`printf("成绩是：%d\n", score);`

## 8. 嵌入式视角

- **`{}` 在嵌入式里是"自保"**：中断服务函数、状态机里常常要在 `if` 里补语句，一开始省了花括号，后来加一行就悄悄掉进坑①——**规范（MISRA 等）直接要求 `if`/`else` 一律带 `{}`**，不管几条语句。
- **缩进在嵌入式里还多一层用**：查寄存器配置时，同一段代码在不同优化等级/不同分支下的行为靠"缩进层次"才能快速扫出来，省下来的时间就是加班时间。
- **`printf` 的坑在单片机上是"串口打印调不出来"**：调试嵌入式时全靠串口 `printf` 看变量，**漏一个 `%d` 就是你盯着串口助手一脸茫然**——今天这个坑，以后在板子上会再遇到一次。
