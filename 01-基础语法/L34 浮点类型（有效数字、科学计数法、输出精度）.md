## 2. 有效数字是什么（打比方）

**比方：浮点数 = 一把能拉很长的卷尺，但刻度只有 7 格。**

- 卷尺能拉到 10³⁸ 那么长（**范围大**）—— 这是 `float` 的"范围 `±3.40×10³⁸`"那一列
- 但从头到尾**只有 7 格刻度**（**有效数字**）—— 你量出 `1.234567` 后面的数字**全是估的**
- `double` 就是同一把卷尺，刻度 15 格（而且更长）

所以表里那两列是**两件事**：
| 列 | 管什么 | 比喻 |
|---|---|---|
| 范围 | 能表示多大/多小 | 卷尺能拉多长 |
| 有效数字 | 能表示多细 | 尺子上有几格刻度 |

**实测坐实（真数字，不是比喻）**：

```c
float g = 1.23456789f;
printf("%.15f\n", (double)g);      // 1.234567880630493
```
我给的 `1.23456789`，**前 7 位 `1.234567` 对上了，第 8 位起是垃圾**（`8898...` 而不是 `89`）。

```c
float f = 16777217.0f;             // 2^24 + 1
printf("%f\n", (double)f);         // 16777216.000000   ← 少了 1
```
`float` 的尾数只有 **24 位二进制**，整数超过 `2²⁴ = 16777216` 就**存不下奇数**了。

```c
double h = 1.234567890123456789;
printf("%.25f\n", h);              // 1.2345678901234566904321355
double d = 9007199254740993.0;     // 2^53 + 1
printf("%.1f\n", d);               // 9007199254740992.0  ← 也少了 1
```
`double` 给到 16 位；到 `2⁵³ = 9007199254740992` 这个坎，同样开始丢 1。

> 🔎 严谨补一句：C 标准宏写的是 `__FLT_DIG__` = **6**、`__DBL_DIG__` = **15**（我实测取的 ARM 工具链的宏）。课件写 float「7 位」是**常见的约数说法**。记「float 约 7 位 / double 约 15~16 位」够用。

## 3. 实测程序 + 真实输出（源码照抄，可自己编译）

```c
#include <stdio.h>

int main(void)
{
    printf("sizeof(float)=%d  sizeof(double)=%d\n\n", (int)sizeof(float), (int)sizeof(double));

    /* ---- 1. 有效数字：float 7 位 / double 15~16 位 ---- */
    float g = 1.23456789f;
    printf("[1] float  1.23456789        -> %%.15f = %.15f\n", (double)g);
    float f3 = 16777217.0f;                 /* 2^24 + 1 */
    printf("[1] float  16777217 (2^24+1) -> %%f  = %f\n", (double)f3);
    double h = 1.234567890123456789;
    printf("[1] double 1.234567890123456789 -> %%.25f = %.25f\n", h);
    double d3 = 9007199254740993.0;         /* 2^53 + 1 */
    printf("[1] double 9007199254740993 (2^53+1) -> %%.1f = %.1f\n", d3);

    /* ---- 2. 课件那张图：double ff = 1E-10; ---- */
    double ff = 1E-10;
    printf("\n[2] %%.16f = %.16f\n", ff);
    printf("[2] %%.30f = %.30f\n", ff);
    printf("[2] %%E    = %E\n", ff);
    printf("[2] %%a(十六进制浮点，二进制真相) = %a\n", ff);

    /* ---- 3. 输出精度那张图 ---- */
    printf("\n[3] %%.3f  of -0.0049  = %.3f\n", -0.0049);
    printf("[3] %%.30f of -0.0049  = %.30f\n", -0.0049);
    printf("[3] %%.3f  of -0.00049 = %.3f\n", -0.00049);

    /* ---- 4. 经典：0.1 + 0.2 ---- */
    printf("\n[4] 0.1+0.2      = %.20f\n", 0.1 + 0.2);
    printf("[4] 0.1+0.2==0.3 -> %d\n", 0.1 + 0.2 == 0.3);

    /* ---- 5. 科学计数法的写法与 %e 输出 ---- */
    printf("\n[5] %%.2e of 12345.678 = %.2e\n", 12345.678);
    printf("[5] %%e   of 0.0001234 = %e\n", 0.0001234);
    printf("[5] %%E   of 5.67E+16  = %E\n", 5.67E+16);
    printf("[5] 省符号的 1e10    = %E\n", 1e10);   /* 不写 + 号 */
    printf("[5] 小数点可省的 .5e3 = %E\n", .5e3);
    return 0;
}
```

## 4. 课件 5 张的关键点

### ① 浮点类型表（`_附件/L34-01`）

| 类型 | 字长 | 范围 | 有效数字 |
|---|---|---|---|
| `float` | 32 位（4 字节，实测 `sizeof(float)=4` ✅） | `±(1.20×10⁻³⁸ ~ 3.40×10³⁸)`, `0, ±inf, nan` | 7 |
| `double` | 64 位（8 字节，实测 `sizeof(double)=8` ✅） | `±(2.2×10⁻³⁰⁸ ~ 1.79×10³⁰⁸)`, `0, ±inf, nan` | 15 |

- `inf` = 无穷大（`1.0/0.0`），`nan` = not a number（`0.0/0.0`）—— 浮点**不会因为超范围而"绕圈变负数"**（对比 L28 的 `int` 溢出），它直接变 `inf`
- ⚠️ 这就是浮点和整数的**根本区别**：整数溢出**绕圈**，浮点溢出**变成 inf**
- **实测坐实**（源码：`float big = 3.4e38f; printf("%f", (double)(big*10.0f));`）：
  ```
  3.4e38f * 10 = inf
  1.0/0.0      = inf
  0.0/0.0      = -nan(ind)     ← 本机(UCRT)的叫法
  -1.0/0.0     = -inf
  ```
  ⚠️ 小坑：`nan` 和 `inf` **各平台印法不同**（本机 Windows 印 `-nan(ind)`，Linux 印 `nan`）——所以看到 `-nan(ind)` 别慌，就是"不是数"

### ② scanf / printf 格式表（`_附件/L34-02`）——**最容易考**

| 类型 | scanf | printf |
|---|---|---|
| `float` | `%f` | `%f`、`%e` |
| `double` | **`%lf`** | `%f`、`%e` |

- **口诀**：`printf` 的 `%f` **两种都收**（因为默认提升成 double）；`scanf` 必须分清 —— **`float` 用 `%f`、`double` 用 `%lf`**（`l` 就是 long，`double` 比 `float` 长）
- 反过来说：`scanf` 里写 `%f` 去接 `double` **不会报错但会读到垃圾**（这是最阴的坑，编译器不一定提醒）

### ③ 科学计数法写法（`_附件/L34-03`）—— `-5.67E+16`

| 位置 | 规则 |
|---|---|
| `E` | 可用 **`e` 或 `E`**，一样 |
| 前面 | 可选的 `+` / `-` 号 |
| 小数点 | **可省**（`.5e3` = 500，实测 `5.000000E+02` ✅） |
| 指数符号 | 可以是 `-` 或 `+`，**也可以省略（表示 +）**（`1e10` 实测 = `1.000000E+10` ✅） |
| 整词 | **不能有空格** |

### ④ `double ff = 1E-10; printf("%E,%.16f\n", ff, ff);`（`_附件/L34-04`）

实测：`%E` → `1.000000E-10`；`%.16f` → **`0.0000000001000000`**

**这里有个陷阱**：`%.16f` 打印出来**看着干干净净**，好像 `1E-10` 存的就是精确值。其实不是 —— 拉长到 30 位就露馅：

```
%.16f = 0.0000000001000000
%.30f = 0.000000000100000000000000003643
                                  ↑ 从这儿开始就是"估"的
%a    = 0x1.b7cdfd9d7bdbbp-34       ← 二进制真身，一看就不是整齐的 1
```

**原理**：小数 0.1 = 1/10，**分母 10 里有质因数 5**，而二进制只能平分（1/2, 1/4, 1/8…）—— 除不尽，只能无限逼近。所以十进制小数「无法被二进制精确表达」的根源**不是位数不够，是进制不对**。
（对照：`0.5 = 1/2` 分母只有 2 → 二进制 `0.1` 精确；`0.25 = 1/4` 精确）

### ⑤ 输出精度（`_附件/L34-05`）

- `%` 和 `f` 之间加 `.n` → 指定**小数点后几位**，**四舍五入**
- 实测：`%.3f` of `-0.0049` → `-0.005`；`%.3f` of `-0.00049` → **`-0.000`** ⚠️（不显示负号消失，是 **`-0.000`**；四舍五入成 0 了但**符号还在**）
- `%.30f` of `-0.0049` → `-0.004899999999999999841793218991` ← `-0.0049` 存进去**根本不是 -0.0049**

## 5. 两条必背的新坑

1. **浮点数不能用 `==` 比较**：实测 `0.1 + 0.2 == 0.3` → **`0`（假）**，因为 `0.1+0.2 = 0.30000000000000004441`。要比就用 `fabs(a-b) < 1e-6`
2. **`%.16f` 印出来"整齐"不代表值精确**：精度（打印几位）和有效数字（存得准几位）是两码事。**打印的位数超过有效数字，后面就是幻觉**

## 6. 🔌 嵌入式视角（以后在单片机哪里用得上）

- 我在 **STM32 的 ARM 工具链**上实测过编译期宏：`__SIZEOF_FLOAT__=4`、`__SIZEOF_DOUBLE__=8`、`__DBL_DIG__=15` —— **`double` 在 STM32 上还是 8 字节，跟 PC 一样**。但 **Cortex-M4 以下没有硬件双精度单元，双精度运算靠软件模拟，慢几十倍** → 单片机里**默认用 `float`**，别用 `double`
- 传感器数据（ADC、温度、IMU）天然是 `float` 量级，记住**只有 7 位有效数字**：几千次累加会**累积误差**（这也是为什么算总和有时改用定点整数）
- 串口打印浮点：`printf("%f")` 在单片机上会**把整个浮点打印库链进去**，Flash 多吃好几 KB —— 嵌入式常用「把 `float` 乘 100 当 `int` 打印」的土办法
- 和 L28（整数溢出绕圈）对照记：**整数溢出绕圈、浮点溢出变 `inf`** —— 上板采集数据时后者更好抓（一看就知道炸了），前者最阴

## 7. 复习题（先自己答，再点开）

> [!question]- Q1 基础：`float` 和 `double` 各占几个字节？有效数字各几位？
>
> **答**：`float` 4 字节 / 有效数字约 7 位；`double` 8 字节 / 约 15 位。

> [!question]- Q2 课件原题：`printf("%.3f\n", -0.00049);` 输出什么？
>
> **答**：`-0.000`。四舍五入成 0 了，**但负号还在**（实测坐实）。

> [!question]- Q3 解释题：为什么 `float x = 1.23456789f;` 存进去以后，只有前 7 位是"真"的？
>
> **答**：`float` 的"刻度"只有 7 格（有效数字 7 位）。实测存进去是 `1.234567880630493`，前 7 位 `1.234567` 对得上，第 8 位起是二进制近似产生的"垃圾"。

> [!question]- Q4 结合题：为什么 `0.1 + 0.2 == 0.3` 是假？
>
> **答**：`0.1`、`0.2`、`0.3` 都是分母含 5 的十进制小数，**二进制除不尽**，存进去都是近似值；近似值相加后是 `0.30000000000000004441`，不等于存成另一个近似值的 `0.3`。所以浮点**不能用 `==`**。

> [!question]- Q5 拐弯题：`1E-10` 用 `%.16f` 打印是 `0.0000000001000000`，干干净净。它是精确值吗？怎么才能看出来不是？
>
> **答**：不是。**把精度拉长**（`%.30f` → 尾巴 `...0000003643`）或者用 `%a` 看二进制真身（`0x1.b7cdfd9d7bdbbp-34`，明显不是整齐的 1）。**打印位数超过有效数字，多出来的就是幻觉。**

## 8. 补充：为什么 `1.345f` 后面要加个 `f`？（他追问，2026-10-02）

**✅ 全是实测的（gcc 16.2 跑数字、MSVC 14.51 跑警告）**

### 先说他的误解

他问：「它前面不是已经用 `float` 定义过了吗？为什么这里还要加 `f`？」

**误解点：把"变量的类型"和"数字的类型"当成一回事了。**

- `float a;` 里的 `float` —— 是给**盒子**贴的标签，管的是变量 `a` 能装什么
- `1.345f` 里的 `f` —— 是给**数字本身**贴的标签，管的是这个常量出厂时是什么型号

**比方**：`float a` 是"一个只能放小号东西的盒子"；等号右边 `1.345` 这个数字**出厂默认是大号（`double`）**。往小盒子里塞大号东西，编译器得**削一刀**（截断）。加个 `f` 就是告诉编译器「这个数出厂就是小号的，不用削」。

> 📌 C 的规矩：**小数常量默认是 `double`**（比如 `1.345`、`2.468`）。要当 `float` 用，得手动加后缀 `f` 或 `F`。

**他第二次追问（2026-10-02）：不加 `f`，是不是"先把这个 `a` 定义成 double，再转成 float"？**

**一半对** —— 确实**多走了 double→float 这一步**，但**不是把变量 `a` 定义成 double**（你写的就是 `float a`，`a` 从头到尾都是 float）。真相是**那个数字 `1.83` 自己天生就是 `double` 类型**（见上面那条 C 的规矩）。真实顺序：

`1.83`（十进制）→ 最接近的 **double** 值 → 最接近的 **float** 值 → 存进 `a`
（**两步都在编译期就做完了**，运行时没有转换动作）

加 `f` 就是**少走一步**：十进制直接按 float 算一次。

**实测证据（源码 + 输出）**：
```c
#include <stdio.h>
#include <string.h>
static unsigned B(float f){ unsigned u; memcpy(&u,&f,4); return u; }
float g1 = 1.83;    /* 不带 f */
float g2 = 1.83f;   /* 带 f   */
int main(void){
    float x1 = 1.83, x2 = 1.83f;
    printf("a1 (不加f) 的字节 = %08X  -> %.20f\n", B(x1), (double)x1);
    printf("a2 (加 f ) 的字节 = %08X  -> %.20f\n", B(x2), (double)x2);
    printf("相等? %d\n", x1 == x2);
    return 0;
}
```
```
a1 (不加f) 的字节 = 3FEA3D71  -> 1.83000004291534423828
a2 (加 f ) 的字节 = 3FEA3D71  -> 1.83000004291534423828
相等? 1
```
再让**全局变量**把常量直接摆进汇编（`gcc -S`）：
```
g1:  .long  1072315761
g2:  .long  1072315761     ← 同一个数（1072315761 = 0x3FEA3D71）
```
**这两行就是"转换在编译期完成"的铁证** —— 汇编里直接就是最终的 4 字节 float，程序跑起来**根本没有 double→float 的动作**。

> 🔎 理论边角（**不用管**）：两步近似（小数→double→float）在数学上叫"双重舍入"，理论上可能与一步近似（`1.83f`）差最后 1 个二进制位。实测常见写法没差过，初学阶段按"两种写法结果一样"记就行。

### 为什么不能偷懒？（课件第 3 张图 `_附件/L34-08`）

课件那段代码的真凶不是"`==` 不能比浮点"，而是**两边类型不一样**：

```c
float a = 1.345f, b = 1.123f, c;
c = a + b;
printf("c = a+b          = %.10f\n", (double)c);
printf("c == 2.468  (double没后缀) -> %d\n", c == 2.468);
printf("c == 2.468f (float有后缀)  -> %d\n", c == 2.468f);
printf("(double)c      = %.20f\n", (double)c);
printf("2.468  当double = %.20f\n", 2.468);
printf("2.468f 当float  = %.20f\n", (double)2.468f);

float x1 = 1.345;    /* 不加 f：double 常量转成 float */
float x2 = 1.345f;   /* 加 f  ：直接是 float 常量 */
printf("x1 == x2  -> %d\n", x1 == x2);
```

**真实输出**：
```
[1] c = a+b          = 2.4679999352
[2] c == 2.468  (double没后缀) -> 0        ← 假！
[3] c == 2.468f (float有后缀)  -> 1        ← 真
[4] (double)c      = 2.46799993515014648438
[5] 2.468  当double = 2.46799999999999997158   ← 和 [4] 不是一个数
[6] 2.468f 当float  = 2.46799993515014648438   ← 和 [4] 一模一样
[7] x1(不加f) = 1.3450000286
[8] x2(加 f ) = 1.3450000286
[9] x1 == x2  -> 1                         ← 单看赋值，加不加 f 结果一样
```

**看懂 [4][5][6] 三行就全懂了**：
- `c` 真实的二进制值是 `2.46799993515014648438`
- `2.468` 当 **double** 是 `2.46799999999999997158` ← **另一个近似值**
- `2.468f` 当 **float** 才是 `2.46799993515014648438` ← **和 c 完全相同**

所以 `c == 2.468` 是拿**两个不同的近似值**在比 → **假**。写成 `2.468f` 就真。
**根子**：比较时 `c`（float）被**提升成 double** 去比，于是"float 的近似"和"double 的近似"对不上。

### VS 里的警告（MSVC 14.51 实测，`/W3` 就是 VS 默认等级）

```c

```
```
warn.c(4): warning C4305: "初始化": 从"double"到"float"截断
```
```c

```
```
（无警告，干净编译）
```

⚠️ 所以 [9] 说明**加不加 f 结果一样**（这台机器上 `1.345` 转 float 和 `1.345f` 是同一个值）—— **加 `f` 不是为了改值，是为了：① 不挨 VS 的警告；② 比较/表达式里不被悄悄提升成 double**。

### 三条必背

1. **`1.345` 是 double，`1.345f` 才是 float** —— 小数常量默认 double
2. `float` 变量赋值：**加 `f`**（否则 VS 报 `C4305`）
3. `scanf` 里 `float` 用 `%f`、`double` 用 `%lf`；**printf 都用 `%f`**（对照第 4 节表）

## 9. 浮点数的内部表达（1 + 11 + 52 位编码）——他的笔记自查

> 课件新增 2 张：`_附件/L34-09-容差与fabs.png`、`_附件/L34-10-浮点数的内部表达.png`

### 9.1 他自己的总结（原话）逐句判定

> 他的原话：「整数一定是精准的，小数不一定是精准的，整数内部是二进制纯二进制数，所以两个整数可以直接做运算，可以直接加减。但是浮点数内部是一种编码形式，它用一个比特来表达正负，1 些比特、52 个比特来表达小数部分是多少」

| 他的原话 | 判定 | 说明 |
|---|---|---|
| 「整数一定是精准的」 | ⚠️ 补条件 | 要加「**在类型的范围内**」—— 溢出就绕圈（L28：`INT_MAX + 1 = -2147483648`），那时候一点都不精准 |
| 「小数不一定是精准的」 | ✅ | 对 |
| 「整数内部是纯二进制数」 | ⚠️ **半对** | **非负整数**才是纯二进制；**负数存的是补码**（L33 刚学过：`-1` 是 `11111111`，不是"负号 + 1"） |
| 「所以两个整数可以直接做运算、直接加减」 | ⚠️ 因果偏了 | **浮点也能直接加减**（课件原话：*浮点数在计算时是由专用的硬件部件实现的*），不是"整数才能直接算"。真正的区别是**刻度**：整数是**均匀刻度**（每格都是 1），浮点是**不均匀刻度**（越靠近 0 越密、越远越稀） |
| 「浮点数内部是一种编码形式」 | ✅ | 对，就是 IEEE 754 编码 |
| 「1 个比特表示正负」 | ✅ | 对（`sign`） |
| 「1 些比特」 | ⚠️ 含糊 | 那是 **`exponent` 指数**，**而且是最关键的一段**，不能一句"一些比特"带过 —— 它决定**范围** |
| 「52 个比特表达小数部分是多少」 | ⚠️ **要改两处** | ① **52 位是 `double` 的**，`float` 只有 **23 位**；② 52 位表示的是**有效数字（尾数 fraction）**，**不是"小数点后多少位"** —— 它跟"十进制有效数字 7/15"直接挂钩 |

### 9.2 真正的排布（课件第 2 张图）

```
double (64 位)：   [符号 1] [指数 11] [尾数 52]
                    63      62..52     51..0
float  (32 位)：   [符号 1] [指数  8] [尾数 23]
```

| 段 | float | double | 管什么 |
|---|---|---|---|
| `sign` 符号 | 1 位 | 1 位 | 正负 |
| `exponent` 指数 | 8 位 | 11 位 | **范围**（能多大/多小）—— 实测 `2^8 = 256` 种 / `2^11 = 2048` 种 |
| `fraction` 尾数 | 23 位 | 52 位 | **有效数字**（能多准）—— 实测 `2^23 = 8388608` 个刻度 / `2^52 = 4503599627370496` 个刻度 |

**两段位数直接对应第 1 节那两个结论**：
- 尾数 23 位 → 刻度 8388608 → 十进制约 **7 位**有效数字 ✅
- 尾数 52 位 → 刻度 4503599627370496 → 十进制约 **15~16 位**有效数字 ✅
- 指数 8 位 → 范围到 `10^±38`；指数 11 位 → 范围到 `10^±308` ✅

> 📌 还有个**隐含的 1**：规格化浮点数的尾数前面永远有个隐含的 `1.`，不存进内存（省一位、白赚一位精度）。所以实际精度是 `1 + 52 = 53` 位（这就是 `__DBL_MANT_DIG__ = 53` 的来历）。

### 9.3 实测：把 `float 1.83` 拆成三段再拼回去

```c
#include <stdio.h>
#include <math.h>
#include <string.h>

static void dumpd(double d){ unsigned char b[8]; int i; memcpy(b,&d,8);
    for(i=7;i>=0;i--) printf("%02X ", b[i]); printf("\n"); }

int main(void)
{
    double one = 1.0;  float fone = 1.0f;
    unsigned char fb[4]; memcpy(fb,&fone,4);
    printf("double 1.0 的 8 字节 = "); dumpd(one);
    printf("float  1.0 的 4 字节 = %02X %02X %02X %02X\n", fb[3],fb[2],fb[1],fb[0]);

    float x = 1.83f; unsigned u; memcpy(&u,&x,4);
    unsigned sign = u >> 31, exp = (u >> 23) & 0xFF, frac = u & 0x7FFFFF;
    printf("\nfloat 1.83 = 0x%08X\n", u);
    printf("  符号(1 位)    = %u  -> %s\n", sign, sign ? "负" : "正");
    printf("  指数(8 位)    = %u  -> 真指数 %d\n", exp, (int)exp - 127);
    printf("  尾数(23 位)   = %u (0x%06X)\n", frac, frac);
    double rebuilt = (1.0 + frac / 8388608.0) * pow(2.0, (int)exp - 127);
    printf("  用这三段手工拼回去 = %.20f\n", rebuilt);
    printf("  原值              = %.20f\n", (double)x);
    printf("  一样吗? %d\n", rebuilt == (double)x);
    return 0;
}
```

**真实输出**：
```
double 1.0 的 8 字节 = 3F F0 00 00 00 00 00 00
float  1.0 的 4 字节 = 3F 80 00 00

float 1.83 = 0x3FEA3D71
  符号(1 位)    = 0  -> 正
  指数(8 位)    = 127  -> 真指数 0
  尾数(23 位)   = 6962545 (0x6A3D71)
  用这三段手工拼回去 = 1.83000004291534423828
  原值              = 1.83000004291534423828
  一样吗? 1
```

**"编码形式"这句话的最硬证据**：我把 `0x3FEA3D71` 拆成 1+8+23 三段，用公式 `(1 + 尾数/2²³) × 2^(指数−127)` **手工拼回去**，得到 `1.83000004291534423828`，和编译器存的一模一样。说明内存里就是这三段，不是"1.83"本身。

（顺带看第 1 行：`double 1.0` 是 `3F F0 00...`、`float 1.0` 是 `3F 80 00 00` —— `3F` 开头那段就是指数，`1.0` 的尾数是全 0，因为整数部分那个 1 是隐含的。）

### 9.4 课件那张容差图（`_附件/L34-09`）里的坑

课件写 `fabs(f1 - f2) < 1e-12` —— **这个阈值是给 `double` 用的，给 `float` 太严了**：

```
c           = 2.4679999352
c - 2.468   = -0.00000006484985348720      ← 差 6.5e-8
c - 2.468f  = 0.00000000000000000000       ← 加 f 后差 0
fabs(c-2.468)  < 1e-12 ? 0    ← 假！1e-12 太严
fabs(c-2.468f) < 1e-12 ? 1    ← 真
fabs(c-2.468)  < 1e-6  ? 1    ← 真！float 该用 1e-6
```

**记法**：`float` 误差量级约 `10⁻⁷`，容差用 **`1e-6`**；`double` 误差量级约 `10⁻¹⁶`，才用 **`1e-12`**。

课件另两句要记：
- **「带小数点的字面量是 double 而非 float，float 需要用 f 或 F 后缀来表明身份」** ← 就是上一节讲的
- **「`f1 == f2` 可能失败」** → 改用 `fabs(f1-f2) < 容差`
- **「浮点数计算由专用硬件部件实现」「计算 double 和 float 用的是同一个部件」** ← 所以 `float` 运算**并不比 `double` 快**（都是同一个 FPU 单元；嵌入式里没 FPU 时才另说）

### 9.5 本节复习题（新 3 题）

> [!question]- Q6：`float` 的 32 位是怎么分的？每段多少位、各管什么？
>
> **答**：符号 1 位（正负）＋ 指数 8 位（**范围**）＋ 尾数 23 位（**有效数字**）。`double` 是 1 + 11 + 52。

> [!question]- Q7：`float` 的尾数 23 位，怎么就和"7 位有效数字"对上了？
>
> **答**：尾数 23 位 = 能记 `2²³ = 8388608` 个刻度（约 838 万，7 位数），所以十进制约 7 位有效数字。`double` 是 `2⁵² ≈ 4.5×10¹⁵`，所以 15~16 位。

> [!question]- Q8：`float` 数据比较时，容差写 `fabs(a-b) < 1e-12` 行不行？
>
> **答**：**不行，太严了**（实测差 6.5e-8 就判假了）。`float` 误差在 `10⁻⁷` 量级 → 用 **`1e-6`**；`1e-12` 是给 `double` 的。

## 10. 一句话总结

**浮点数 = 「能拉很长的卷尺，刻度只有 7 格」；范围管"能多大"，有效数字管"能多准"；十进制小数除不尽二进制，所以 `0.1+0.2` 不等于 `0.3`，浮点永远别用 `==`。**
