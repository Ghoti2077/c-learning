# L15 if 语句与关系运算符（判断的起点）

- 日期：2026-09-17
- 来源：我的笔记 + 鹏哥课件 4 张（如果 / 关系运算的结果 / 优先级 ×2）
- 标签：`#C语言` `#基础语法` `#if` `#关系运算符` `#分支`

> **一句话总结**：`if (条件) { ... }` —— **括号里的条件"成立"就进大括号，不成立就跳过**。
> 关系运算的结果**永远是整数 `1` 或 `0`**（不是"真/假"两个新类型）；`0` 是假、**任何非 0 都是真（包括负数）**。

| （课件图 1、2） | ✅ 结构图 | `if (条件成立) { ... }` |

## 1. `if` 的基本结构

![[L15-if结构.png]]

```c
if (条件) {
    条件成立时做的所有事;
    可以写很多句;
}
后面的代码;      // 不管条件成立不成立，都会继续往下走
```

**完整例子**：

```c
int a = 5;
if (a > 0) {
    printf("a 是正数\n");
    printf("这句话也在大括号里\n");
}
printf("不管上面成不成立，这句都会执行\n");
```

### ⚠️ 大括号能省，但**非常危险**（我实测了）

```c
int a = 5;
if (a > 100)                        // 条件明明是假的
    printf("这行属于 if，不会执行\n");
    printf("这行【不属于 if】，永远执行！\n");   // ← 缩进了骗人，但它真的会打
```

**实测输出**：

```
这行【不属于 if】，永远执行！
（看上面：条件明明是假的，第二行还是打了）
```

**原因**：**`if` 后面不写大括号，它就只管【紧跟着的那一句】。** 第二句已经是"另一句话"了，跟 `if` 没关系。

> 📌 **"管住"的意思**（2026-09-17 我提问后补充，这词很关键）：
> 编译器说的 guard 是"**管着 / 罩着 / 圈进自己的地盘**"，**不是"程序错了"**。
> 写成上面那样，`if` 只把**第一句**圈进了自己的地盘；**第二句在外面，谁也管不着它，所以它永远执行。**

**编译器也会警告**（我跑的原文，一字不漏）：

```
warning: this 'if' clause does not guard... [-Wmisleading-indentation]
    5 |     if (a > 100)
      |     ^~
note: ...this statement, but the latter is misleadingly indented as if it were guarded by the 'if'
    7 |         printf("不属于 if，永远执行！\n");
      |         ^~~~~~
```

**逐句翻译**：

| 原文 | 人话 |
|---|---|
| `this 'if' clause does not guard...` | 这个 `if` **没管住**…… |
| `...this statement` | ……**后面那条语句**（即第 7 行那句） |
| `but the latter is misleadingly indented as if it were guarded by the 'if'` | 但**它缩进得让人误会**，看起来像被 `if` 管着（其实没有） |

### ⭐ 这里有个新手必须分清的区别：**编译通过 ≠ 程序正确**

| | 语法错误 | **逻辑错误**（本例） |
|---|---|---|
| 编译器怎么说 | `error:` → **编译不过** | `warning:` → **只是警告** |
| 能不能生成 exe | ❌ 不能 | ✅ **能**（我实测：生成了 `guard.exe`） |
| 程序能不能跑 | ❌ 跑不起来 | ✅ **能跑**（实测输出了"不属于 if，永远执行！"） |
| 问题在哪 | 我写错了字/符号 | **程序行为跟我想的不一样** |

**所以我的疑问"这程序不是正确的吗"——答案是：语法上完全正确 ✅，但它的行为不是我以为的那样。**

> ⚠️ 这类"能编译、能运行、结果却不对"的问题叫**逻辑错误**，它比语法错误**难查得多**——因为编译器不会拦你。
> **写法上的自保**：`if` 后面**永远加大括号**，就别给自己留这种坑。

> 📌 **规矩（现在就要养成）**：**`if` 后面永远写大括号**，哪怕里面只有一句。省 2 秒钟，可能省你 2 小时调试。

## 2. 关系运算符：一共 6 个

![[L15-关系运算的结果.png]]

| 运算符 | 意思 |
|---|---|
| `<` | 小于 |
| `>` | 大于 |
| `<=` | 小于等于 |
| `>=` | 大于等于 |
| `==` | **等于**（两个等号！） |
| `!=` | 不等于 |

**⚠️ 最容易错的一对**：

| 写法 | 意思 |
|---|---|
| `a = 5` | **赋值**（把 5 装进 a） |
| `a == 5` | **判断相等**（问：a 是不是 5？） |

## 3. ⭐ 关系运算的结果：**整数 1 或 0**

课件原话：**两个值的关系符合运算符的预期时，结果是整数 `1`，否则是整数 `0`。**

**我实测的三行（就是课件那三行）**：

| 表达式 | 结果 |
|---|---|
| `5 == 3` | **0**（5 不等于 3） |
| `5 > 3` | **1**（成立） |
| `5 <= 3` | **0**（不成立） |

**这说明什么？** 关系运算**不是**"真/假"两个特殊东西，它吐出来的**就是普通的整数**——`1` 或 `0`。这正好对上 L09 学的：**0 是假、非 0 是真**。

> 💡 所以下面这些写法全都合法（而且很常见）：
> ```c
> int r = a > 0;        // r 装的是 1 或 0
> if (5 > 3) { ... }    // 括号里其实是 1
> ```

## 4. 优先级：算术 > 关系 > 赋值

![[L15-优先级-关系vs算术vs赋值.png]]

课件原话：**所有关系运算符的优先级比算术运算低，但比赋值运算高。**

| 谁的优先级高 | 运算符 |
|---|---|
| **最高** | 算术：`+ - * / %` |
| ↓ | 关系：`< > <= >=`（然后才是 `== !=`） |
| **最低** | 赋值：`=` |

**实测**：

| 写法 | 实际怎么算 | 结果 |
|---|---|---|
| `7 >= 3 + 4` | 先算 `3+4 = 7` → 再判断 `7 >= 7` | **1** |
| `int r = a > 0;`（a=5） | 先判断 `a > 0` → 得 1 → 再赋给 r | **r = 1** |

> 所以 `int r = a > 0;` 不用加括号也能按你想要的顺序算（但如果记不清，**加括号永远不错**：`int r = (a > 0);`）

## 5. ⚠️⚠️ 连续关系运算的巨大陷阱（从左到右）

![[L15-优先级-连续关系.png]]

课件原话两条：
1. **判断相等的 `==` 和 `!=` 优先级比其他关系运算符低**
2. **连续的关系运算是从左到右进行的**

**我实测的结果（这几个都反直觉）**：

| 写法 | 实际怎么算 | 结果 | 人话 |
|---|---|---|---|
| `5 > 3 == 6 > 4` | `(5>3) == (6>4)` → `1 == 1` | **1** | 这个恰好对了 |
| `6 > 5 > 4` | `(6>5) > 4` → `1 > 4` | **0** ❌ | **不是"6大于5大于4"的意思！** |
| `6 == b == 6`（b=6） | `(6==b) == 6` → `1 == 6` | **0** ❌ | 明明 b 就是 6，结果却是 0 |
| `6 == b > 0`（b=6） | `6 == (b>0)` → `6 == 1` | **0** ❌ | 6 当然不等于 1 |

**gcc 也看不下去，直接警告**（我跑的原文）：

```
warning: comparisons like 'X<=Y<=Z' do not have their mathematical meaning
（X<=Y<=Z 这种写法没有数学上的意义）
warning: comparison of constant '6' with boolean expression is always false
（把常量 6 和"布尔表达式"比较，永远为假）
```

### 为什么？

**因为关系运算的结果是 1 或 0（第 3 节学的）！** 所以：

```
6 > 5 > 4
  ↓
(6 > 5) > 4        ← 先算左边，得到 1
  ↓
1 > 4              ← 变成"1 大于 4"了
  ↓
0                  ← 当然是假
```

> **一句话**：`6 > 5 > 4` 在 C 里**不是"6 大于 5 且 5 大于 4"**，而是"**先算 6>5 得到 1，再拿 1 跟 4 比**"。
> 想要数学上的意思，得写成 `6 > 5 && 5 > 4`（`&&` 是"而且"，**这门课后面会学**）。**现在只要记住：别写连续的关系运算。**

## 6. ⭐ `if` 里放的东西：非 0 就是真

因为关系运算给的是整数，所以 `if` 的括号里其实**可以放任何能算出数字的东西**。**判断规则：不是 0 → 成立；是 0 → 不成立。**

**实测**：

| 写法 | 结果 |
|---|---|
| `if (72)` | ✅ 进来了（72 非 0） |
| `if (0)` | ❌ 走 else（0 是假） |
| `if (-5)` | ✅ **也进来了！负数也是真** |

> 📌 **"0 是假，非 0 是真"——这一条现在开始天天用。** 特别注意：**负数是真**，`-1`、`-100` 都是真。

## 7. ☠️ 最经典的坑：把 `==` 写成 `=`

```c
int x = 0;
if (x = 5)              // 我本想写 x == 5，结果手滑写成一个等号
    printf("进来了！x 变成了 %d\n", x);
```

**实测结果是"进来了"，而且 x 被改成了 5！**（原文输出：`if (x = 5) 进来了，x 变成了 5`）

**为什么？** 因为 `x = 5` 是**赋值**，它的意思是"把 5 装进 x，然后这个表达式的值是 5"——**5 是非 0 → 真 → 进 if**。所以我不仅判断错了，还**顺手把 x 改了**，这是最难查的一类 bug。

**编译器也警告了**（我跑的原文）：

```
warning: suggest parentheses around assignment used as truth value
（建议给"当条件用的赋值"加括号——它在提醒你：你是不是想写 == ？）
```

> ⚠️ **防身口诀**：判断相等，**两个等号**。
> 看到编译器的这条警告（`assignment used as truth value`），**立刻回去检查**——它十有八九在救你。

## 9. 复习题（先自己答）

1. `if` 后面的大括号**能不能省**？省了会有什么风险？
2. `5 == 3`、`5 > 3`、`5 <= 3` 分别等于几？
3. `6 > 5 > 4` 的结果是几？**为什么不是"成立"**？
4. `if (-5)` 会进来吗？`if (0)` 呢？
5. `if (x = 5)` 和 `if (x == 5)` 有什么区别？（结合"x 会不会被改掉"说）

> [!question]- 参考答案（先自己答完再点开）
>
> 1. **能省**，但 `if` 就**只管紧跟着的那一句**，后面的语句就不再受它控制了。**风险**：缩进看着像在 if 里，其实不是 → 程序行为跟你想的不一样。**所以：永远写大括号。**
> 2. `5 == 3` → **0**；`5 > 3` → **1**；`5 <= 3` → **0**。关系运算的结果是整数 1 或 0。
> 3. **0**。因为是从左到右算：`(6>5)` 先得到 **1**，然后变成 `1 > 4` → 假 → **0**。要表达"6大于5并且5大于4"，得写 `6 > 5 && 5 > 4`。
> 4. `if (-5)` → **会进来**（非 0 就是真，负数是真）；`if (0)` → **不会**，走 else。
> 5. `if (x == 5)` 是**判断**（x 不会被改）；`if (x = 5)` 是**赋值**——它会把 5 装进 x，**x 被改掉了**，而且赋值的结果是 5（非 0）→ **永远进 if**。这是很危险的 bug，编译器会警告 `assignment used as truth value`。

## 10. 嵌入式视角

- **`if` 是嵌入式里"判断状态"的基本工具**：`if (按键被按下)`、`if (温度 > 上限)`、`if (串口收到数据)`——**所有"条件响应"都是它**。
- **"非 0 为真"直接对应寄存器位判断**：以后最常见的写法是
  ```c
  if (GPIOA->IDR & 0x01)     /* 第 0 位是 1 -> 条件非 0 -> 成立 */
  ```
  **你现在学的"非 0 即真"，就是为了以后读寄存器**。
- **"关系运算结果是 1/0"在嵌入式里很有用**：可以直接把判断结果当数字用（比如 `count += (a > 100);` 数"超标了几次"）。
- **`==` 写成 `=` 这种坑在嵌入式里是真实事故**：`if (flag = 1)` 看起来完全合理，实际永远为真——单片机上"永远进某个分支"就是死循环/功能失灵。所以团队规范里**常常把常量写在左边**：`if (1 == flag)`——写错了会直接编译报错，抓得比警告还快。（以后学 `switch`/循环会再见到这个老规矩）
