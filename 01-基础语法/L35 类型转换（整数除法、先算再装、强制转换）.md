## 1. 两个比方（记住这两句就够）

**比方一：听谁的大。——做运算时，编译器先看两边各是什么类型，谁的范围大就按谁的规矩算。**

`int + double` → 按 `double` 算（int 被"抬高"成 double）。

**比方二：先算，再装。——右边的算式怎么算，跟你把它装进哪个类型的盒子里一点关系都没有。**

左边写 `double d = 5 / 2;` —— 左边是 double **没用**，右边 `5` 和 `2` 都是 int，就先按整数算得 `2`，**再**装进 double 变成 `2.0`。

> 💡 这一条就是 L31 那个 `sum += 1 / i` 全场变 0 的**病根**：`1` 和 `i` 都是 int → 先整除 → `1/2 = 0`、`1/3 = 0`…全 0，加进去当然还是 0。写 `1.0 / i` 才让右边变成浮点运算。

## 2. 实测程序 + 真实输出（源码照抄，可自己编译）

```c
#include <stdio.h>

int main(void)
{
    /* 1. 两个整数相除 = 整除（丢小数） */
    printf("1)  1 / 2        = %d\n", 1 / 2);
    printf("2)  3 / 2        = %d\n", 3 / 2);
    printf("3)  1 / 3        = %d\n", 1 / 3);
    printf("4)  1.0 / 2      = %f\n", 1.0 / 2);
    printf("5)  1.0 / 3      = %.10f\n", 1.0 / 3);

    /* 2. 关键：先算，再存 */
    double d1 = 5 / 2;      /* 右边先按整数算 = 2，再存进 double */
    double d2 = 5.0 / 2;    /* 右边按浮点算 = 2.5 */
    printf("6)  double d = 5 / 2    -> %.1f\n", d1);
    printf("7)  double d = 5.0 / 2  -> %.1f\n", d2);

    /* 3. 强制转换的位置差别 */
    printf("8)  (double)5 / 2   = %.1f\n", (double)5 / 2);    /* 只转 5 */
    printf("9)  (double)(5 / 2) = %.1f\n", (double)(5 / 2));  /* 先算完再转 */

    /* 4. 小数 -> 整数：截断（向零取整），不是四舍五入 */
    printf("10) (int)3.9        = %d\n", (int)3.9);
    printf("11) (int)-3.9       = %d\n", (int)-3.9);
    printf("12) (int)(3.9 + 0.1)= %d\n", (int)(3.9 + 0.1));

    /* 5. 取余 % 只能给整数 */
    printf("13) 10 / 4 = %d ,  10 %% 4 = %d\n", 10 / 4, 10 % 4);

    /* 6. 塞不下就截断（大盒子 -> 小盒子） */
    int big = 300;
    char ch = (char)big;
    printf("14) (char)300       = %d\n", ch);

    short s = 32768;        /* 故意溢出 */
    printf("15) short 32768     = %d\n", s);

    /* 7. 表达式自己的类型 */
    printf("16) sizeof(1 / 2)   = %d   sizeof(1.0 / 2) = %d\n",
           (int)sizeof(1 / 2), (int)sizeof(1.0 / 2));

    /* 8. 左结合 */
    printf("17) 7 / 2 * 2.0     = %.1f\n", 7 / 2 * 2.0);
    printf("18) 7.0 / 2 * 2     = %.1f\n", 7.0 / 2 * 2);
    return 0;
}
```

**真实输出**（`gcc 16.2.0`，`gcc -Wall` 编译 **0 错误 0 警告**）：

```
1)  1 / 2        = 0
2)  3 / 2        = 1
3)  1 / 3        = 0
4)  1.0 / 2      = 0.500000
5)  1.0 / 3      = 0.3333333333
6)  double d = 5 / 2    -> 2.0   (先整除)
7)  double d = 5.0 / 2  -> 2.5
8)  (double)5 / 2   = 2.5
9)  (double)(5 / 2) = 2.0
10) (int)3.9        = 3
11) (int)-3.9       = -3
12) (int)(3.9 + 0.1)= 4
13) 10 / 4 = 2 ,  10 % 4 = 2
14) (char)300       = 44
15) short 32768     = -32768
16) sizeof(1 / 2)   = 4   sizeof(1.0 / 2) = 8
17) 7 / 2 * 2.0     = 6.0
18) 7.0 / 2 * 2     = 7.0
```

## 3. 逐条看（哪条最坑）

### ① 第 1~3 行：两个 int 相除 = **整除**（小数直接扔，不是四舍五入）

`1/2 = 0`、`3/2 = 1`、`1/3 = 0`。想让结果带小数，**至少一边得写成小数**（第 4、5 行的 `1.0`）。

### ② 第 6、7 行：**本课核心 —— 先算，再装**

- `double d1 = 5 / 2;` → 右边两个都是 int → 先算出 `2` → 再装成 `2.0` ❌
- `double d2 = 5.0 / 2;` → 右边有小数 → 按浮点算 → `2.5` ✅

**左边变量的类型管不了右边的算式。**

### ③ 第 8、9 行：`(类型)` 只管它**右边挨着的第一个东西**

| 写法 | 过程 | 结果 |
|---|---|---|
| `(double)5 / 2` | `5` 先变 `5.0` → `5.0/2` | **2.5** ✅ |
| `(double)(5 / 2)` | 括号里先按整数算出 `2` → 再转成 `2.0` | **2.0** ❌ 白转 |

### ④ 第 10~12 行：小数 → 整数是**截断**（往 0 砍），不是四舍五入

- `(int)3.9 = 3`
- **`(int)-3.9 = -3`** ← 注意！是 **-3**，不是 -4（往 0 的方向砍，不是往下）
- `(int)(3.9 + 0.1) = 4` ← 括号里先算成 `4.0` 再截

**想四舍五入得自己写**：`(int)(x + 0.5)`。

### ⑤ 第 13 行：`%` 取余**只能给整数**，浮点用不了

`10/4 = 2`、`10%4 = 2` —— 一个给商、一个给余数。

### ⑥ 第 14、15 行：塞不下就**绕圈**（L28 学过的那套）

- `char` 只有 8 位（-128~127），放 300 → `300 - 256 = ` **44**
- `short` 上限 32767，`32768` 越界 → **-32768**（待办本里记的正是这条，今天实测坐实）

### ⑦ 第 16 行：**算式自己就有类型**（最硬的证据）

`sizeof(1 / 2) = 4`（int）、`sizeof(1.0 / 2) = 8`（double）。

**写在纸上的算式本身是有类型的**，跟左边变量是谁毫无关系 —— 这就是"先算再装"的物理证据。

### ⑧ 第 17 行：左结合，从左往右算

`7 / 2 * 2.0` → 先 `7/2 = 3`（整除！）→ 再 `3 * 2.0 = ` **6.0** ❌
想对就得先转：`7.0 / 2 * 2` = **7.0** ✅

## 4. 三条必背

1. **两个 int 相除 = 整除**（扔小数）。要小数，至少一边写成 `1.0`、`5.0`。
2. **先算，再装** —— 左边变量的类型管不了右边怎么算。`double d = 5/2` 就是 `2.0`。
3. **`(类型)` 只管右边挨着的第一个东西**；小数→整数是**截断**（`(int)-3.9 = -3`，往 0 砍）。

## 5. 复习题（他的答案 + 讲评，2026-10-04）

> [!question]- Q1：`int a = 5, b = 2; double c = a / b;` 打印 `c` 是多少？为什么？
>
> **他答**：「2.0，因为计算机先计算了 A÷B，再把它转化成 double 的形式，而 A÷B 的结果是 2」
> **判定**：✅ **满分** —— 把"先算再装"说得一字不差。
> **答**：`2.0`。`a` 和 `b` 都是 int → 先按整数算出 `2` → 才装进 `c`（double）。左边写 double 救不了右边的算式。

> [!question]- Q2：`(int)5.99` 和 `(int)-5.99` 分别输出几？
>
> **他答**：「五和负五」
> **判定**：✅ 对（5 和 -5）
> **答**：`5` 和 **`-5`**。截断 = **往 0 的方向砍**，不是四舍五入、也不是"往下取整"。`-5.99` 砍掉尾巴是 `-5`。

> [!question]- Q3：`7 / 2 * 2.0` 和 `7.0 / 2 * 2` 分别是多少？
>
> **他答**：「6.0 和 7」
> **判定**：⚠️ **数值对，但有一处要收紧** —— 第二个的结果是 **`7.0`（浮点）**，不是整数 `7`。
> **答**：`6.0`（先 `7/2 = 3` 整除，再 `3*2.0`）和 `7.0`（`7.0/2 = 3.5`，`3.5*2 = 7.0`）。
> **为什么揪这个**：类型不一样，用 `printf("%d", ...)` 去印浮点会打出垃圾 —— 数值对不代表类型对，**心里要带上"它是浮点"**。

## 6. 🔌 嵌入式视角（以后在单片机哪里用得上）

**ADC 采电压的经典翻车现场**（上板第一周必踩）：

```c
float v = adc / 4095 * 3.3f;        /* ❌ adc 是 int（比如 0~4095）→ adc/4095 几乎永远是 0 → v 全 0 */
float v = (float)adc / 4095 * 3.3f; /* ✅ 先把 adc 转成 float，再做除法 */
```

- ADC 读出来的是 **int**（12 位分辨率 = 0~4095），要换算成电压必须**先转 float**，否则整除把小数全砍了 → 串口打出来一排 0
- 另一类常见处：**算平均值** `sum / count`（两个 int）→ 温度/电压平均值全是整数，小数丢了 → 写 `(float)sum / count`
- 和 L28 对照记：**大盒子→小盒子的隐式转换编译器不一定警告**，但值已经绕圈了（`char` 装 300 → 44），上板看传感器数据变负、变怪，先想想是不是类型塞不下

## 7. 补充课件：自动类型转换（`_附件/L35-01`）

> 2026-10-04 他补发的课件，正好把第 1 节的"谁范围大听谁的"升级成**官方链条**。

**课件原话**：当运算符两边出现不一致的类型时，会**自动转换成较大的类型**；「大」的意思是**能表达的数的范围更大**。

```
char → short → int → long → long long
int → float → double
```

**实测：`sizeof` 一个运算式**（gcc 16.2）

```c
printf("sizeof('a' + 1)        = %d\n", (int)sizeof('a' + 1));
printf("sizeof(char + char)    = %d\n", (int)sizeof((char)1 + (char)2));
printf("sizeof(short + short)  = %d\n", (int)sizeof((short)1 + (short)2));
printf("sizeof(int + int)      = %d\n", (int)sizeof(1 + 2));
printf("sizeof(int + float)    = %d\n", (int)sizeof(1 + 1.0f));
printf("sizeof(int + double)   = %d\n", (int)sizeof(1 + 1.0));
printf("sizeof(char + double)  = %d\n", (int)sizeof('a' + 1.0));
printf("sizeof(long + float)   = %d\n", (int)sizeof(1L + 1.0f));
printf("sizeof(long long + int)= %d\n", (int)sizeof(1LL + 1));
```

```
sizeof('a' + 1)        = 4
sizeof(char + char)    = 4        ← 不是 1！
sizeof(short + short)  = 4        ← 不是 2！
sizeof(int + int)      = 4
sizeof(int + float)    = 4
sizeof(int + double)   = 8
sizeof(char + double)  = 8
sizeof(long + float)   = 4        ← long 被转成 float
sizeof(long long + int)= 8
```

**两个反直觉的：**

1. **`char + char` 和 `short + short` 的结果都是 `int`（4 字节）** —— 这叫**整型提升**：比 `int` 小的类型（`char`、`short`、`_Bool`）参与运算前，**一律先提升成 `int`**。所以 `sizeof('a' + 1) = 4`，连字符常量都算 int。
2. **`long + float` = 4 字节 float** —— 按链条 `int → float → double`，`float` 排在 `long long` 级别之上，所以 `long` 被转成 `float`（**可能丢精度**，float 只有 7 位有效数字）。

**实际后果（实测）**：

```c
char a = 100, b = 100;
printf("a + b = %d\n", a + b);        /* 200  —— 不是 -56！先提升成 int 再算 */
printf("(char)(a+b) = %d\n", (char)(a + b));  /* -56 —— 存回 char 才绕圈 */
```
```
a + b = 200   （不是 -56！因为先提升成 int 再算）
但存回 char: -56
```

**这就是「先算，再装」的第二层**：**运算是在"提升后的类型"里做的**，只有往小盒子里装的时候才截断。`char` 装不下 200，但 `char + char` 的计算过程完全够用。

## 8. 补充课件 2：printf / scanf 的自动转换（`_附件/L35-02`）

**课件原话：**

- 对于 `printf`，**任何小于 `int` 的类型会被转换成 `int`；`float` 会被转换成 `double`**
- 但是 `scanf` **不会**，要输入 `short`，需要 `%hd`

这就是**默认实参提升**：`printf` 是可变参数函数，传进去的时候小类型一律"升级"。

**实测（gcc 16.2）**

```c
#include <stdio.h>

struct Pair { short s; short t; };      /* 两个 short，一定挨着 */

int main(void)
{
    float f = 1.5f;
    printf("1) printf(\"%%f\", float变量) = %f\n", f);
    printf("2) sizeof(f) 只有 %d 字节，但 printf 收到的是 8 字节的 double\n\n", (int)sizeof(f));

    short h = -1;
    printf("3) short -1:  %%d -> %d    %%hd -> %hd\n\n", h, h);

    struct Pair v;
    v.s = 111;
    v.t = 222;
    printf("4) struct {short s; short t;} 共 %d 字节，s 和 t 挨着\n", (int)sizeof(v));
    printf("   写之前: s=%d  t=%d\n", v.s, v.t);
    printf("   请输入一个数（输入 70000 试试）：");
    fflush(stdout);
    scanf("%d", &v.s);                   /* 故意用错：%d 会给 short 写 4 字节 */
    printf("   写之后: s=%d  t=%d   <- 隔壁的 t 被踩了\n", v.s, v.t);
    return 0;
}
```

```
1) printf("%f", float变量) = 1.500000
2) sizeof(f) 只有 4 字节，但 printf 收到的是 8 字节的 double

3) short -1:  %d -> -1    %hd -> -1

4) struct {short s; short t;} 共 4 字节，s 和 t 挨着
   写之前: s=111  t=222
   请输入一个数（输入 70000 试试）：   写之后: s=4464  t=1   <- 隔壁的 t 被踩了
```

**而且编译器当时就警告了**（这条实测里最有教育意义的一点）：

```
l38_vararg.c:24:13: warning: format '%d' expects argument of type 'int *',
                        but argument 2 has type 'short int *' [-Wformat=]
      |            %hd          ← 编译器直接把正确写法告诉你了
```

**三个结论：**

1. **`printf` 永远收不到 `short` / `char` / `float`** —— 它收到的都是 **int / double**。所以 `%f` 能接 float（float 在传进去之前就已经变成 double 了，占 8 字节）
2. `%hd` 在 printf 里**还能用**，只是告诉它「按 short 解释这个 int 值」—— 值本身早就提升完了
3. **`scanf` 完全不同**：它拿到的是**地址**，地址不会提升 → **必须写对 `%hd`**。写 `%d` 就是给 short 那 2 字节的空间**写 4 个字节**，多出来的 2 字节**踩到隔壁**（实测：70000 的低 16 位 `0x1170 = 4464` 进了 `s`，高 16 位的 `1` 踩进了 `t`）

**串起来（顺手把 L34 那个疑问解释掉）：**

| 类型 | `printf` | `scanf` |
|---|---|---|
| `float` | `%f` 就行（**已经提升成 double**） | **必须 `%f`**（往里写 4 字节） |
| `double` | `%f` | **必须 `%lf`**（往里写 8 字节） |
| `short` | `%d` / `%hd` 都行 | **必须 `%hd`** |

**一句话记**：`printf` 是「**往外送统一型号的货**」（小的一律升级），`scanf` 是「**按你给的地址往里塞指定尺寸的货**」（尺寸必须你自己说对）。

### 他答的三道题（2026-10-04）—— **全对** ✅

| Q1 `sizeof(char+char)` 为什么是 4 | 「因为 `char` 类型比 `int` 要小，所以运算的时候提升成 `int`」 | ✅ 抓住了"整型提升" |
| Q2 `char a=100,b=100; a+b` 为什么是 200 不是 -56 | 「计算 `a+b` 的时候是在 `int` 里算的，只有把它往 `char` 里面装的时候才会截断成 -56」 | ✅ **「先算，再装」的第二层说对了** |

## 9. 一句话总结

**C 的运算规矩：「谁范围大听谁的」+「先算，再装」—— 两个 int 相除就是整除，左边写什么类型都救不回右边；要小数，就把算式里至少一个数写成小数，或者用 `(类型)` 把它转过去。**
