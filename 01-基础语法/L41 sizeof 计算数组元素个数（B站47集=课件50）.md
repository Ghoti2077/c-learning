## 1. 一句话总结

`sizeof(数组)` ÷ `sizeof(数组的一个元素)` = **元素个数**。
**除的是一个元素占几个字节，不是元素的个数本身。**

---

## 2. 比方：一整箱饮料

一整箱饮料放在秤上，秤只会告诉你「**总重量**」多少克。

想知道里面**有几瓶**，你不能直接问秤，得自己算：

> 总重量 ÷ **一瓶的重量** = 瓶数

对应到 C：

- `sizeof(a)` = 一整箱的总重量（总字节数）
- `sizeof(a[0])` = 一瓶的重量（一个元素的字节数）
- 相除 = 瓶数（元素个数）

**关键**：除的是「**一瓶多重**」，不是「有几瓶」。
拿「有几瓶」去当除数，等于用答案求答案，会算出没意义的东西。

`sizeof` 还有一个身份要记住：它是**编译时**就出结果的，程序跑起来之前数字就写死了，所以它**不会真去访问**那一格内存。

---

## 3. 标准写法

```c
#include <stdio.h>

int main(void)
{
    int a[10] = {0};

    int n = sizeof(a) / sizeof(a[0]);   /* 元素个数 */

    printf("%zu\n", sizeof(a));         /* 40：整个数组 40 字节 */
    printf("%zu\n", sizeof(a[0]));      /*  4：一个元素 4 字节   */
    printf("%zu\n", n);                 /* 10：元素个数          */
    return 0;
}
```

逐行：

- 第 5 行：`int a[10]` 创建 10 格的 int 数组，`= {0}` 只把第一格填 0，后面 9 格自动补 0（[[L39 一维数组的初始化与数组类型（鹏哥47：不完全初始化补0）]] 的 C1）
- 第 7 行：`sizeof(a)` = 40，`sizeof(a[0])` = 4，40 ÷ 4 = 10 → `n` 装的是 **个数**
- 第 9~11 行：`%zu` 是 `size_t` 类型（`sizeof` 的返回值类型）专用的格式符

### 为什么不能写死 4 或 8

```c
int    a[6];   /* sizeof(a) / sizeof(a[0]) = 24 / 4 = 6   ✅ */
double b[3];   /* sizeof(b) / sizeof(b[0]) = 24 / 8 = 3   ✅ */
               /* sizeof(b) / 4            = 24 / 4 = 6   ❌ 算出 6 个 */
```

**分母跟着类型走**，换个类型分母就变了。写死 4 只对 `int` 成立，换 `double` 立刻错一半。

### 不用 sizeof 的写法（只适用于当场能数清的时候）

```c
int a[6] = {1, 2, 3, 4, 5, 6};
int n = 6;                   /* 方括号里的数就是个数，直接抄 */
int n2 = sizeof(a) / sizeof(a[0]);   /* 也是一样，6 */
```

两种写法都对，但**数组一长、一改大小，手抄的 6 就容易忘改**，所以 `sizeof` 那种写法更抗改。

## 4. 实测证据（2026-11-18 现场跑）

### gcc（MSYS2 UCRT64, GCC 16.2）

源码 `sz47.c`：

```c
#include <stdio.h>

int main(void)
{
    double b[3] = {0};
    int a[10] = {0};

    printf("sizeof(b)=%d\n", (int)sizeof(b));
    printf("sizeof(b[0])=%d\n", (int)sizeof(b[0]));
    printf("sizeof(b)/4=%d  <-- 错算法\n", (int)(sizeof(b) / 4));
    printf("sizeof(b)/sizeof(b[0])=%d  <-- 对算法\n", (int)(sizeof(b) / sizeof(b[0])));
    printf("sizeof(a[1000])=%d\n", (int)sizeof(a[1000]));
    return 0;
}
```

输出：

```
sizeof(b)=24
sizeof(b[0])=8
sizeof(b)/4=6  <-- 错算法
sizeof(b)/sizeof(b[0])=3  <-- 对算法
sizeof(a[1000])=4
```

两条结论：

1. **除以 4 而不是"一个元素的字节数"** → `double b[3]` 会被算成 **6 个**（实际只有 3 个）。
2. `sizeof(a[1000])` 对 10 格的数组是**越界的**，但照样打出 4、程序不崩 —— 因为 `sizeof` 是**编译时**按类型算的，根本没去碰那块内存。

### MSVC（VS2026, vcvars64 + cl /W3）

源码 `sz47b.c`：

```c
#include <stdio.h>

int main(void)
{
    char s[20];
    int a[6] = {1, 2};
    printf("%zu\n", sizeof(s) / sizeof(s[0]));
    printf("%zu\n", sizeof(a) / sizeof(a[0]));
    printf("%zu\n", sizeof(int[10]));
    return 0;
}
```

输出：

```
20
6
40
```

编译**零警告**（`/W3`）→ 说明 `%zu` 是他自己写的正道写法，不是我硬要求的。

## 5. 三个坑

> [!warning]- 坑 1：分母写成元素个数
> 他的原话（2026-11-18）：「除错数了，应该除 `sizeof(b[0])` 或者 **3**」
> 前半对，后半错 —— **3 正是他要问的答案**。除的必须是「**一格几字节**」。
> `double b[3]` 一格 8 字节，所以除 `sizeof(b[0])`（等于 8），24÷8=3 才对。

> [!warning]- 坑 2：把数组类型说成 `a[10]`
> 他的原话：「是 **a[10]**」❌
> 正解：`int a[10]` 的类型是 **`int[10]`**，**数组名要去掉**。
> 名称是你叫它的方式，类型是它长什么样。实测 `sizeof(int[10])` = **40**（MSVC / gcc 都是 40）。

> [!warning]- 坑 3：`sizeof` 不是函数
> `sizeof` 是**运算符**，编译期就算完。所以 `sizeof(a[1000])` 越界也不崩、`sizeof` 后面不加括号也能写（`sizeof a`）。
