# L08 注释（`/* */` 和 `//`）

- 日期：2026-09-15
- 来源：我问的问题 + AI 一起做的三个编译器实验
- 标签：`#C语言` `#基础语法` `#注释`

> **一句话总结**：`/* */` 能跨多行，但**不能嵌套**——编译器不数层数，**看到第一个 `*/` 就认为注释结束**。另外我猜的没错：**注释不是被删掉，而是被替换成一个空格**（有字节级证据）。

## 1. C 有几种注释

| 写法 | 名字 | 能不能跨行 | 备注 |
|---|---|---|---|
| `// 注释内容` | 单行注释 | ❌ 只能到本行末尾 | C99 起支持，VS 完全支持 |
| `/* 注释内容 */` | 块注释（多行注释） | ✅ 可以跨很多行 | C89 就有，最老牌 |

```c
// 这是单行注释

/* 这是
   可以跨行的
   块注释 */
```

## 2. ⭐ 为什么不支持嵌套（我的问题，这里是答案）

**"嵌套"就是**：在 `/*` 里面再写一个 `/*`：

```c
/* 外层开始
   printf("A\n");
   /* 我想在这儿再嵌一层注释 */
   printf("B\n");
这行还在注释里吗 */
```

### 编译器的真实反应（我跑出来的原文）

```
t3.c:8:5: error: unknown type name '这行还在注释里吗'
t3.c:8:23: error: expected identifier or '(' before '/' token
```

**报错的行是第 8 行**——就是那句"这行还在注释里吗"。说明：

> **编译器根本没有把这行当注释！它把从"我想在这儿再嵌一层注释"往后的东西全当成了代码。**

### 原理：编译器是"看到第一个 `*/` 就关灯"，它不数层数

```
/* 外层开始          ← 开灯的瞬间
   ...
   /* 我想在这儿再嵌一层注释 */     ← 遇到第一个 */ ，【关灯】！注释到这里就结束了
       printf("B\n");              ← 已经变成真代码了，会被编译
    这行还在注释里吗 */             ← 这行也是真代码 → 报错
```

> 比方：`/*` 是**开灯**，`*/` 是**关灯**。你按一下开、再按一下关——**开关不会因为你"多按了一次开"就记住两层**。多按的那个"开"根本不存在，只有第一次关灯算数。
>
> **所以嵌套的后果是：内层的 `*/` 提前把注释关掉了，后面的内容全都变成真代码**（可能报一堆莫名其妙的错）。

⚠️ **实用提醒**：**想"注释掉一段已经带着注释的代码"，千万别直接用 `/* */` 包起来**——里面那些 `*/` 会提前关灯。正确做法：

- 用 **`//` 一行一行注释**（最稳）
- 或者写 `#if 0 ... #endif`（预处理指令，以后学）

## 3. 注释被替换成【一个空格】，不是被删掉（我的猜测，验证通过）

### 实验 1：`int/**/x = 1;` 会不会粘成 `intx`？

**原文件**：

```c
int/**/x = 1;
```

**预处理后的字节级输出**（`od -c`，空格会显示成独立的空位）：

```
i   n   t       x       =       1   ;
```

读出来就是 **`int x = 1;`** —— `int` 和 `x` 中间**留下了一个空格**。

✅ 所以我说对了：**注释被替换成一个空格，不是删掉。**

**为什么必须是空格而不是直接删？** 因为如果直接删掉，`int/**/x` 就会粘成 **`intx`**——变成一个编译器不认识的标识符，直接报错。**留一个空格 = 保证两个东西不被粘在一起。**

> 顺带一个安全知识：这也是为什么**不能用注释去切断一个关键字**。`in/**/t x;` 不会变成 `int x;`，而是变成 `in t x;`（`in` 和 `t` 两个都不认识）。

### 实验 2：多行注释里的换行去哪了？

**原文件（4 行）**：

```c
1  int a = 1; /*
2  注释
3  注释
4  注释 */ int b = 2;
```

**预处理后（字节级）**：

```
i n t   a   =   1 ;   i n t   b   =   2 ;
```

**而且只剩 1 行**（`wc -l` = 1）。

✅ 结论：**整块注释（连里面那些换行）被压成了"一个空格"**，代码就挤到一行去了。`int a = 1;` 和 `int b = 2;` 之间正好是一个空格，所以还是合法代码，能正常跑（实测输出 `1 2`）。

> 🔎 小知识：真编译器在正式编译时会用 `# 行号 "文件"` 这类标记记住原始行号，**这样报错时告诉你的行号还是对的**——所以别担心"注释把行号搞乱了"。

## 4. 注释的几个实用坑

| 坑 | 说明 |
|---|---|
| 注释里带 `*/` | 会提前结束注释（比如注释里写 `a = b*/c;`——`*/` 一出现就关灯了） |
| 注释掉带注释的代码 | 用 `//` 或 `#if 0`，别用 `/* */` 硬包 |
| 字符串里的 `/*` | 字符串里的 `/*` `*/` 只是普通文字，**不会被当注释**（实测 `printf("/* */")` 原样打印 `/* */`） |
| 字符串不能跨行 | `"` 到 `"` 必须在同一行，中间直接回车会报 `missing terminating " character`；要换行就打 `\n` |
| 中文标点 | 注释里的中文、全角符号**随便写**，注释不参与编译（但**代码部分**必须英文符号） |
| 注释占不占程序空间 | **不占**。预处理阶段就被处理掉了，编译出来的 exe 里没有注释 |

**VS 里注释的快捷键（比手动敲快得多）**：

| 快捷键 | 作用 |
|---|---|
| `Ctrl+K` 然后 `Ctrl+C` | 把选中的行注释掉 |
| `Ctrl+K` 然后 `Ctrl+U` | 取消注释 |

> 调试时很实用：**怀疑哪几行有问题，就选住 → `Ctrl+K Ctrl+C` 屏蔽掉，试完再 `Ctrl+K Ctrl+U` 恢复。** 别直接删代码（删了容易忘了加回来）。

## 7. 嵌入式视角

- **注释不占空间**，但在嵌入式团队里**注释质量 = 代码质量**：寄存器操作、时序、硬件绕坑的原因，必须写在注释里（不然三个月后连自己都看不懂）。
- **硬件相关的坑一定要留注释**：比如"这里必须延时 10us，否则传感器不应答"——这种一句注释能救一个项目。
- 排查硬件问题时，**用注释快速屏蔽代码块**（配合 `Ctrl+K Ctrl+C`）是最常用的手法之一：二分法屏蔽，快速定位是哪一段把板子搞死了。

### 第 3 题：真正的原因是"它在字符串里"，跟有没有 `*/` 无关

我写了个对照实验：

```c
printf("A: [/*]\n");
printf("B: [/* */]\n");
```

**实测输出**：

```
A: [/*]
B: [/* */]
```

**B 那一行里面有完整的 `/* */`，照样原样打印出来！** 说明：

> **在字符串里面，`/*` 和 `*/` 只是两个普通符号，编译器根本不把它们当注释。**
> 注释标记只有在**代码部分（字符串外面）**才有"开关灯"的效力。

> 比方：`/*` `*/` 是**门禁卡**。门禁卡在**大楼里**能开门；你把门禁卡**拍张照片**（= 放进字符串），照片就只是一张照片，开不了任何门。

### 顺带记一个坑：字符串不能跨行

我第一版实验写坏了——把字符串写成了两行：

```c
printf("... /* 这些符号 */
");                      // ❌ 字符串中间直接回车了
```

编译器报：`error: missing terminating " character`（"你这个字符串没结束"）。

**原因**：C 里**字符串不能直接换行**（从 `"` 到 `"` 必须在同一行，除非用 `\` 续行）。要换行就打 **`\n`**——这就是为什么我们一直在写 `printf("...\n")`。

### 第 5 题：`Ctrl+K Ctrl+C` 和 `Ctrl+/` 的关系

- **`Ctrl+K` → `Ctrl+C`**（注释）、**`Ctrl+K` → `Ctrl+U`**（取消）：这是 **Visual Studio 官方的默认键位**，任何版本、任何电脑上都有，**最保险**。
- **`Ctrl+/`**：这是 **VS Code 的习惯键位**。你说在你的 VS 里也能用——**那就以你亲手试的结果为准**（我这边没法从机器上验证 VS 的默认键位，它不存在明文配置里，我查过 `VS2026\...\Profiles` 那几个 `.vssettings` 都没写键盘绑定）。

> 建议：**两个都记着**。以后换电脑、换 IDE（比如嵌入式常用的 Keil、IAR、CLion），快捷键全都不一样——`Ctrl+K Ctrl+C` 是 VS 系的老规矩，`Ctrl+/` 是新时代的通用习惯。
