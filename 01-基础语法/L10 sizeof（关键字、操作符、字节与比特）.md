# L10 sizeof（关键字？操作符？字节？比特？）

- 日期：2026-09-16
- 来源：我自己用 VS 学的笔记 + 课件图 + 我的**四次 VS 实测截图**（含作业）
- 标签：`#C语言` `#基础语法` `#sizeof` `#数据类型`

> **一句话总结**：`sizeof` **不是函数，是操作符**（所以 `sizeof x` 不加括号也能用），作用是**量出"操作数占几个字节"**。1 字节 = 8 比特；**字节数决定能装多大的数**。还有个大坑：**`sizeof` 里面的表达式不会被算**（这是我自己截图里 `s` 还是 12 的原因）。

## 1. 关键字、操作符，到底啥区别（我提的问题）

| 名字 | 是什么 | 例子 |
|---|---|---|
| **关键字**（keyword） | **语言自己占用的词**，有特权含义，你**不能**拿它当变量名 | `int`、`return`、`if`、`while`、`sizeof`、`void`…… |
| **操作符**（也叫运算符） | **参与运算的东西**，负责"做一件事" | `+` `-` `*` `/` `=` `==` `<<` `sizeof`…… |

**两个词是从不同角度看同一个东西，不冲突：**

- `sizeof` 是**关键字** → 它是 C 语言**钦定**的，你不能写 `int sizeof = 3;`（保留字）
- `sizeof` 是**操作符** → 它像 `+` 一样**会算出一个结果**，只不过它算的是"占几字节"

> 比方：**关键字 = "编制"**（它是官方在编人员，有特权），**操作符 = "岗位职责"**（它干的活是"运算"）。
> `sizeof` 既在编、岗位又是运算，所以两个称呼都对。

### 顺带分清：操作符和函数不是一回事

| | 操作符（`sizeof`） | 函数（`strlen`） |
|---|---|---|
| 要 `#include` 吗 | ❌ 不用（语言自带的） | ✅ 要（`<string.h>`） |
| 必须加括号吗 | ❌ **可以不**（`sizeof x` 合法） | ✅ 必须（`strlen(x)`，不写括号就调不动） |
| 啥时候算出来 | **编译时就知道了** | 程序跑起来才算出 |

**实测证据**（`int x = 3;`）：

```
sizeof x      = 4      ← 不加括号也能用！函数不行
sizeof x + 1  = 5      ← 先算 sizeof x（=4），再加 1
```

> 💡 记住一句话：**`sizeof` 是"官方的秤"，不是"仓库里的工具"。** 用秤不需要先去仓库借（不用 include）。

## 2. "sizeof 的操作数的类型长度" —— 逐词翻译

这句话之所以绕，是因为**术语叠在一起**了。拆开看：

```
sizeof     的   操作数      的   类型      长度
  ↓              ↓                ↓        ↓
那张秤      你放上去的东西     它的品种   占几字节
```

- **操作数** = "被这个操作符作用的东西"（`+` 的操作数是左右两边；`sizeof` 的操作数是它后面那一个）
- 整句话人话版：**"量一下后面那个东西，它这种类型占几个字节。"**

三种操作数都能用：

| 写法 | 操作数是什么 | 结果 |
|---|---|---|
| `sizeof(int)` | **类型名** | 4 |
| `sizeof(x)` | **变量** | 4 |
| `sizeof(x + 1)` | **表达式** | 4（看表达式**结果的类型**，不看值） |

⚠️ **唯一的规矩**：**操作数是"类型名"的时候必须加括号**。

```c
sizeof(int)     // ✅ 类型名，必须带括号
sizeof int      // ❌ 报错：expected expression before 'int'
sizeof x        // ✅ 变量，括号可省（但还是建议写上）
```

> 记忆法：**类型名后面没法"接"东西，编译器会懵**，所以必须用括号把它框起来当"一个整体"看。

## 3. 字节（byte）和比特（bit）的区别

![[L10-字节与比特导图.png]]

| 单位 | 英文 | 是什么 | 关系 |
|---|---|---|---|
| **比特 / 位** | bit | **一个二进制位**，只能放 0 或 1（最小单位） | — |
| **字节** | byte | C 里计量大小的单位 | **1 字节 = 8 比特** |

实测：`sizeof(int)` = 4 字节 = **32 比特**。

> 比方：**比特 = 一个开关**（开/关，0/1）；**字节 = 8 个开关排成一排**（一排 8 个位，正好能存 0~255 或者一个 ASCII 字符）。
> C 规定 **`sizeof(char)` 永远是 1**——这里说的"1"是**1 个字节**，不是 1 个比特。

**为什么 `_Bool` 占 1 字节（8 比特），明明 1 个比特就够了？**

> 因为 **C 里能操作的最小单位是"字节"**，没法只给 1 个比特。所以存"真/假"也要占一整格、浪费 7 个位。
> 📌 嵌入式里为了省这点位，会用**位运算**（把一个字节掰成 8 个标志位用）和**位域**——这就是以后重点学位运算的原因之一。

## 4. 字节数 → 能装多大的数（"范围"是怎么来的）

**规律**：`n` 个比特能表示 `2ⁿ` 种不同的值。

| 类型 | 字节 | 比特 | 能表示的范围（实测） |
|---|---|---|---|
| `char` | 1 | 8 | -128 ~ 127（或 0~255，看有无符号） |
| `short` | 2 | 16 | **-32768 ~ 32767** |
| `int` | 4 | 32 | **-2147483648 ~ 2147483647** |
| `long long` | 8 | 64 | 约 ±9.2 × 10¹⁸ |

实测输出：

```
5) short 最大 32767，最小 -32768
   int   最大 2147483647，最小 -2147483648
```

> **一句话因果链**：类型 → 占几字节 → 有几比特 → 能表示几种值 → 数值范围。
> 这也是为什么我在笔记里说"**变量长度不同，存储的数据范围就有差异**"——这句话是对的，而且现在能自己解释了。

## 5. ★ 大坑：`sizeof` 里面的表达式**不会被算**

看我自己 VS 里跑的这段（**作业截图**）：

![[L10-sizeof不求值.png]]

```c
short s = 12;
int b = 10;
printf("%zu\n", sizeof(s = b + 1));   // 打印 2
printf("s=%d\n", s);                  // 打印 s=12（不是 11！）
```

**输出**：

```
2
s=12
```

**为什么是 2？** `s` 是 `short`，占 2 字节 → `sizeof` 只关心**类型**，就给了 2。

**为什么 `s` 还是 12？** 因为 **`sizeof` 只"看类型"，不会真的执行里面的赋值**。那行 `s = b + 1` 一次都没跑。

我在 gcc 上也重复了一遍，结果一模一样：

```
3) sizeof(s = b + 1) = 2
   算完之后 s 还是 = 12   （那行赋值压根没执行）
```

> 原理：`sizeof` 的结果**在编译阶段就定下来了**（编译器一看 `s = b+1` 这整句的结果类型是 `short`，就知道是 2 字节），**根本不需要在运行时去算**——所以里面的代码不会被执行。
>
> ⚠️ 所以千万别把 `sizeof` 当成"帮我算一下这个表达式"的工具：**它只量类型，不干活。**

### 标准只保证"下限"和"顺序"（cppreference 的表）

![[L10-标准类型宽度表.png]]

| 类型 | C 标准规定（**最少**几位） | 说明 |
|---|---|---|
| `char` | at least **8** | 至少 1 字节 |
| `short` | at least **16** | 至少 2 字节 |
| `int` | at least **16** | ⚠️ 标准只说至少 16 位，但现在几乎所有平台都是 32 位 |
| `long` | at least **32** | Windows 上是 32 位，Linux 上常是 64 位 |
| `long long` | at least **64** | 至少 8 字节 |

标准同时保证这条**大小顺序链条**（正好对应我笔记里那句话）：

```
1 == sizeof(char) ≤ sizeof(short) ≤ sizeof(int) ≤ sizeof(long) ≤ sizeof(long long)
```

> 📌 注意 `1 == sizeof(char)`：**char 永远是 1 字节**（因为"字节"这个单位就是按 char 定义的）。

> [!question]- 参考答案（先自己答完再点开）
>
> 1. **不是函数，是操作符**。判断依据：① `sizeof x` **不加括号也能用**（函数必须加括号）；② 不需要 `#include` 任何头文件（函数要）；③ 结果在**编译时**就定下来了。

## 9. 嵌入式视角

- **比特是嵌入式的真正战场**。单片机 RAM 以字节计（几 KB），但**寄存器是逐位操作的**：`GPIOA->ODR |= (1 << 5);` 意思是"把第 5 个位拉高"，这里每一个位都对应一根真实的引脚。**今天搞清 1 字节 = 8 比特，就是为后面点灯、配置寄存器铺路。**
- **省内存靠"选对类型"**：只是数到 100 的计数器，用 `char`（1 字节）就够了，别用 `int`（4 字节）。几 KB 的 RAM 里，这种节省是成倍的。
- **跨平台用 `stdint.h`**：因为 `long` 在 Windows/Linux 上不一样，嵌入式代码普遍用 **`uint8_t` / `uint16_t` / `uint32_t`**（名字里写明了位数），换芯片不用改代码。
- **`sizeof` 在嵌入式里的高频用法**：算缓冲区大小、算要发几个字节、`sizeof(arr)/sizeof(arr[0])` 求数组元素个数（学到数组会用到）。

## 10. 复习题讲评（2026-09-16 我的作答）

**我的答案**：1. 不是函数，后面不带 `()`　2. `sizeof(int)` 对　3. 8、32　4. **2 和 5**　5. 括号内不进行运算，**8**

**评分：4 / 5**

| 题 | 判定 | 讲评 |
|---|---|---|
| 1 是不是函数 | ✅ 对 | "后面不带 `()`"抓住了关键。说精确点：**不是"必须不带"，而是"可以不带"**——`sizeof x` 合法、`strlen x` 不合法，这就是分界线 |
| 2 哪个对 | ✅ 对 | `sizeof(int)` 对；`sizeof int` 会报 `expected expression before 'int'` |
| 3 字节 / 比特 | ✅ 对 | 8、32 全对 |
| 4 打印什么 | ❌ **错**（答 2，应该是 **4**） | 第二个数（`n = 5`）答对了。第一个数错在**看错了表达式的结果类型**，见下 |
| 5 信 8 还是 16 | ✅ 对 | "8"（以自己机器的实测为准）+ "括号内不进行运算"也说对了 |

### 第 4 题错在哪：`sizeof` 看的是"**结果类型**"，`n` 是 `int` 不是 `short`

我把两个例子并排跑了一遍，一眼就看出差别：

```c
short s = 12;
int   b = 10;
int   n = 5;
```

| 表达式 | 我算的 | 实测 | 为什么 |
|---|---|---|---|
| `sizeof(s = b + 1)` | 2 | **2** | 赋值给 `s`，`s` 是 **short** → 2 字节 |
| `sizeof(n = n + 100)` | ~~2~~ ❌ | **4** | 赋值给 `n`，`n` 是 **int** → **4 字节** |

**我错在把上面那题的 `short` 印象直接搬过来了**——但这题里 `n` 是 `int`，所以是 4。

> **判断口诀**：`sizeof(表达式)` **不看值、不看算式**，只看**这条表达式最后得出的东西是什么类型**。
> 第 4 题的表达式是 `n = n + 100`，它最后"吐出来"的是一个 **int**（因为左边 `n` 是 int）→ 4 字节。

### 完整实测（含一个彩蛋：整数升级）

```
sizeof(s = b + 1)   = 2   <- 结果是 short 类型
sizeof(n = n + 100) = 4   <- 结果是 int 类型（n 是 int！）
sizeof(s + b)       = 4   <- short + int 会自动升级成 int
sizeof(s + s)       = 4   <- 两个 short 相加也会升级成 int
----------------------------------------
算完之后: s = 12, n = 5   （都还是原值 -> 里面的运算没执行）
```

**彩蛋解读**（现在只要有个印象，不用记）：

- `s + b`：`short + int` → 结果是 **int**（4 字节）
- `s + s`：**两个 short 相加，结果也是 int**（4 字节），不是 short！

这叫**整数提升**：C 在做运算时，会把比 `int` 小的类型（`char`、`short`）先"升级"成 `int` 再算。
> 所以 `sizeof(s + s)` 是 4 不是 2 —— **这是以后写代码时容易踩的坑**（比如 `char + char` 不会溢出在 8 位里，而是在 32 位里算）。先记住有这么回事。
