# L26 整数逆序（把 352 变成 253）

- 日期：2026-09-21
- 来源：翁恺《C语言程序设计》循环练习，我自己写的整数逆序程序
- 标签：`#C语言` `#基础语法` `#循环` `#取余`

> **一句话总结**：
> **想逆序一个整数，就从个位开始一位一位"拔"出来，再一位一位"往右边接"**：
> `x % 10` 拔个位 → `ret = ret * 10 + digit` 接到结果末尾 → `x /= 10` 把个位丢掉 → 循环。

---

## 1. 我的程序

![[L26-我的整数逆序代码.png]]

```c
int main() {
    int x;
    scanf("%d", &x);
    int digit;
    int ret = 0;

    while (x > 0) {
        digit = x % 10;                  /* ① 拔出个位 */
        ret = ret * 10 + digit;          /* ② 接到结果末尾 */
        printf("x=%d,digit=%d,ret=%d\n", x, digit, ret);   /* 调试用 */
        x /= 10;                         /* ③ 丢掉个位 */
    }
    printf("%d", ret);
    return 0;
}
```

**逐轮推演**（输入 `352`，AI 实测输出）：

| 轮次 | 进循环时 `x` | `digit = x%10` | `ret = ret*10 + digit` | `x /= 10` 后 |
|---|---|---|---|---|
| 第 1 轮 | 352 | **2** | `0*10+2` = **2** | 35 |
| 第 2 轮 | 35 | **5** | `2*10+5` = **25** | 3 |
| 第 3 轮 | 3 | **3** | `25*10+3` = **253** | 0 |
| 第 4 次检查 | 0 | — | — | `x > 0` 不成立 → 退出 |

→ 输出 **253** ✅

## 2. 三步套路（这三行就是"逆序"的全部秘密）

| 步骤 | 代码 | 作用 |
|---|---|---|
| ① 拔 | `digit = x % 10;` | **拿到个位数**（L23 学的：`%10` 取尾巴） |
| ② 接 | `ret = ret * 10 + digit;` | **把已有结果整体左移一位（乘 10），个位空出来给新数字** |
| ③ 丢 | `x /= 10;` | **把刚拔掉的那位丢掉**（`/10` 丢尾巴） |

**打比方**：像**拧一个万花筒/拨一个号码盘**——
先把手里已经攒的数**整体往左挪一格**（乘 10，腾出最右边的个位），
再把刚拔下来的数字**塞进那个空位**。每轮塞一个，塞完的位数正好反过来。

**这两个写法是同一族的**（以后会一直遇到）：

- **数位数**（L23）：`n++; x /= 10;` —— 只要计数
- **逆序**（L26）：`ret = ret*10 + x%10; x /= 10;` —— 不但数，还**用上了每一位**
- **拆位求和**（以后）：`sum += x % 10; x /= 10;`

## 3. 实测结果

### ✅ 逻辑完全正确

**1~100000 穷举对比参考实现：不一致 0 处** ✅

### ⚠️ 边界样品（他这套代码的实际行为）

| 输入 | 输出 | 判定 |
|---|---|---|
| 352 | 253 | ✅ 正确 |
| 5 | 5 | ✅ |
| 101 | 101 | ✅ |
| **10** | **1** | ⚠️ 尾部的 `0` 丢了（"01" → 整数不存前导零，就是 `1`） |
| **100** | **1** | ⚠️ 同上（"001" → 1） |
| **1000** | **1** | ⚠️ 同上（"0001" → 1） |
| **120** | **21** | ⚠️ 同上（"021" → 21） |
| **0** | **0** | ✅（`while` 一次没进，`ret` 保持 0，恰好对） |
| **-352** | **0** | ❌ 负数一次都进不了循环 → 输出 0（应该输出 -253） |
| 2147483647 | **-1126087180** | ❌ 逆序后超过 `int` 上限 → **溢出错值**（原理待学） |
| 1999999999 | 1410065399 | ❌ 同上（溢出） |
| 123456789 | 987654321 | ✅ 这个刚好没溢出 |

**结论**：

- **正数范围内，你的写法是对的**（穷举 0 处错）；
- 但**"尾部有 0 的数"**和**"负数"**是这类题的两大边界坑；
- **数字太大还会溢出**（`int` 装不下逆序后的值）—— 溢出的原理**以后学到再讲**，现在只要记住"输入很大时会出怪值"。

## 5. 复习题（先自己答）

1. `ret = ret * 10 + digit;` 里的 `* 10` 是干什么用的？不乘 10 会怎样？
2. `x % 10` 和 `x /= 10` 这两句分别在"拿哪一位"？
3. 输入 `120`，这套程序输出什么？为什么不是 `021`？
4. 输入 `-352` 会输出什么？为什么？
5. 交 OJ 之前，这个程序有哪三处必须先改？

> [!question]- 参考答案（先自己答完再点开）
>
> 1. **`* 10` 是把已有的结果整体左移一位**（腾出最右边的个位），好让新拔出来的数字塞进那个空位。不乘 10 的话，`ret` 只是在**累加**各位数字（352 → 2+5+3 = 10），而不是拼接成 253。
> 2. `x % 10` 拿的是**当前最低位（个位）**；`x /= 10` 丢掉刚拿掉的那一位，把原来的十位升成新的个位。
> 3. 输出 **21**。因为 `120` 逆序是 `021`，而**整数不保存前导零**——`021` 和 `21` 是同一个数，打印出来就是 `21`。（要输出 `021` 就得用字符串处理，以后学。）
> 4. 输出 **0**。因为 `while (x > 0)` 对负数**一次都不成立**，循环体一下都没跑，`ret` 保持初始值 0。（要处理负数得先取绝对值、或改成 `while (x != 0)` 并用 `x % 10` 的负数结果去处理，属于进阶。）
> 5. ① **删掉调试 `printf`**；② **最后那句补 `\n`**；③ 如果题目还要用原数，**先把 `x` 备份**（另外交之前先自己试 `0`、负数、尾部有 0 的数三组边界）。

## 6. 嵌入式视角

- **逆序/拆位这套操作在嵌入式和通信里天天用**：
  - **字节序翻转（大小端）**：串口/网络收到多字节整数，常常要把高低字节反序，方法就是同一套"拔-接"思路（配合移位和掩码）。
  - **BCD 转换**：数码管、时钟芯片（DS1302 等）用 BCD 码存时间，`x % 10` 拿个位、`x / 10` 拿十位是标准写法。
  - **显示数字到数码管/LCD**：要把一个整数一位位拆开送出去，跟逆序用完全一样的三步。
  - **校验和/CRC**：逐位取出处理，也是 `%` 和 `/` 的循环。
- **`ret = ret * 10 + digit` 里的"乘 10"在单片机上的代价**：早期单片机没有硬件乘法器，`* 10` 会被编译成**移位加法**（`ret*10 = ret*8 + ret*2`）；有的编译器让写 `ret = (ret << 3) + (ret << 1) + digit;`。现在 Cortex-M 系列都有单周期乘法，直接写 `* 10` 就行，编译器自己优化。
- **溢出在嵌入式上更危险**：`int` 在 32 位单片机上同样是 32 位，逆序大数会溢出；而嵌入式没有"报错弹窗"，溢出只是**默默给个错值**去驱动电机/继电器——所以**边界测试比 PC 上更要紧**。
