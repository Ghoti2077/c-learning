# L23 `while` 循环第一课（数位数）+ `else if` 条件顺序

- 日期：2026-09-21
- 来源：我开始学 `while`（翁恺课件的"数位数"程序）+ 我自己总结的一条规律
- 素材：课件"数位数"代码截图（我注释掉了其中两行）
- 标签：`#C语言` `#基础语法` `#循环` `#while` `#分支`

> **一句话总结**：
> **`while (条件) { 循环体 }`** = "**条件成立就一直重复做**，每做一轮重新检查一次条件"。
> 我那两行被注释掉的 `n++; x /= 10;` **不是多余的**：它们是"**先手动算掉一位**"，
> 让 **0（和负数）这种"进不去循环"的输入也有答案**——我测试用的都是正数，所以看不出差别。

---

## 1. 先看这段代码（数位数）

![[L23-课件 数位数程序（两行预处理）.png]]

```c
int main() {
    int x;
    int n = 0;
    scanf("%d", &x);
    //n ++;          /* ← 我把这两行注释掉了 */
    //x /= 10;
    while (x > 0) {
        n++;
        x /= 10;
    }
    printf("%d\n", n);
    return 0;
}
```

**`while` 的结构**：

```
while (条件)
{
    循环体;        /* 条件成立 → 做一遍 → 回去再看条件 → 直到条件不成立才往下走 */
}
```

**打比方**：像"**刷卡进门反复交费**"——门口保安每次都问"余额还够吗（条件）"，够就放你进去做一轮（循环体），做完回到门口**再问一次**，直到不够为止。

**逐行读这段程序**（`x = 123`）：

| 轮次 | 进循环前 `x` | 条件 `x > 0` | 做 `n++` | 做 `x /= 10` | 这轮后 |
|---|---|---|---|---|---|
| 第 1 轮 | 123 | 真 | n=1 | x=12 | n=1, x=12 |
| 第 2 轮 | 12 | 真 | n=2 | x=1 | n=2, x=1 |
| 第 3 轮 | 1 | 真 | n=3 | x=0 | n=3, x=0 |
| 第 4 次检查 | 0 | **假** | — | — | 跳出循环 |

→ 最后打印 `3`，正好是 123 的位数 ✅

**两个要点**：

1. `x /= 10` 每轮把末尾一位丢掉（整数除法），所以循环一定会**结束**——这叫"**循环变量在往条件不成立的方向走**"，写 `while` 时**永远要确认这一点**，否则就是死循环。
2. `n` 就是"数了几轮"。

## 2. 我注释掉的那两行，到底有没有用？

**我为什么看不出差别**：我试的输入（123、5、10000）都是正数，循环至少能进一次，所以那两行"白干"。

**实测（AI 跑了两份代码对比）**：

| 输入 | 有那两行 | 注释掉后 | 说明 |
|---|---|---|---|
| 123 | 3 | 3 | 一样 |
| 5 | 1 | 1 | 一样 |
| 10000 | 5 | 5 | 一样 |
| **0** | **1** | **0** ❌ | **差别在这！** |
| **-5** | **1** | **0** ❌ | 负数同理 |
| **-123** | **1** | **0** ❌ | 负数同理 |

**为什么**：`while (x > 0)` 对 `x = 0` **一次都进不去** → `n` 还是 0。而 **0 这个数本身是 1 位数**，所以：

- **有那两行**：先手动数掉一位（`n=1`、`x=0`），循环再处理剩下的 → 0 得到 **1** ✅
- **注释掉**：0 得到 **0** ❌

> **所以那两行是"先手动做一遍，再交给循环做剩下的"** —— 这种写法专门用来兜住
> "**循环条件一上来就不成立**"的情况。课件留下它们是有理由的：**输入 0 时答案才对**。
>
> （对负数，需求本身没定义"位数"，程序的输出只是行为，不算对错。）

**给我的教训**：判断某行代码"有没有用"，**不能只试几组输入**——要试**边界**（这里就是 0）。我上一道题（成绩转换）也是边界（59、100）出问题。

## 3. 我总结的那条规律：条件顺序

> **我的原话**：「用大于来判断的时候要从大到小来，用小于来判断的时候要从小到大来。」

**✅ 完全正确。** AI 用三种写法穷举 0~120 分对表：

| 写法 | 顺序 | 结果 |
|---|---|---|
| `if (s >= 90) ... else if (s >= 80) ...` | **大到小** | **错 0 处** ✅ |
| `if (s < 60) ... else if (s < 70) ...` | **小到大** | **错 0 处** ✅ |
| `if (s < 90) ... else if (s < 80) ...` | 大到小（配 `<`） | **错 80 处** ❌ |

**错的那个例子**：`x = 50` → 先问"50 < 90 吗" → 成立 → 直接输出 `B`（正确答案是 `E`）。

**本质上就一条**：

> **级联里的条件要"由窄到宽"排** —— 先问**最严格、范围最窄**的那个；
> 一旦某条成立，后面的**全部不看**（这是我们在 L20 实测过的）。
> - 用 `>=` 写：最窄的是**最大的那个边界** → 所以从大到小；
> - 用 `<` 写：最窄的是**最小的那个边界** → 所以从小到大。

**所以你的"口诀"和本质是一致的**，我把它归纳成一句：**别让宽条件挡在窄条件前面。**

## 4. 复习题（先自己答）

1. `while (条件) { 循环体 }` 里的条件，是在**什么时候**被检查的？（一次还是很多次？）
2. 数位数程序里，`x /= 10` 为什么能让循环**一定结束**？如果不写它，会发生什么？
3. 输入 `0` 时，注释掉那两行会输出什么？为什么？
4. 用 `>=` 写成绩等级级联时，为什么必须**从大到小**？如果从小到大会怎样（举一个分数）？
5. 用 `<` 写的时候，条件该怎么排？

> [!question]- 参考答案（先自己答完再点开）
>
> 1. **每一轮都检查**：进循环前检查一次，每做完一轮循环体**回到开头再检查一次**，直到条件不成立才跳出。
> 2. `x /= 10`（整除）每轮都让 `x` **变小**，最终会掉到 0，那时 `x > 0` 不成立 → 循环结束。**不写它**：`x` 永远不变、条件永远成立 → **死循环**（程序卡死）。
> 3. 输出 **0**。因为 `while (x > 0)` 在 `x = 0` 时一次都进不去，`n` 保持 0；而 0 其实是 1 位数。那两行"先手动算一位"就是为了兜住这种情况。
> 4. 因为级联**一旦某条成立后面的都不看**。写成小到大（`>= 60` 在前），90 分也会先命中 `>= 60` → 被打成"及格"。所以要用最大/最严格的边界先去筛。
> 5. **从小到大**：`if (s < 60) ... else if (s < 70) ... else if (s < 80) ... else if (s < 90) ... else ...`（最窄的边界最小，先问）。

## 5. 嵌入式视角

- **`while` 是单片机的"主循环"骨架**：`int main(void) { 初始化(); while (1) { 做事情(); } }` —— 嵌入式程序**几乎不会退出**，就是靠一个永不结束的 `while (1)` 一直跑（这就是"死循环"在 PC 上是 bug、在单片机上却是**设计**的原因）。
- **"先手动做一次再进循环"的思路在嵌入式里也有**：比如按键消抖，第一拍先采样，之后 `while` 里反复采样确认；或者串口收包，先处理第一个字节，再循环处理剩下的。
- **边界测试就是硬件测试**：今天这个"0 是 1 位数"的坑，等价于嵌入式里的"传感器读数为 0 / 满量程 / 负值"——**正常值都对，边界值才暴露问题**。
