# L16 运算符的优先级、结合性、求值顺序（谁先算？）

- 日期：2026-09-20
- 来源：我提问"搞不清运算符、赋值这类的先后顺序" + 我自己的找零程序
- 标签：`#C语言` `#基础语法` `#运算符` `#优先级`

> **一句话总结**：判断一条式子怎么算，要分清**三件事**：
> ① **优先级**（谁先算）→ ② **结合性**（同一级别时往哪边算）→ ③ **求值顺序**（这个**C 往往不保证**）。
> **保命办法：记不住就加括号**——括号永远最高，加了它你说的算。

---

## 1. 先分清三件事（混在一起才会晕）

| 概念 | 回答的问题 | 例子 |
|---|---|---|
| **优先级** | 谁先算？ | `2 + 3 * 4` → 先 `3*4`（`*` 比 `+` 高） |
| **结合性** | 同一级别时，往左算还是往右算？ | `10 - 4 - 3` → 从左往右 `(10-4)-3 = 3` |
| **求值顺序** | 两边的"东西"谁先被算出来？ | **C 常常不规定！**（见第 4 节） |

> 我原来的困惑就是把前两个和后一个混着记了。**先记住"优先级管谁先算"，这一步就够用 90%。**

## 2. 优先级阶梯（只列你已经学过的 + 预告）

```
  高  ┌────────────────────────────┐
  ↑   │  1. ( )                    │  ← 括号，永远最优先
  │   │  2. ++ -- ! sizeof  -x     │  ← 单目运算（只有一个操作数）
  │   │  3. * / %                  │
  │   │  4. + -                    │
  │   │  5. < <= > >=              │  ← 关系
  │   │  6. == !=                  │  ← 相等（比关系低！）
  │   │  7. &&                     │  ← 逻辑"而且"（以后学）
  │   │  8. ||                     │  ← 逻辑"或者"（以后学）
  │   │  9. = += -= *= /= %=       │  ← 赋值：几乎最底
  │   │ 10. ,                      │  ← 逗号：最低
  低  └────────────────────────────┘
```

**一句话抓住重点**：

> **括号最优先 → 单目（`++` `--` `sizeof`）→ 乘除取余 → 加减 → 比较 → 赋值最后做。**

**赋值是全表里倒数第二低的**——这一条最有用：`int ih = hour2 - hour1;` 里，**右边的减法一定会先算完，最后才把结果装进 `ih`**。

## 3. 实测：把"谁先算"跑给你看

### ① 算术内部：`* / %` 比 `+ -` 高

| 式子 | 结果 | 怎么算的 |
|---|---|---|
| `2 + 3 * 4` | **14** | 先 `3*4=12`，再 `+2` |
| `(2 + 3) * 4` | **20** | 括号强行先算 |
| `1 + 2 * 3 - 4` | **3** | `1+6-4` |
| `(1 + 2) * (3 - 4)` | **-3** | 两个括号各自先算 |

### ② 同级别看结合性：**从左往右**

| 式子 | 结果 | 怎么算的 |
|---|---|---|
| `10 - 4 - 3` | **3** | `(10-4)-3 = 3`（**不是** `10-(4-3)=9`） |
| `100 / 10 / 2` | **5** | `(100/10)/2` |

### ③ 赋值：**从右往左**（这个叫"右结合"，和别的相反）

| 式子 | 结果 | 怎么算的 |
|---|---|---|
| `a = b = 5` | a=5、b=5 | **先** `b=5`，**再**把 b 的值给 a |
| `x = 1 + 2 * 3` | x=**7** | 先把右边全算完（=7），**最后**才赋值 |
| `a = b = c`（c=3） | a=3、b=3、c=3 | 从最右边开始往左传 |

### ④ 关系 比 相等 高；算术又比关系高

| 式子 | 结果 | 怎么算的 |
|---|---|---|
| `3 < 5 == 1` | **1** | 先 `3<5` 得 1，再 `1 == 1` |
| `7 >= 3 + 4` | **1** | 算术先于关系：`7 >= 7` |
| `4 > 2 + 1` | **1** | `4 > 3` |
| `(4 > 2) + 1` | **2** | 括号先算得 1，再 `1+1` |

> 最后两行是关键对比：**同一堆符号，加不加括号结果从 1 变成 2。**

## 4. ⚠️ 优先级 ≠ 求值顺序（这个区别很高级，但必须知道）

**"优先级高"只说明"谁和谁先黏在一起"，不保证"谁先被算出来"。**

最典型的例子（我在 L12 里踩过）：

```c
int a = 2;
printf("%d %d %d\n", a++, ++a, a);   /* 同一个 a，一句里自增两次 */
```

编译器警告：`operation on 'a' may be undefined`（**未定义行为**）。

> **结论**：C 标准**不规定**函数参数、`+` 左右两边这些"并列的东西"谁先求值。
> **所以规矩是**：一句里对一个变量只改一次；**别写依赖求值顺序的代码**。

## 5. 实用口诀（背这三条就够）

| 口诀 | 说明 |
|---|---|
| **拿不准就加括号** | 括号最高、最清楚，还能防错。工程代码里到处是"多余的括号"，那不是啰嗦，是自保 |
| **赋值几乎总是最后做** | 右边全算完 → 才赋值。所以 `x = 复杂式子;` 不用怕 |
| **一句里只改一个变量一次** | 避免掉进"求值顺序"的坑 |

## 6. 怎么读一个复杂表达式（方法）

```
1. 先找括号 → 括号里先算（从最里面一层开始）
2. 再找单目（++ -- sizeof ! 负号）
3. 然后按阶梯：* / % → + - → 比较 → 赋值
4. 同级别时从左往右（赋值除外，从右往左）
```

**拿 `int ih = hour2 - hour1;` 走一遍**：没有括号 → 没有单目 → 先 `-`（加减级）→ 最后赋值给 `ih`。

## 7. 顺便：我的新程序（找零计算器）+ 实测

![[L16-找零程序.png]]

```c
int main(void)
{//初始化
    int price = 0;
    int bill = 0;
    //input price and bill
    printf("请输入金额");
    scanf("%d", &price);
    printf("请输入票面");
    scanf("%d", &bill);
    //计算找零
    printf("应该找您%d元", bill - price);

    return 0;
}
```

**我实测跑了两组**：

| 输入金额 | 输入票面 | 输出 |
|---|---|---|
| 35 | 100 | `应该找您65元` ✅ |
| 80 | 50 | `应该找您-30元` ⚠️ **出现了负数** |

**这里正好是优先级实战**：`printf("应该找您%d元", bill - price);` 里，`bill - price` **先算完再交给 printf**——因为函数参数先算、`-` 的优先级又比赋值高。**程序能工作，就是靠这条。**

**可以改进的地方（正好用上刚学的 `if`）**：

```c
if (bill < price) {
    printf("票面不够，还差 %d 元\n", price - bill);
} else if (bill == price) {
    printf("刚好，不用找零\n");
} else {
    printf("应该找您 %d 元\n", bill - price);
}
```

> 📌 **这是你的第 2 个实用程序**（第 1 个是时间差计算器）。它已经从"算一个值"进阶到"输入 → 处理 → 输出"的完整小工具了 👍

## 9. 复习题（先自己答）

1. `2 + 3 * 4` 等于几？为什么不是 20？
2. `10 - 4 - 3` 等于几？为什么不是 9？
3. `a = b = 5` 是先做哪一步？（从左还是从右？）
4. 下面两句结果一样吗？为什么？
   ```c
   printf("%d\n", 4 > 2 + 1);
   printf("%d\n", (4 > 2) + 1);
   ```
5. `int ih = hour2 - hour1;` 里，赋值是第几步做的？
6. 你的找零程序输入"金额 80、票面 50"时会输出什么？该怎么改？

> [!question]- 参考答案（先自己答完再点开）
>
> 1. **14**。`*` 优先级比 `+` 高，先算 `3*4=12`，再 `2+12=14`。想得 20 要加括号：`(2+3)*4`。
> 2. **3**。同一级别**从左往右**：先 `10-4=6`，再 `6-3=3`。（`10-(4-3)=9` 是另一种算法，C 不这么算）
> 3. **从右往左**（赋值是右结合）：先执行 `b = 5`，再把 `b` 的值赋给 `a`。
> 4. **不一样**。第一句：算术先于关系 → `4 > 3` → **1**；第二句：括号先算 → `(4>2)=1`，再 `1 + 1` → **2**。
> 5. **最后一步**。赋值优先级很低：先把 `hour2 - hour1` 算完，最后才装进 `ih`。
> 6. 输出 `应该找您-30元`（出现负数，说明输入不合理）。改法：用 `if` 判断——`bill < price` 提示"票面不够"、`bill == price` 提示"刚好"、否则才算找零。

## 10. 嵌入式视角（优先级的坑在这里最要命）

- **`&` 的优先级比 `==` 低**——嵌入式最著名的坑：
  ```c
  if (a & 0x01 == 0)        /* ❌ 实际是 a & (0x01 == 0) -> a & 0 */
  if ((a & 0x01) == 0)      /* ✅ 必须加括号 */
  ```
  **判断寄存器某一位，一定要给按位运算加括号。**
- **`<<` 比 `+` 低、比 `|=` 高**，所以 `GPIOA->ODR |= 1 << 5;` 才成立（先把 1 左移 5 位，再按位或进去）。**这句以后点灯第一天就要写**，写错一位灯就不亮。
- **求值顺序的坑在中断里更危险**：`flag++` 之类同一个变量在一条语句里改两次，在不同优化等级下行为可能不同 → 单片机上是"改一下优化就复现不了"的玄学 bug。
- **工程规范**：`if ((x > 0) && (y > 0))` 这种"看着多余的括号"，在嵌入式代码里是**标准写法**——因为它是自保，不是啰嗦。
