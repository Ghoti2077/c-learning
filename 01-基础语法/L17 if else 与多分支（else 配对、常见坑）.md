# L17 if…else 与多分支（else 到底跟谁配对）

- 日期：2026-09-21
- 来源：接 L15（`if` + 关系运算符）→ 把 `if` 升级成**完整分支**
- 标签：`#C语言` `#基础语法` `#分支` `#if`

> **一句话总结**：`if` 是"如果"，`else` 是"否则"，`else if` 是"再不然的话"——
> **它们从上往下一条条试，第一条为真的就执行，后面全部跳过。**
> 规矩：**要么全写花括号，要么别缩进骗自己**（`else` 永远粘最近那个没配对的 `if`）。

---

## 1. 先打比方：学校门口的保安

你早上进校门，保安按顺序问你：

1. 「有校卡吗？」→ 有 → **放行**（后面两个问题他就不问了）
2. 「有学生证吗？」→ 有 → 放行
3. 「啥都没有？」→ **请去登记**（这就是 `else`）

关键点两个：
- **从上往下问，问到"是"就停**（后面不看了）
- **`else` 不用"条件"**——它是"前面全不成立"的兜底

## 2. 三种形态（这是本课全部内容）

### 形态①：只有 if（可能什么都不做）

```c
if (bill < price)
{
    printf("票面不够\n");
}
```

条件不成立 → **整块跳过，程序继续往下走**。不需要 `else`。

### 形态②：if + else（二选一，必走一条）

```c
if (bill < price)
{
    printf("钱不够\n");
}
else
{
    printf("够\n");
}
```

`==` 判断和这个配合最顺：

```c
if (bill == price)
{
    printf("刚好，不用找零\n");
}
else
{
    printf("要算找零\n");
}
```

### 形态③：if + else if + else（多选一，我从上往下一条条试）

```c
if (score >= 90)
{
    printf("等级 A\n");
}
else if (score >= 80)
{
    printf("等级 B\n");
}
else if (score >= 60)
{
    printf("等级 C\n");
}
else
{
    printf("不及格\n");
}
```

**语义**：一个分数**只会打印一行**。因为第一条成立就跳出整条链了。

**实测**（gcc 编译运行）：`score = 78`

```
等级 C
```

> 为什么不是 B？因为 78 先被 `>= 90` 判否、再被 `>= 80` 判否、`>= 60` 成立 → 打印"等级 C"，然后**整条链结束**，不等它再往下比。

⚠️ **顺序写错结果就错**：如果把 `score >= 60` 放到最上面，那么 95 分也会打印"等级 C"（因为 95 >= 60 先成立就跳出了）。**条件越严格的要写在越上面。**

## 3. ⚠️ 三个必踩的坑（都实测过）

### 坑①：`else` 永远粘**最近那个**没配对的 `if`（悬空 else）

```c
int a = 10;
int b = 20;

if (a > 5)
    if (b > 100)
        printf("A\n");
else
    printf("B\n");      /* 这个 else 到底跟谁？ */
```

**缩进看着像跟外层 `if (a > 5)` 配对，其实 `C` 认的是最近的内层 `if (b > 100)`。**

实测输出：

```
B（这个 else 跟谁跑了？）
```

编译器还会当场警告（gcc）：

```
warning: suggest explicit braces to avoid ambiguous 'else' [-Wdangling-else]
```

**改成给外层加花括号**，`else` 就老实跟着外层了：

```c
if (a > 5)
{
    if (b > 100)
        printf("A\n");
}
else
{
    printf("B\n");
}
```

这个版本实测：**什么都不打印**（`a > 5` 成立进去了，里面 `b > 100` 不成立，啥也不干；`else` 属于外层，不执行）。

> **两种写法结果完全不同**：一个打印 B，一个啥也不打印。
> **保命规矩：只要里面还套着 if，外面就加花括号。**

### 坑②：`if (a = 5)` —— 一个等号，是赋值不是比较

```c
int a = 0;
if (a = 5)              /* 把 5 装进 a，然后判断"5"是不是真 */
{
    printf("进来了，a 现在 = %d\n", a);
}
```

实测输出：

```
版本1：进来了，a 现在 = 5
```

条件恒成立（非 0 就是真），而且 a 被悄悄改成了 5。gcc 警告：

```
warning: suggest parentheses around assignment used as truth value [-Wparentheses]
```

对比正确的写法（`a = 0; if (a == 5)`）实测输出：`版本2：没进去，a = 0`。

> **口诀**：**一个等号 `=` 是"装进去"，两个 `==` 才是"问一句是不是"。**
> 看到编译器说 `-Wparentheses` 就八成是这里的锅。（我在 L15 已经踩过一次）

### 坑③：`if (...)` 后面多写一个分号

```c
a = 1;
if (a > 0);          /* ← 这个分号 = 一句空话，if 只管住它 */
{
    printf("这行其实和 if 没关系，永远会执行\n");
}
```

实测输出：

```
版本3：这行其实和 if 没关系，永远会执行
```

gcc 也会提醒：

```
warning: this 'if' clause does not guard... [-Wmisleading-indentation]
```

> **分号本身是"空语句"**。`if (a > 0);` 的意思是"如果 a 大于 0，就执行一句空话"，下面那对花括号变成一个**独立的语句块**，跟 `if` 没关系了。

## 4. 花括号到底写不写？

| 写法 | 好不好 |
|---|---|
| `if (x > 0) printf("好");` | 合法，单句可以省 |
| 里面两句却不写花括号 | ❌ 只有第一句归 `if`，第二句永远执行（经典坑） |
| **一律写花括号** | ✅ **推荐**，省得数"哪句归谁" |

嵌入式工程代码基本**一律带花括号**，不是为了好看，是为了不出坑。

## 5. 升级我的找零计算器（第 2 个实用程序 → 完整版）

```c
#define _CRT_SECURE_NO_WARNINGS 1
#include <stdio.h>

int main(void)
{
    int price = 0;
    int bill = 0;

    printf("请输入金额：");
    scanf("%d", &price);
    printf("请输入票面：");
    scanf("%d", &bill);

    if (bill < price)
    {
        printf("票面不够，还差 %d 元\n", price - bill);
    }
    else if (bill == price)
    {
        printf("刚好，不用找零\n");
    }
    else
    {
        printf("应该找您 %d 元\n", bill - price);
    }

    return 0;
}
```

**实测三组**（gcc，输入用回车分隔）：

| 输入金额 | 输入票面 | 输出 | 走了哪条 |
|---|---|---|---|
| 80 | 50 | `票面不够，还差 30 元` | 第一个 `if` |
| 50 | 80 | `应该找您 30 元` | 最后的 `else` |
| 80 | 80 | `刚好，不用找零` | `else if` |

> ✅ 这就是 L16 里"负数找零"那个问题的正解 —— 用分支把不合理的情况提前拦住。

3. `if (x = 0)` 和 `if (x == 0)` 有什么区别？哪个"永远不进去"？
4. `if (a > 0);` 后面那个分号删掉和留着，程序行为差在哪？
5. 下面这句合法吗？实际哪几句归 `if` 管？
   ```c
   if (n > 0)
       printf("1\n");
       printf("2\n");
   ```
6. 用 `if / else if / else` 写一个"判断成绩及格线并输出等级"的完整程序（自己手打，输出中文，跑出来给我看）。

> [!question]- 参考答案（先自己答完再点开）
>
> 1. 会出错。链是**从上往下一试就跳出**：`>= 60` 放最上面，95 分先命中它，直接打印"及格"，后面的 `>= 90` 根本轮不到。**条件越严格要排越上面。**
> 2. 打印 **`B`**。`else` 粘**最近**那个没配对的 `if`，也就是内层的 `if (b > 100)`：内层条件假 → 走 `else` 打印 B。（给外层加花括号后，就变成什么都不打印）
> 3. `if (x = 0)` 是**赋值**：把 0 装进 x，然后判断 0 —— **假，永远不进去**（而且 x 被改了）。`if (x == 0)` 是**比较**：x 等于 0 时才进去。记住：`=` 装值、`==` 问话。
> 4. 留着分号：那是个**空语句**，`if` 只"管住"这个空话，下面花括号/语句跟 `if` 无关，**永远执行**。删掉分号：下面的语句才真正归 `if` 管（条件假就不执行）。gcc 会警告 `-Wmisleading-indentation`。
> 5. 合法（编译器最多提醒缩进可疑）。**只有 `printf("1\n")` 归 `if` 管**；`printf("2\n")` 是独立语句，**永远执行**。所以 `n > 0` 时打两行，`n <= 0` 时也打第二行。
> 6. 参考第 2 节的形态③（`score >= 90 / >= 80 / >= 60 / else`），**条件从严格到宽松往下排**。

## 7. 嵌入式视角

- **`if` 是单片机里出现最多的语句**，而且常常写成"查寄存器某一位"的形式：
  ```c
  if ((GPIOA->IDR & 0x0001) == 0)   /* 检测 PA0 是不是低电平 */
  ```
  ⚠️ 这个 `&` 的判断**必须带括号**（L16 讲过的优先级坑）——**分支 + 位运算一起用的时候最容易翻车**。
- **`else if` 链的顺序在嵌入式里是"状态判断"**：按键是"按下 / 松开 / 长按"，谁排在前面直接决定逻辑对不对，跟成绩等级一个道理。
- **工程规范**：嵌入式编码规范（如 MISRA）**要求 `if`/`else` 一律加花括号**、`if` 里不许写赋值——上面那三个坑，在航空/汽车代码里都是"直接判不合格"的级别。
- 按键消抖、状态机、报警阈值判断，**本质都是今天这条 if-else 链**。

## 8. 我的实操（2026-09-21 在 VS 里手打 + AI 逐句核对）

### ① 找零程序升级成 if / else

![[L17-找零程序带 else 实测（93-200）.png]]

```c
int main(void)
{//初始化
    int price = 0;
    int bill = 0;
    //input price and bill
    printf("请输入金额");
    scanf("%d", &price);
    printf("请输入票面");
    scanf("%d", &bill);
    //计算找零
    if (bill > price) {
        printf("应该找您: %d\n", bill - price);
    }
    else {
        printf("您的钱不够");
    }
    return 0;
}
```

**逐句核对**：

| 检查点 | 判定 |
|---|---|
| 两个变量都先初始化 `= 0` | ✅ |
| 两个 `scanf` 都写了 `&` | ✅ |
| 注释写了（`//初始化`、`//input price and bill`） | ✅ 好习惯 |
| `if` / `else` 结构 | ✅ 用对了，`else` 负责"钱不够" |
| `if (bill > price)` 的条件 | ⚠️ **少了"刚好相等"**（见下） |
| 提示语没有 `\n` | ⚠️ 小瑕疵（见下） |

**AI 实测（gcc 直接跑你这份原代码）**：

| 输入金额 / 票面 | 输出 | 判定 |
|---|---|---|
| 93 / 200 | `应该找您: 107` | ✅ 对（和你截图一致） |
| **80 / 80** | `您的钱不够` | ❌ **相等不该说"不够"** |
| 100 / 50 | `您的钱不够` | ✅ 对，但没换行，会接在"请输入票面"后面 |

**改法（二选一）**：

```c
if (bill >= price)          /* ① 改成 >=，相等就走"找零"分支，输出 0 元 */
{
    printf("应该找您: %d 元\n", bill - price);
}
else
{
    printf("您的钱不够，还差 %d 元\n", price - bill);
}
```

```c
/* ② 或者用 else if 单独处理相等（就是 L17 学的那条链） */
if (bill > price)          { printf("应该找您: %d 元\n", bill - price); }
else if (bill == price)    { printf("刚好，不用找零\n"); }
else                       { printf("您的钱不够，还差 %d 元\n", price - bill); }
```

**关于 `\n`**：`printf("请输入金额");` 后面没有换行，你输入的数字就**接在同一行**上了——这就是截图里"请输入金额93"的原因。提示语结尾加 `\n`（或者干脆用 `printf("请输入金额：\n");`）就清爽了。

### ② 新写了一个"求最大值"程序 → 撞上 `mian` 拼错

![[L17-mian拼错导致 LNK2019.png]]

```c
int mian() {                      /* ← 问题就在这一行 */
    int a = 0, b = 0;
    printf("输入两个整数: ");
    scanf("%d %d", &a, &b);
    int max = 0;
    if (a > b) {
        max = a;
    }
    else {
        max = b;
    }
    printf("大的那个是%d\n", max);
    return 0;
}
```

**VS 报的两条错（原样抄下来）**：

```
LNK2019 无法解析的外部符号 main，函数 "int __cdecl invoke_main(void)" (?invoke_main@@YAHXZ) 中引用了该符号   MSVCRTD.lib(exe_main.obj)
LNK1120 1 个无法解析的外部命令   study2.exe
```

**这两条是说**：`main` 打成 **`mian`** 了，是拼写错误。

- 为什么**编译**能过：`mian` 语法上是个**合法的普通函数名**，编译器不认识"哪个名字才是入口"，只管语法
- 为什么**链接**挂：C 规定程序从 **`main`** 开始跑；链接器去 `MSVCRTD.lib` 里找 `main`，找不到 → 报 `LNK2019`，接着 `LNK1120` 说"共 1 个没解析出来的符号"
- 关键词：**错误只在"链接"阶段出现，说明代码语法没错，是"名字/入口"的问题**。以后看到 `LNK` 开头的错，先想"是不是拼错名字、漏了函数、或者有两个 main"

**AI 复现证据**（本机 VS2026 的 `cl.exe`，和你截图里一字不差）：

```
mian_typo.c
MSVCRTD.lib(exe_main.obj) : error LNK2019: 无法解析的外部符号 main，函数 "int __cdecl invoke_main(void)" (?invoke_main@@YAHXZ) 中引用了该符号
mian_typo.exe : fatal error LNK1120: 1 个无法解析的外部命令
```

把 `int mian()` 改成 `int main(void)` 后：编译通过，跑 `3 7` 输出 `max is 7` ✅。

**除了拼写，这段代码本身写得很对**：

| 检查点 | 判定 |
|---|---|
| 先定义 `int max = 0;`、两个分支都给它赋值 | ✅ |
| `if (a > b)` → `max = a`；`else` → `max = b` | ✅ 逻辑正确 |
| `scanf("%d %d", &a, &b);` 两个 `&` 都写了 | ✅ |
| 函数名 | ❌ `mian` → **`main`**（m-a-i-n） |
| `int max` 的位置 | ✅ 合法。小知识：C99 起允许在语句中间定义变量（你写的就是）；老标准（C89）要求变量都写在函数开头 |

> 💡 **少写一行的写法**（可选）：`int max = a;` 然后 `if (b > a) { max = b; }`——把"默认取 a、比 a 大才换成 b"写出来，就不用 else 了。
