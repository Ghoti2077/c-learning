# L33 补码与 unsigned：同一串位，两种读法

> 教材：**翁恺《C语言程序设计》**课件 5 张（补码 / 数的范围 / char c=255 / 整数的范围 / unsigned 与进制字面量）

> 课件 5 张已存 `_附件/`；两个验证程序源码在本文第 3 节（**都真跑过**）

## 1. 课件原话（我抄下来的）

### ① 补码（这节是全课的钥匙）

- 考虑 -1，我们希望 `-1 + 1 → 0`；而 `0` 是 `00000000`
- **补码的意义就是：拿补码和原码可以加出一个"溢出的零"**
- `11111111 + 00000001 → (1)00000000` —— 进位的那个 1 溢出丢掉，正好得 0
- 因为 `0 - 1 → -1`，所以 `-1 = (1)00000000 - 00000001 → 11111111`
- **「11111111 被当作纯二进制看待时，是 255；被当作补码看待时是 -1」** ← 记住这句
- 推广公式：对 `-a`，其补码就是 `0 - a`，也就是 **`2^n - a`**（n 是该类型的位数）
  - 8 位：`-1 = 2⁸ - 1 = 255 = 11111111` ✅
  - 8 位：`-128 = 2⁸ - 128 = 128 = 10000000` ✅

### ② 一个字节（8 位）能表示哪些数

| 位模式 | 值 |
|---|---|
| `00000000` | 0 |
| `00000001 ~ 01111111` | **1 ~ 127**（正的那半边） |
| `10000000 ~ 11111111` | **-128 ~ -1**（负的那半边；二进制越大，值越负） |

### ③ 课件里的那段代码

```c
char c = 255;
int i = 255;
printf("c=%d,i=%d\n", c, i);      /* 输出 c=-1,i=255 */
```

课件注释写着：`11111111` / `00000000 00000000 00000000 11111111`

> 为什么 `c` 是 -1：`char` 只有一个字节，255 塞进去就是 `11111111`；用**补码**读它 = -1。
> 为什么 `i` 还是 255：`int` 有 4 个字节，塞得下。

### ④ 整数的范围

| 类型 | 字节 | 范围 |
|---|---|---|
| `char` | 1 | -128 ~ 127 |
| `unsigned char` | 1 | 0 ~ 255 |
| `short` | 2 | -32768 ~ 32767 |
| `int` | 4（**本机实测**） | ±21 亿（见 [[L28 int的上限与溢出（为什么变负数）]]） |
| `long` | 4（Windows）/ 8（Linux） | 取决于编译器 |
| `long long` | 8 | 约 ±9.2×10¹⁸ |

（本机 `int` 和 `long` **都是 4 字节** —— 见 [[L10 sizeof（关键字、操作符、字节与比特）]]）

### ⑤ unsigned 与进制字面量

- **「unsigned 的初衷并非扩展数能表达的范围，而是为了做纯二进制运算，主要是为了移位」** ← 课件原话，本课第二个钥匙
- 输入输出只有两种形式：`int` / `long long`；`%d`(int)、`%u`(unsigned)、`%ld`、`%lu`
- **八进制以 `0` 开头**、十六进制 `0x`；`%o` 打八进制、`%x` 打十六进制
- **「8 / 16 进制只是"如何把数字表达为字符串"，与内部如何表达数字无关」**

## 2. 他的总结 + 判定

| 他说 | 判定 |
|---|---|
| 「unsigned **排除了负数**」 | ✅ **对**（范围就是 0 ~ 255） |
| 「unsigned **不以补码来表示**」 | ⚠️ **要拧一下**：位还是那串位，**变的只是"怎么读"** |

**为什么拧**：补码是**解读规则**，不是存储格式。课件自己那句就是证据 —— `11111111` 当纯二进制读 = 255，当补码读 = -1。

**比方（8 盏灯）**：8 盏灯的开关状态是**同一串** `11111111`：
- **补码读法（有符号）**：第 1 盏灯是"正负牌"（亮 = 负），剩下 7 盏从 0 往回数 → **-1**
- **纯二进制读法（无符号）**：**没有正负牌**，8 盏全算命 → **255**

**灯一盏都没动，只是读法变了。** 准确说法：unsigned **不是"没有补码"，而是压根不去解释符号** —— 8 位全是数值位。

## 3. 实测（源码 + 真输出，都是本机 gcc 跑的）

### 程序一：同一串位，两种读法

```c
#include <stdio.h>

int main(void)
{
    /* ① 同一串位，两种读法 */
    unsigned char bits = 0xFF;              /* 内存里：11111111 */
    printf("内存里的 11111111：\n");
    printf("  当纯二进制读 = %u\n", (unsigned)bits);
    printf("  当补码读     = %d\n", (int)(signed char)bits);

    /* ② 赋同一个字面量 255，两种类型 */
    signed char   sc = (signed char)255;
    unsigned char uc = 255;
    printf("\n都写 = 255：\n");
    printf("  signed char   sc = %d\n", (int)sc);
    printf("  unsigned char uc = %u\n", (unsigned)uc);
    printf("  它们在内存里的字节：%02X 和 %02X\n", (unsigned char)sc, uc);

    /* ③ 范围：数的个数一样，只是分界线挪了 */
    printf("\n一个字节能表示 2^8 = 256 个数：\n");
    printf("  signed char  : -128 ~ 127\n");
    printf("  unsigned char: 0 ~ 255\n");

    /* ④ 坑：signed 和 unsigned 混着比较 */
    printf("\n-1 < 1u 的结果：%s\n", (-1 < 1u) ? "真" : "假（-1 被转成 4294967295）");
    printf("-1 转成 unsigned 是：%u\n", (unsigned)-1);

    /* ⑤ 移位：课件说 unsigned 的"初衷" */
    signed char   s = -2;                   /* 11111110 */
    unsigned char u = 254;                  /* 11111110 */
    printf("\n同一串 11111110，右移一位：\n");
    printf("  signed   (-2) >> 1 = %d  （算术右移，左边补符号位 1）\n", (int)(s >> 1));
    printf("  unsigned (254) >> 1 = %u  （逻辑右移，左边补 0）\n", (unsigned)(u >> 1));
    return 0;
}
```

**真输出**：

```
内存里的 11111111：
  当纯二进制读 = 255
  当补码读     = -1

都写 = 255：
  signed char   sc = -1
  unsigned char uc = 255
  它们在内存里的字节：FF 和 FF        ← 字节一模一样！

一个字节能表示 2^8 = 256 个数：
  signed char  : -128 ~ 127
  unsigned char: 0 ~ 255

-1 < 1u 的结果：假（-1 被转成 4294967295）
-1 转成 unsigned 是：4294967295

同一串 11111110，右移一位：
  signed   (-2) >> 1 = -1  （算术右移，左边补符号位 1）
  unsigned (254) >> 1 = 127  （逻辑右移，左边补 0）
```

**最硬的证据**：`sc` 和 `uc` 内存里的字节**都是 `FF`** —— **存的一样，读的不一样**。

### 程序二：原理 —— 最高位的权重

```c
#include <stdio.h>

int main(void)
{
    /* ① 同一批字节，两种读法对照表 */
    printf("字节   纯二进制(unsigned)   补码(signed)\n");
    printf("0x00          %3u              %4d\n", 0u, 0);
    printf("0x7F          %3u              %4d\n", (unsigned)(unsigned char)0x7F, (int)(signed char)0x7F);
    printf("0x80          %3u              %4d\n", (unsigned)(unsigned char)0x80, (int)(signed char)0x80);
    printf("0xFF          %3u              %4d\n", (unsigned)(unsigned char)0xFF, (int)(signed char)0xFF);

    /* ② 原理就是"最高位的权重不同" */
    printf("\n0x80 = 10000000：\n");
    printf("  unsigned 读法：最高位权重 +2^7     = %u\n", 1u << 7);
    printf("  signed   读法：最高位权重 -2^7     = %d\n", -(1 << 7));

    printf("\n0xFF = 11111111：\n");
    printf("  unsigned 读法：128+64+32+16+8+4+2+1 = %u\n", 255u);
    printf("  signed   读法：-128 + 127           = %d\n", -128 + 127);

    printf("\n0x7F = 01111111（最高位是 0，所以两种读法一样）：\n");
    printf("  unsigned = %u   signed = %d\n", (unsigned)(unsigned char)0x7F, (int)(signed char)0x7F);

    /* ③ 范围公式 */
    printf("\n位数 b 的补码范围 = -2^(b-1) ~ 2^(b-1)-1\n");
    printf("  b=8 : %d ~ %d\n", -(1 << 7), (1 << 7) - 1);
    printf("  b=16: %d ~ %d\n", -(1 << 15), (1 << 15) - 1);

    /* ④ 八进制/十六进制字面量的坑 */
    int a = 010;        /* 0 开头 = 八进制！ */
    int b = 0x10;
    int c = 10;
    printf("\n010  = %d   ← 八进制，等于十进制的 8，不是 10！\n", a);
    printf("0x10 = %d\n", b);
    printf("10   = %d\n", c);
    printf("同一个数 255 的三种写法：%%d=%d   %%o=%o   %%x=%x\n", 255, 255, 255);
    return 0;
}
```

**真输出**：

```
字节   纯二进制(unsigned)   补码(signed)
0x00            0                 0
0x7F          127               127
0x80          128              -128
0xFF          255                -1

0x80 = 10000000：
  unsigned 读法：最高位权重 +2^7     = 128
  signed   读法：最高位权重 -2^7     = -128

0xFF = 11111111：
  unsigned 读法：128+64+32+16+8+4+2+1 = 255
  signed   读法：-128 + 127           = -1

0x7F = 01111111（最高位是 0，所以两种读法一样）：
  unsigned = 127   signed = 127

位数 b 的补码范围 = -2^(b-1) ~ 2^(b-1)-1
  b=8 : -128 ~ 127
  b=16: -32768 ~ 32767

010  = 8   ← 八进制，等于十进制的 8，不是 10！
0x10 = 16
10   = 10
同一个数 255 的三种写法：%d=255   %o=377   %x=ff
```

### 程序三：边界与"绕圈"（附编译器警告）

```c
#include <stdio.h>

int main(void)

    unsigned char u2 = 256;   /* 装不下，绕一圈 */
    unsigned char u3 = 0;

```

**真输出**（`-Wall -Wextra`）：


## 4. 原理：为什么 `0x80` 读成 -128、`0xFF` 读成 -1

**一句话：两种读法只差「最高位的权重」。**

| 读法 | 最高位（第 7 位）的权重 | 其余位 |
|---|---|---|
| 纯二进制（unsigned） | **+2⁷** | 2⁶…2⁰ 照旧 |
| 补码（signed） | **−2⁷** | 2⁶…2⁰ 照旧 |

**逐条验算**：

- `10000000` = **−2⁷** = **−128** ✅
- `11111111` = −128 + (64+32+16+8+4+2+1) = −128 + 127 = **−1** ✅
- `01111111` = 最高位是 0，两种读法完全一样 = **127** ✅

**另一种算法（课件那条）**：`-a` 的补码 = `2ⁿ − a` → `0x80` 表示 `-(256−128) = -128` ✅

**为什么没有「−0」**：补码里 0 只有一种写法（全 0）。`10000000` 若拿去表示 −0 就等于浪费一个位模式，所以把它分给 **−128** —— 于是负数能多表示一个（有 −128、没有 +128），范围成为 **−128 ~ 127**。

**通用公式**：b 位的补码范围 = **−2^(b−1) ~ 2^(b−1) − 1**

## 5. unsigned 真正存在的理由：**移位**

| 运算 | 规则 | 实测（`10000000 >> 1`） | 实测（`11111110 >> 1`） |
|---|---|---|---|
| `signed` 右移 | **算术右移**（左边补符号位） | `-64` | `-2 >> 1 = -1` |
| `unsigned` 右移 | **逻辑右移**（左边补 0） | `64` | `254 >> 1 = 127` |

同一串位，两种移法结果完全不同。
**只要你要把"位"当位看（掩码、CRC、寄存器、加密），就必须用 unsigned** —— 这就是课件那句"初衷是为了移位"的意思，**不是为了表示更大的数**（256 个位模式的总量没变，只是分界线挪了）。

## 7. 四个坑

**坑① `-1 < 1u` 结果是「假」** —— `-1` 会先被转成 `4294967295` 再比较。
> 规矩：**一边是 unsigned，另一边就会被"翻译"成 unsigned。**

**坑② `int a = 010;` 是八进制！** `010` = **8**，不是 10。**0 开头 = 八进制**（实测输出 `010 = 8`）。

**坑③ `printf("%u", 负数)` 是灾难** —— 同一份数据，老实写 `%d` 得 `-1`，错写成 `%u` 得 `4294967295`。

**坑④ `unsigned` 做减法会"绕回去"** —— `unsigned char` 的 `0 - 1` = **255**。
> ⚠️ 循环里写 `for (i = n; i >= 0; i--)`，**如果 `i` 是 unsigned → 死循环**（永远 `>= 0`）。

## 8. 复习题与讲评（2026-10-02）

> [!question]- Q1 `unsigned char x = 200; x = x + 100;` 之后 x 是多少？
> **他答：44** ✅ 完全正确。
> 原理：`unsigned char` 只有 256 个位置（0~255），数轴首尾相接。`200 + 100 = 300`，超出的 `300 - 256 = 44` 绕回来了。
> （对比：如果是 `signed char`，200 本身就已经是负数了 —— 200 在补码里读作 −56。）

> [!question]- Q2 为什么说 unsigned 的初衷是"为了移位"，而不是"为了表示更大的数"？
> **他答：因为计算机里的二进制数字没有变，变得是翻译方式** —— ⚠️ **内容对，但答的是另一问**（那是在解释"补码是读法"）。
> **正确答案**：因为**数的总量并没变** —— 8 位永远只有 256 个位模式。signed 是 −128~127，unsigned 是 0~255，**都是 256 个**，只是把负数那半边挪给了正数。所以它没"扩展范围"。
> 它真正的用处是**移位**：`signed` 右移是算术右移（补符号位）、`unsigned` 右移是逻辑右移（补 0）—— 同一串 `11111110`，`-2>>1 = -1` 而 `254>>1 = 127`。要"把位当位看"就得用 unsigned。

> [!question]- Q3 内存里一个字节是 `0x80`，用 `signed char` 读是多少？用 `unsigned char` 读是多少？
> **他答：-128 和 128** ✅ 完全正确，**并且主动追问了原理**（第 4 节已讲透）。
> 权重法：`10000000` → 纯二进制 = +2⁷ = 128；补码 = −2⁷ = −128。

> [!question]- 加练（另一个会话出的，留着以后自测）
> 1. 8 位二进制 `11111110`，当作补码是多少？当作纯二进制是多少？
> 2. `unsigned char u = 0; u = u - 1;` 之后 `u` 是多少？为什么？
> 3. 为什么做"移位"运算时要用 unsigned，而不是 int？
>
> 答案：
> 1. 补码 → `-2`（`2⁸ − 2 = 254`，所以是 −2）；纯二进制 → `254`。
> 2. `255`。无符号数没有负数，`0 − 1` 会绕到最大值（8 位就是 `2⁸ − 1 = 255`）。
> 3. 有符号右移**左边补符号位**（负数一直补 1），无符号**左边补 0** —— 做掩码/寄存器运算时必须"纯二进制"，不能被符号位污染。
