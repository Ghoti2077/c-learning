# L09 数据类型与布尔类型（顺便解决 `true` 未定义）

- 日期：2026-09-15
- 来源：我自己写的笔记 + 鹏哥数据类型导图 + **我自己程序的报错截图**
- 标签：`#C语言` `#基础语法` `#数据类型` `#布尔` `#报错排查`

> **一句话总结**：C 的内置数据类型分 4 族：**字符型 char、整型（short/int/long/long long）、浮点型（float/double/long double）、布尔型 `_Bool`**。
> 而我程序里 `true` 报未定义的**真正原因不是布尔类型的问题**，而是我**把三个 `#include` 挤在了同一行**——预处理指令必须**一行一条**，挤一起的话后面那些全都不生效。

## 1. ★ 为什么 `true` 显示未定义（三条线索串起来）

### 第一步：先看那条被我忽略的第 1 行报错

`C4067 预处理器指令后有意外标记 - 应输入换行符` 翻译成人话：

> **"`#include` 这条指令我念完了，可这行后面还有别的东西没处理——`#include` 必须独占一整行。"**

**预处理指令（`#include`、`#define` 这类以 `#` 开头的）有个铁规矩：一行只能写一条。**

我那行挤了三条：

```c
#include <stdio.h>      #include <string.h>#include<stdbool.h>
```

编译器的实际处理是：**只认第一条 `#include <stdio.h>`，后面两条被当成"多余的垃圾"直接扔掉（还顺便警告我一句）**。

> 所以我的 `#include <stdbool.h>` **根本没生效**——虽然它字面上写在文件里，编译器压根没理它。

### 第二步：为什么没 include 就认识不了 `true`

**C 语言里 `true` 不是关键字**（在 C23 之前），它只是 `<stdbool.h>` 这个头文件里定义的**一个名字**（实际上 `true` 就是数字 `1`、`false` 就是 `0` 的别名）。

> 打个比方：`true` = "真"这个小名的**花名册**写在 `<stdbool.h>` 里。我没把花名册借来（include 没生效），那编译器看到 `true` 就只能说：**"这人我不认识。"** → `未声明的标识符 "true"`。

编译器自己都提示了（我在 gcc 上实测，原文）：

```
error: 'true' undeclared (first use in this function)
note: 'true' is defined in header '<stdbool.h>'; this is probably fixable by adding '#include <stdbool.h>'
```

**最后那句 note 就是答案**：`true` 定义在 `<stdbool.h>` 里，include 一下就好。

### 第三步：改好之后

**正确写法**（每个 `#include` 单独一行）：

```c
#include <stdio.h>
#include <string.h>
#include <stdbool.h>

int main()
{
    _Bool flag = true;
    if (flag)
        printf("i like C\n");     // 顺便把 /n 改成 \n，见第 3 节

    return 0;
}
```

**实测通过，输出**：

```
i like C
```

### 补充：`_Bool` 和 `bool` 的区别（这个要分清）

| 写法 | 需要 include 吗 | 说明 |
|---|---|---|
| `_Bool flag;` | **不需要** | `_Bool` 是**关键字**，语言自带的 |
| `bool flag;` | **要 `<stdbool.h>`** | `bool` 是头文件里给 `_Bool` 起的小名 |
| `true` / `false` | **要 `<stdbool.h>`** | 头文件里定义的 `1` / `0` 的别名 |
| C23 标准起 | **都不用** | `bool`、`true`、`false` 升级成关键字了，我实测 `gcc -std=c23` 不 include 也能编过 |

⚠️ 但要注意：**VS 默认用的是 C17 之类的老标准**，所以你现在必须老老实实 `#include <stdbool.h>`。

> **记忆法**：`_Bool`（带下划线、大写 B 的）是**原装名字**，丑但哪儿都有；`bool`/`true`/`false` 是**头文件里的化名**，好写，但得先 include 才能用。

## 2. 数据类型全图（我的导图 + 各类型占几字节）

![[L09-数据类型导图.png]]

### 内置类型（语言自带）

| 族 | 类型 | 干啥的 |
|---|---|---|
| **字符型** | `char` | 装一个字符（实际装的是它的编号，见 [[L03 字符与ASCII码]]） |
| **整型** | `short`、`int`、`long`、`long long` | 装整数。`int` 是最常用的 |
| **浮点型** | `float`、`double`、`long double` | 装小数 |
| **布尔型** | `_Bool` | 装"真/假"两个值 |

**整型的省写规则**：`short int`、`long int`、`long long int` 里的 **`int` 可以省略**，直接写 `short`、`long`、`long long`，意思完全一样。

### 自定义类型（自己拼出来的，后面才学）

| 类型 | 关键字 | 干啥的 |
|---|---|---|
| 数组 | `[]` | 一排同类型的格子 |
| 结构体 | `struct` | 把不同类型的数据打包成"一个东西" |
| 枚举 | `enum` | 自己定义一组名字（比如 红/黄/绿） |
| 联合体 | `union` | 几个类型共用一块内存 |

### 它们各占几个字节（我在 gcc 上实测）

| 类型 | 字节数 |
|---|---|
| `char` | **1** |
| `short` | **2** |
| `int` | **4** |
| `long` | **4**（Windows 上；Linux 上通常是 8！） |
| `long long` | **8** |
| `float` | **4** |
| `double` | **8** |
| `long double` | **16**（MinGW 上；MSVC 通常等于 double 的 8） |
| `_Bool` | **1** |

> ⚠️ **别把这些数字当死记硬背的**：`long` 在 Windows 是 4 字节、在 Linux 是 8 字节，`long double` 各编译器也不同。**想知道准确值，写 `sizeof(类型名)` 自己问编译器，永远不吃亏。**

## 3. 顺便纠正：`/n` 不是换行，是"斜杠 n"

我代码里写的是：

```c
printf("i like C/n");     // ❌ 是斜杠 /，不是反斜杠 \
```

**实测打印结果**：

```
i like C/n<- 上一行没换行
```

`\n`（反斜杠）才是换行；`/n`（斜杠）只是两个普通字符，**原样打出来**。

> 🔥 这是**第 2 次**把反斜杠 `\` 写成斜杠 `/` 了（上次是把 `\0` 写成 `/0`）。**这个错在 VS 里不报错，只会安静地打出奇怪的结果**——比报错更麻烦。写 `\` 的时候盯着看：**它是往左倒的**（`\`），**斜杠是往右倒的**（`/`）。

## 6. 嵌入式视角

- **类型 = 占几个字节 = 能装多大的数**。单片机里选类型很讲究：一个计数变量能用 `char`（1 字节）就别用 `int`（4 字节）——**RAM 只有几 KB 的时候，每个字节都金贵**。
- **`long` 在不同平台上字节数不同**，所以嵌入式代码里更爱用 `stdint.h` 里的 `uint8_t`、`uint16_t`、`uint32_t`——**名字里就写明了位数**，换平台不会翻车（这个以后必学，先记个印象）。
- **布尔量在单片机里就是"标志位"**：`_Bool led_on = 1;` 这种标志到处都是（按键是否按下、串口是否收到数据）。而且**"0 是假、非零是真"这条在寄存器判断里天天用**：`if (REG & 0x01)` 意思是"如果这一位是 1"。
- 顺带：`sizeof` 是嵌入式面试的高频题（"int 几个字节？long 呢？"）——**答"看平台，用 sizeof 最准"**，比硬背一个数字更专业。

### 补一课：`void`（空类型）到底是什么

**四族内置类型是**：**字符型 `char`**、**整型**（`short`/`int`/`long`/`long long`）、**浮点型**（`float`/`double`/`long double`）、**布尔型**（`_Bool`）。（你发的导图上就是这四条，`char` 在最上面）

那 `void` 是什么？**它是"空类型"，专门用来表示"没有"**——它**不是拿来装数据的**，别把它当成第五族：

| `void` 用在哪 | 意思 |
|---|---|
| `void say_hi(void)` 前面 | **这个函数不返回任何值** |
| `(void)` 参数里 | **这个函数不需要任何参数** |
| `void *p` | 万能指针（学到指针再讲） |

**实测一个 void 函数**（能正常跑）：

```c
void say_hi(void)          // 不返回东西、也不要参数
{
    printf("hi，我不返回东西\n");
}

int main()
{
    say_hi();              // 只能这么叫，不能写 x = say_hi();
    return 0;
}
```

输出：`hi，我不返回东西` ✔

**区分口诀**：
> 我们前面写的 `int main()` 是**"main 干完活交回一个整数"**（所以要有 `return 0;`）；
> 换成 `void main_xxx()` 就是**"干完就完，什么都不交"**（不需要 `return`）。
> **`void` 是"没有"的意思，`char`/`int`/`float`/`_Bool` 才是"有东西可装"。**

**顺带一个有意思的实验**（`sizeof(void)` 到底等于几）：

| 编译器 | 结果 |
|---|---|
| gcc 默认 | 打印 `void 占 1 字节`（**这是 GCC 的扩展**，不是标准行为） |
| gcc 严格标准模式 | `error: invalid application of 'sizeof' to a void type`（**标准里不允许**） |

> 所以答案是：**标准 C 里 `sizeof(void)` 是非法的**（你不能量"什么都没有"的大小）。GCC 平时容你、给个 1；你在 **VS 里试一下**，大概率直接报错——这正好是个"同一段代码不同编译器反应不同"的实例。**这也是嵌入式里为什么强调"要按标准写代码"**（换编译器就露馅）。
