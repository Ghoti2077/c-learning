# L12 复合赋值、递增递减、前缀与后缀

- 日期：2026-09-17
- 来源：鹏哥课件 3 张（复合赋值 / 递增递减 / 前缀后缀）+ 我自己的 VS 实测截图
- 标签：`#C语言` `#基础语法` `#运算符` `#自增自减`

> **一句话总结**：`+=` `-=` `*=` `/=` `%=` 是"简写"；`++` `--` 是**单目运算符**（只能作用在**变量**上）。
> 最要紧的一条：**`a++` 的值是"加之前"的老值，`++a` 的值是"加之后"的新值——但不管哪种，`a` 自己都会 +1**。**"表达式的值"和"变量本身"是两件事，千万分开看。**

## 1. 复合赋值运算符（5 个）

![[L12-复合赋值课件.png]]

| 简写 | 等价于 | 意思 |
|---|---|---|
| `total += 5;` | `total = total + 5;` | 加完再存回去 |
| `total -= 5;` | `total = total - 5;` | 减 |
| `total *= 5;` | `total = total * 5;` | 乘 |
| `total /= 5;` | `total = total / 5;` | 除 |
| `total %= 5;` | `total = total % 5;` | 取余 |

**实测**（`total = 10` 开始）：

```
total += 5 之后: 15
total *= 2 之后: 30
total %= 7 之后: 2
```

**⚠️ 课件重点提醒：两个运算符中间不要有空格！**

```c
total += 5;    // ✅ 对
total + = 5;   // ❌ 编译器报错
```

**实测报错原文**：

```
error: expected expression before '=' token
```

> 人话：**"`+=` 是一个整体符号，中间敲了空格，编译器就只看到 `+` 和 `=` 两个不认识的东西了。"**
> 记住：`+=` 是**一个**运算符，不是 `+` 加 `=`。

## 2. `++` 和 `--`：两个特殊角色

![[L12-递增递减课件.png]]

课件原话要点：

- 它们是**单目运算符**（只有一个操作数）
- **算子（操作数）必须是变量**
- 作用：给变量 **+1 / -1**

**为什么"必须是变量"？** 实测一下就知道：

```c
int a = 5;
(a + 1)++;      // ❌ 行不行？
```

**编译器原话**：

```
error: lvalue required as increment operand
```

翻译：**"自增需要一个能装东西的『格子』（lvalue），你给我个算式 `a+1`，它只是个临时算出来的值，没地方存 +1 的结果。"**

> 比方：`++` 是"把这个盒子里的东西换掉"。**`a` 是盒子（能换）**；**`a+1` 是算出来的一个临时结果（没盒子，换不了）**。

## 3. ⭐ 前缀 vs 后缀（本课最核心）

![[L12-前缀后缀课件.png]]

**课件那句话说得很准**：

> `a++` 的值是 a 加 1 **以前**的值；`++a` 的值是加了 1 **以后**的值。**无论哪个，a 自己的值都加了 1。**

**关键是分清两件事**（这是全部困惑的来源）：

| | ① 这个**表达式**的值 | ② **变量 a 自己**的值 |
|---|---|---|
| `a++` | **老值**（加之前的） | 加 1 |
| `++a` | **新值**（加之后的） | 加 1 |

**我 VS 里的实测**（`a = 10;`）：

![[L12-VS实测自增自减.png]]

```c
int a;
a = 10;
printf("a++=%d\n", a++);   // a++=10
printf("a=%d\n", a);       // a=11
printf("++a=%d\n", ++a);   // ++a=12
printf("a=%d\n", a);       // a=12
```

**我用 gcc 又跑了一遍，输出一模一样** ✔

### 逐行解释（当傻子版）

| 行 | a 现在的值 | 打印出来的 | 为什么 |
|---|---|---|---|
| `a = 10;` | 10 | — | 先给 a 装 10 |
| `printf("a++=%d\n", a++);` | 10 → **11** | **10** | `a++` **先把老值 10 交出去**给 printf，然后 a 自己变成 11 |
| `printf("a=%d\n", a);` | 11 | **11** | 上一步 a 已经变 11 了 |
| `printf("++a=%d\n", ++a);` | 11 → **12** | **12** | `++a` **先让 a 变成 12**，再把新值 12 交出去 |
| `printf("a=%d\n", a);` | 12 | **12** | a 就是 12 |

**记忆法**（课件的口诀）：

- **后缀 `a++`**：**先用后加** —— 先拿老值去用，用完自己偷偷 +1
- **前缀 `++a`**：**先加后用** —— 先把自己 +1，再拿新值去用

> 比方：**`a++` 是先付钱后拿货的"记账"**（钱先按老价付，账本后面才改）；
> **`++a` 是先加价再卖的"现价"**（先改标签，再按新价卖）。

## 4. 前缀后缀对照表（课件那张表，原图有弹幕遮挡，我转成干净的）

| 表达式 | 运算 | 表达式的值 |
|---|---|---|
| `count++` | 给 count 加 1 | **count 原来的值** |
| `++count` | 给 count 加 1 | **count + 1 以后的值** |
| `count--` | 给 count 减 1 | **count 原来的值** |
| `--count` | 给 count 减 1 | **count - 1 以后的值** |

> 规律一眼看穿：**符号在后面 → 表达式的值是老值；符号在前面 → 表达式的值是新值。**
> 但**四行的"运算"列都是"给 count 加/减 1"**——这就是"变量自己总会变"的意思。

## 5. ⚠️ 顺便说个坑：一句话里自增两次 = 未定义行为

那张表的原图上有一条**别人发的弹幕**说"答案应该是 2 1 1"（你说了那是弹幕，忽略它）。**忽略是对的，而且理由很硬**：

我实测了这种题：

```c
int a = 2;
printf("%d %d %d\n", a++, ++a, a);   // 同一个 a，一句里自增两次
```

**gcc 的实测结果和最关键的警告**：

```
3 4 4
warning: operation on 'a' may be undefined [-Wsequence-point]
```

**"may be undefined" = 未定义行为（UB）**：C 标准**没规定**这种写法应该算出什么，**每个编译器可以给出不同答案**（我这台给 3 4 4，你的 VS 可能是别的）。

> 结论：**`a++ + ++a`、`printf("%d %d", a++, ++a)` 这类写法，答案没有意义——考试可能会考，实际写代码绝对要避免。**
> 弹幕里的"2 1 1"就是这种"没有标准答案"的东西，不用记。**记住这条规则比记答案有用：一句话里，同一个变量只自增一次。**

2. `++` 能用在 `(a + 1)` 上面吗？为什么？
3. 下面打印什么？**按顺序写出每一行**

   ```c
   int a = 5;

   ```
4. 用一句话说清 `a++` 和 `++a` 的区别。（提示：分开说"表达式的值"和"变量本身"）

> [!question]- 参考答案（先自己答完再点开）
>
> 1. **不能加空格**。`total + = 5;` 报 `expected expression before '=' token`——`+=` 是**一个**运算符，中间断开编译器就不认识了。
> 2. **不能**。`(a + 1)` 是算出来的临时值，不是变量（不是 lvalue）。报错 `lvalue required as increment operand`——自增需要一个"能装东西的格子"。
> 3. 逐个看：
>    - `printf("%d\n", a++);` → 先交出老值 **5**（然后 a 变 6）
>    - `printf("%d\n", ++a);` → 先把 a 变 **7**，再交出 **7**
>    - `printf("%d\n", a);` → **7**
>    → 输出 **5、7、7**
> 4. `a++`（后缀）：**先用后加**——表达式的值是**老值**；`++a`（前缀）：**先加后用**——表达式的值是**新值**。**两种写法里 a 自己都 +1。**
> 5. **不好，绝对别写。** 同一句话里对同一个变量自增两次属于**未定义行为**（gcc 警告 `operation on 'a' may be undefined`），不同编译器结果可能不同。**一个表达式里，同一个变量只自增一次。**

## 8. 嵌入式视角

- **`++` 在嵌入式里到处都是**：循环计数 `for (i = 0; i < N; i++)`、扫描按键、遍历缓冲区、延时循环——**它是你用次数最多的运算符之一**。
- **`+=` 是配置寄存器的常用写法**：`GPIOA->ODR |= (1 << 5);` 就是复合赋值的亲戚（`|=` 是按位或赋值），以后点灯第一行就是它。
- **`i++` 和 `++i` 在 C 里效率一样**（编译器都优化），但在 **C++ 里 `++i` 更快**——所以老工程师习惯写 `++i`。你现在写哪个都行，看到别慌。
- **别在一条语句里塞两个 `++`**——嵌入式调试本来就难，写这种"未定义行为"会让 bug 变成玄学（改一下优化等级结果就变了，那种问题查一星期都查不出来）。

### 第 3 题错在哪：三行是"接力"，不是各自独立

**题目**：

```c
int a = 5;
printf("%d\n", a++);
printf("%d\n", ++a);
printf("%d\n", a);
```

**实测输出**（我跑的原始结果）：

```
5
7
7
```

**逐行走一遍**（重点看"执行前 a 是多少"这一列）：

| 行 | 执行**前** a 是多少 | 发生了什么 | 打印 |
|---|---|---|---|
| `printf("%d\n", a++);` | **5** | 交出老值 5，**a 变成 6** | `5` |
| `printf("%d\n", ++a);` | **6** ← 不是 5！ | a 先变成 **7**，再把 7 交出去 | `7` |
| `printf("%d\n", a);` | 7 | 直接交出去 | `7` |

**我错在哪**：第二行我按 a 还是 5 去算，所以觉得 `++a` 是 6。**但第 1 行的 `a++` 已经把 a 从 5 改成了 6，第二行的起点是 6，不是 5。**

> 比方：**这三行是接力赛，不是三次独立考试。**
> `a` 是一个**一直在变的接力棒**：第一棒把它从 5 交成 6，第二棒就**必须从 6 出发**（→7），不能每次都回到起点。
>
> **一句话**：算这种连续题，**每一行结束后都要问自己"现在 a 是几？"**，把这个数写在旁边再往下算。
