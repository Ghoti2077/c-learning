# L22 PAT 成绩转换：十位数法 + switch 穿透

- 日期：2026-09-21
- 来源：翁恺《C语言程序设计》视频里的**习题**（Programming Ability Test「分支-06. 成绩转换(15)」）+ 我写的两个版本
- 素材：PAT 题目截图、我的 if-else 版、我的 switch 版
- 标签：`#C语言` `#基础语法` `#分支` `#switch` `#刷题` `#PAT`

> **一句话总结**：
> 老师那句"**用分数的十位数来判断**"就是把**区间判断**变成**等值判断**：`grade / 10` 之后
> 90~99 全是 9、80~89 全是 8……于是能用 `switch` 写，还能用**穿透**让 `case 10` 和 `case 9` 共用一句 `printf("A\n")`。
> **算法对了，但两个细节错了**：① 小于 60 应该输出 **E**，我写成了 **F**；② 我把 `printf("输入成绩:");` 留在了程序里 → **交到 OJ 上直接 WA**。

## 1. 题目（PAT 分支-06 成绩转换）

![[L22-PAT 题目截图.png]]

| 分数段 | 输出 |
|---|---|
| ≥ 90 | A |
| 90 > 分数 ≥ 80 | B |
| 80 > 分数 ≥ 70 | C |
| 70 > 分数 ≥ 60 | D |
| < 60 | **E** |

**输入**：一行给 1 个整数（百分制成绩）。**输出**：一行输出**对应的五分制字母**。
样例：输入 `90` → 输出 `A`。

**老师给的思路**（视频字幕原文）：**"其实我们可以用分数的十位数来判断我该说出什么。"**

## 2. 老师那句话翻译成代码

十位数 = **整数除法** `grade / 10`（整数除法**直接丢掉小数**）。我实测了一遍：

| 分数 | `score / 10` |
|---|---|
| 100 | **10** |
| 90 | **9** |
| 89 | **8** |
| 60 | **6** |
| 59 | **5** |
| 0 | 0 |
| -1 / -5 | 0（C 的整数除法**向零截断**） |

**看懂这张表就懂了**：判断"90~99"这种**区间**，只要判断"`grade/10` 是不是 **9**"这种**等值** —— 而**等值判断正是 `switch` 的主场**。

## 3. 我的 switch 版（老师思路）

![[L22-我的 switch 版（十位数法）.png]]

```c
int main() {
    printf("输入成绩:");           /* ← 问题②：这句不该留 */
    int grade;
    scanf("%d", &grade);
    grade /= 10;                   /* 取十位数 */
    switch (grade) {
    case 10:
    case 9:                        /* ← 故意穿透：100 分和 90 分都是 A */
        printf("A\n");
        break;
    case 8:
        printf("B\n");
        break;
    case 7:
        printf("C\n");
        break;
    case 6:
        printf("D\n");
        break;
    default:
        printf("F\n");             /* ← 问题①：题目要求 <60 输出 E */
        break;
    }
    return 0;
}
```

### 逐句核对

| 检查点 | 判定 |
|---|---|
| 用 `grade / 10` 把区间判断变成等值判断 | ✅ **思路对**（老师说的就是这个） |
| `case 10:` + `case 9:` **故意穿透**共用 `printf("A\n")` | ✅ **用得漂亮**——100 分和 90~99 都落在 A |
| 每个 `case` 后面都有 `break` | ✅ 一个都没漏（`default` 也有） |
| `printf` 全部带 `\n` | ✅ **这次记得了** 👍 |
| 小于 60 的分支输出 | ❌ **写成了 `F`，题目要求是 `E`** |
| 开头那句 `printf("输入成绩:");` | ❌ **交 OJ 会 WA**（见第 5 节） |
| `int grade;` 写在 `printf` 之后 | ✅ 合法（C99 起允许变量定义写在语句后面），但习惯上把变量声明放最前面更清爽 |

### AI 穷举验证：0~120 分全跑一遍

我把这段逻辑抽成函数，**0 到 120 分每个分数都跑一遍**，跟题目要求逐一对表：

```
0~120 全跑一遍：不一致 71 处
```

**71 处全部是同一个问题**：0~59 分我输出 `F`，题目要 `E`。

```
分数 | 他的程序 | 题目要求
   0 |     F    |    E
   1 |     F    |    E
 ...
```

**逻辑结构全对，只有"最后那个字母"写错了** —— 而这种错，编译器、VS、我肉眼都看不出来，**只有拿题目要求去对才会露馅**。

## 4. 我之前的 if-else 版（同一道题）

![[L22-我的 if-else 版（成绩等级）.png]]

```c
int main() {
    int score;
    scanf("%d", &score);
    if (score >= 90)
        printf("成绩为A");
    else if (score >= 80)
        printf("成绩为B");
    else if(score >= 70)
        printf("成绩为C");
    else if (score >= 60)
        printf("成绩为D");
    else if(score<60)              /* ← ①多余的条件 */
        printf("成绩为E");
    return 0;
}
```

| 检查点 | 判定 |
|---|---|
| 五个分数段判断 | ✅ 逻辑正确（我实测 90 分 → `成绩为A`） |
| **最后那个 `else if (score < 60)`** | ⚠️ **多余**：前面已经把 ≥60 的情况全部拦掉了，剩下的**必然是 <60**，直接写 `else` 就行（少打一串字，还不会漏） |
| 输出带中文前缀 `成绩为A` | ❌ 题目要求**只输出字母 `A`** → 交 OJ 也是 WA |
| `printf` 没有 `\n` | ⚠️ （这段是之前写的，本次 switch 版已经记得加了） |

> 两个版本对比一下就能看出 **switch 版的好处**：结构更整齐，一眼看出"A 覆盖 10 和 9"。但**两个版本都犯了同一个错——没按题目要求输出**。

## 5. ⚠️ 交 OJ（在线评测）的铁律：输出必须**逐字符**一样

我实测了自己那版程序（带提示语）的输出：

| 输入 | 我的程序实际输出 | 题目要求 |
|---|---|---|
| 90 | `输入成绩:A` | `A` |
| 100 | `输入成绩:A` | `A` |
| 85 | `输入成绩:B` | `B` |
| 59 | `输入成绩:F` | `E` |

**OJ 是拿"标准答案"和你的输出一个字符一个字符比的**：

- 多打一个 `输入成绩:` → **WA**（答案错误），而且它不会告诉你"是因为多了提示语"，只会冷冰冰一个 WA；
- 少打一个 `\n` 通常不影响（评测会忽略行尾空白），但**多打了字、少打了字、字母错了**，一律 WA；
- 所以：**自己测试时加提示语没问题，提交前必须删掉**。

**提交前的三条自查**（我也要养成习惯）：

1. **输出里有没有多余的文字**（提示语、单位、"答案是"等在 OJ 上都是错的）；
2. **输出内容/字母和题目要求逐字对过没有**（我这次把 E 写成了 F）；
3. 结果对不对**用穷举/边界测**（0 分、59、60、90、100 都试一遍），别只看样例那一个。

## 6. 复习题（先自己答）

1. `grade / 10` 为什么能把"90~99 分"变成"判断等于 9"？100 分变成几？
2. `case 10:` 后面什么都不写、直接接 `case 9:`，这样做有什么好处？这里为什么不加 `break`？
3. 我最后那个 `default` 输出 `F` 有什么问题？怎么发现的？
4. 为什么自己测试时加的 `printf("输入成绩:");` 交到 OJ 上会 WA？

> [!question]- 参考答案（先自己答完再点开）
>
> 1. 因为整除**丢掉小数**：90~99 除以 10 都是 **9**、80~89 都是 **8**……于是"区间"变成"等值"；**100 / 10 = 10**（所以要多写 `case 10:`）。
> 2. 好处是**让 10 和 9 两个值共用同一段代码**（都输出 A），少写一遍。这里不加 `break` **正是因为要穿透**——加在 `case 10:` 后面就穿不到 `case 9` 了。
> 3. 题目要求 **<60 输出 `E`**，我写成了 `F`。发现方式：**把程序在 0~120 分上全部跑一遍、跟题目要求逐项对照**（穷举），结果 71 处不一致全在这。
> 4. 因为 OJ 把"标准输出"和"你的输出"**逐字符比对**，多打的 `输入成绩:` 就是多余内容 → 直接判 **WA**。自己测试看着舒服，提交前必须删。

## 7. 嵌入式视角

- **"十位数法"就是嵌入式里的"分档"思想**：ADC 采回来的电压值要分成"低电量/正常/偏高"几档、温度要分几段报警 —— 把**连续值先做一次整数除法/移位，变成有限的几档**，再用 `switch` 处理，代码又短又清楚（和 `grade / 10` 一模一样的手法）。
- **"输出格式必须逐字符对"在嵌入式里等于通信协议**：单片机和上位机/模块之间，多一个字节、少一个换行，对方就解析不了 —— OJ 那种"一个字符都不能错"的严格性，正是协议开发每天都在面对的事。
- **穷举 + 边界测试是好习惯**：这次靠"0~120 全跑"才揪出 F/E。嵌入式里同理——**边界值（0、满量程、负数）必须专门测**，正常值往往都是对的。
