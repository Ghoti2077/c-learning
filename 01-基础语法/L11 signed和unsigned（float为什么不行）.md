# L11 signed 和 unsigned（以及 float 为什么不能加 unsigned）

- 日期：2026-09-16
- 来源：我自己写的笔记 + 课件（signed/unsigned、limits.h、char 三种写法）+ 我提的问题
- 标签：`#C语言` `#基础语法` `#signed` `#unsigned` `#char`

> **一句话总结**：`signed` / `unsigned` 是**正负号开关**，但**只能开在"字符型 + 整型"身上**——`char`、`short`、`int`、`long`、`long long` 都有两种版本；**`float`、`double`、`long double` 没有**（写 `unsigned float` 直接报错，因为浮点数天生就带正负号）。
> 另外 `char` 到底有没有符号，**是编译器说了算**——这是个隐藏大坑。

## 1. signed / unsigned 是什么

![[L11-signed和unsigned课件.png]]

| 关键字 | 意思 | 能装什么 |
|---|---|---|
| `signed` | **有正负号** | 负数 + 0 + 正数 |
| `unsigned` | **无正负号** | 只有 0 + 正数 |

**同样的字节数，装的东西不一样**：

| 类型（16 位为例） | 范围 | 说明 |
|---|---|---|
| `signed short` | **-32768 ~ 32767** | 一半正一半负 |
| `unsigned short` | **0 ~ 65535** | 全给正数用，**最大值变大了一倍** |

**实测**：

```
USHRT_MAX = 65535,  SHRT_MAX = 32767
UINT_MAX  = 4294967295,  INT_MAX = 2147483647
```

> ⚠️ 小提醒：别理解成"unsigned 能装的数变多了"。**值的总数没变**（16 位还是 65536 种），只是把原本分给负数的那一半**搬给正数**了。

## 2. ★ 我的问题：`float` 和 `long` 能不能加 signed/unsigned？

**答案：`long` 能，`float` 不能。** 口诀：

> **`signed`/`unsigned` 只认"整数家族"（字符型 + 整型），不认"浮点家族"。**

| 类型 | 有 signed/unsigned 版本吗？ | 写法 |
|---|---|---|
| `char` | ✅ 有 | `signed char` / `unsigned char` |
| `short` | ✅ 有 | `signed short` / `unsigned short` |
| `int` | ✅ 有 | `signed int` / `unsigned int` |
| `long` | ✅ **有** | `signed long` / `unsigned long` |
| `long long` | ✅ **有** | `signed long long` / `unsigned long long` |
| **`float`** | ❌ **没有** | — |
| **`double`** | ❌ **没有** | — |
| **`long double`** | ❌ **没有** | — |

**实测证据**：写 `unsigned float f = 1.5f;` 编译器当场拒绝：

```
error: both 'unsigned' and 'float' in declaration specifiers
```

翻译人话：**"`unsigned` 和 `float` 不能同时出现。"**

**为什么浮点型没有 unsigned？** 因为**浮点数天生就带正负号**——它内部有一块专门存符号（就像科学计数法里的 ± 号），所以不需要你声明"有没有符号"。而整数是"纯数字"，符号是**解释方式**的问题，才需要你选。

> 比方：
> **整数**像一排格子，`signed`/`unsigned` 决定"最高位那一格是当数字用还是当正负号用"；
> **浮点数**长得完全不一样（小数部分 + 指数部分 + 符号位），**符号位它自带**，你想拆都拆不掉。

**`long`/`long long` 实测都能编过**：

```
signed long long = -1
unsigned long    = 1
signed short     = -1
unsigned short   = 1
```

## 3. `unsigned` 里硬塞负数会怎样（实测）

```c
unsigned int u = -1;
printf("%u\n", u);
```

**实测输出**：

```
unsigned int 里塞 -1  -> 显示成 4294967295
```

**它不报错！** 而是把 -1 "绕"成了 4294967295（也就是 `UINT_MAX`）。因为无符号数是"环形"的：0 往下一格不是 -1，而是**绕到最后面**（最大值）。

> ⚠️ 所以"unsigned 不得存负数"的准确含义是：**你硬塞它也不拦你，但结果不是你想要的**。而且如果 `printf` 用了错的格式符（`%d` 打 unsigned），显示还会更乱。

## 4. ★ 隐藏大坑：`char` 到底有没有符号，是编译器说了算

![[L11-char三种写法与类型清单.png]]

课件里列得清楚：`char` 有三种写法——

```c
char            // 到底是正是负？【看编译器】
signed char      // 明确：有符号
unsigned char    // 明确：无符号
```

**我做了个实验：同一份代码，只改编译选项，结果完全不同**：

```c
char c = -1;
if (c < 0)
    printf("char 是有符号的\n");
else
    printf("char 是无符号的，c 变成了 %d\n", c);
```

| 编译方式 | 实测输出 |
|---|---|
| 默认（我的编译器） | `char 是【有符号】的：c = -1 被当成负数，c < 0 成立` |
| 加 `-funsigned-char` | `char 是【无符号】的：c = -1 变成了 255，c < 0 不成立` |

**同一段代码、同一个编译器，加个选项结果就反了。** 这就是我笔记里说的"`char` 可能是 signed 也可能是 unsigned"的真正含义。

📌 **嵌入式提醒**（你以后一定会遇到）：**在 ARM 平台（单片机）上，GCC 默认把 `char` 当无符号**。所以同一份代码在电脑上跑得好好的，烧到板子上就出问题。
（这条我这边没有 ARM 工具链，**没法实测**，你以后上单片机时**亲手验证一下**，记进笔记。）

**所以写代码的规矩**：

> **只要一个字节的值可能超过 127、或者可能为负，就别写 `char`，明明白白写 `signed char` 或 `unsigned char`。**
> 特别是以后做串口通信、读传感器字节时——**用 `unsigned char`/`uint8_t` 最稳**。

## 5. `limits.h` 里的范围（课件图 + 实测）

![[L11-limits.h定义.png]]

课件里贴的 VS2022 的 `limits.h` 定义：

```c
#define SHRT_MIN  (-32768)          // 有符号 16 位整型的最小值
#define SHRT_MAX  32767             // 有符号 16 位整型的最大值
#define USHRT_MAX 0xffff            // 无符号 16 位整型的最大值（0xffff = 65535）
#define INT_MIN   (-2147483647 - 1) // 有符号整型的最小值
#define INT_MAX   2147483647        // 有符号整型的最大值
```

**实测对得上**：

```
USHRT_MAX = 65535,  SHRT_MAX = 32767
UINT_MAX  = 4294967295,  INT_MAX = 2147483647
```

**一个小细节（有意思）**：`INT_MIN` 为什么写成 `(-2147483647 - 1)` 而不直接写 `-2147483648`？

> 因为在 C 里 `2147483648` 这个数**已经超过 int 能表示的最大值**（2147483647）了，编译器会把它当成更大的类型看待。所以标准库绕个弯：**先写能表示的最大值，再减 1**，这样结果一定落在 int 里。
> （现在只要知道"有这么个讲究"，不用记。）

1. `unsigned float f;` 这么写行不行？为什么？
2. `long` 有没有 `unsigned` 版本？`double` 呢？
3. `unsigned short` 能表示的范围是多少？（有符号 `short` 是 -32768~32767）
4. 同一份代码里写 `char c = -1;`，为什么换个平台结果可能不一样？该怎么办？
5. `unsigned int u = -1;` 之后，`u` 显示成多少？

> [!question]- 参考答案（先自己答完再点开）
>
> 1. **不行**，报 `both 'unsigned' and 'float' in declaration specifiers`。因为 `signed`/`unsigned` 只能修饰**字符型和整型**；浮点数**天生自带正负号**，不需要也不能加。
> 2. **`long` 有**（`unsigned long`、`unsigned long long`）；**`double` 没有**（浮点家族都没有）。
> 3. **0 ~ 65535**。无符号把原本分给负数的那一半也拿来装正数，所以最大值翻倍（32767 → 65535）。
> 4. 因为 **`char` 有没有符号是"实现（编译器/平台）定义"的**——同一份代码，编译器默认和加 `-funsigned-char` 结果就不同；ARM 上 GCC 默认还是**无符号**。**办法：别裸写 `char`，明确写 `signed char` / `unsigned char`（或 `uint8_t`）。**
> 5. **4294967295**（也就是 `UINT_MAX`）。它不报错，而是"绕一圈"绕到最大值上去了。

## 8. 嵌入式视角

- **`unsigned char` / `uint8_t` 是嵌入式里最常用的"字节"类型**：串口收发、I2C/SPI 读寄存器、处理传感器原始数据，全是它。因为**数据是按字节来的，没有正负概念**。
- **`char` 的符号性跨平台不一致，在嵌入式里是真实事故来源**：PC 上（有符号 char）跑得好好的判断，烧到 ARM（默认无符号 char）就反了。**所以嵌入式代码里几乎看不到裸 `char`**。
- **`unsigned` 用在位运算上更合适**：以后移位 `<<`、位与 `&` 操作用无符号类型，能避开"符号位被带进来"的坑（学到位运算会重点讲，那是嵌入式的核心）。
- **范围就是命**：`unsigned short` 最大 65535，超过就绕回去（比如计时器溢出）——单片机里"计数器溢出"是常见 bug，也是常见特性（定时器就这么用的）。
