# L33 补码与数的范围（unsigned 后缀、右移补 0）

> 这一课是 **L28（int 上限与溢出）时欠下的"补码"** 的正式补课，也是 **L11 signed/unsigned** 的深化。
> 课件对应：*补码 / 数的范围 / 整数的范围 / unsigned* 四张幻灯片。

---

## 1. 先判他的原话

> 「unsigned 不以补码来表示，排除了负数」

| 说法 | 判定 | 精确表述 |
|---|---|---|
| 不以补码来表示 | ✅ 对 | **补码只是"有符号整数的编码规则"**，unsigned 根本不参与这套规则 |
| 排除了负数 | ✅ 对 | 8 位 unsigned 范围是 **0 ~ 255**，没有负数 |

**要补的关键一句**：**位数和二进制串是同一个，区别只在"怎么解读"。**

```
11111111
  ├─ 当补码解读（有符号）  → -1
  └─ 当纯二进制解读（无符号）→ 255
```

→ unsigned **不是换了一套表示法，而是"取消了符号位的解读"**（课件原话："被当作纯二进制看待时，是 255"）。

---

## 2. 打比方：同一串灯，两种读法

8 盏灯的开关状态是**同一串** `11111111`，两种读法：

- **补码读法（有符号）**：第 1 盏灯是"正负牌"（亮 = 负），剩下 7 盏按"**从 0 往回数**"算 → `-1`
- **纯二进制读法（无符号）**：**没有正负牌**，8 盏全算命 → `255`

**灯一个都没变，只是读法变了。**

---

## 3. 补码是什么（课件那条推导链）

想要 `-1 + 1 → 0`，怎么做？

```
    0  -> 00000000
  -1  = ?
  因为 0 - 1 -> -1，所以：
    (1)00000000 - 00000001 -> 11111111
  验证：11111111 + 00000001 -> 1 00000000  ← 溢出的那个"1"丢掉，结果正好是 0 ✅
```

**结论**：`-1` 就是 `11111111`。补码的意义 = **拿补码和原码相加，能加出一个溢出的"零"**。

推广公式（课件最后一条）：**对于 `-a`，它的补码是 `0 - a`，实际就是 `2^n - a`，n 是这种类型的位数。**

- 8 位：`-1 = 2^8 - 1 = 256 - 1 = 255 = 11111111` ✅
- 8 位：`-128 = 2^8 - 128 = 128 = 10000000` ✅

---

## 4. 数的范围（8 位 / 1 字节）

```
00000000                     -> 0
00000001 ~ 01111111          -> 1 ~ 127
10000000 ~ 11111111          -> -128 ~ -1        （负数：值越大，二进制越小）
```

- **有符号 char**：`-128 ~ 127`
- **无符号 char**：`0 ~ 255`

各种类型范围（本机实测 `int`/`long` 都是 4 字节，见 [[L10 sizeof（关键字、操作符、字节与比特）]]）：

| 类型 | 字节 | 范围 |
|---|---|---|
| `char` | 1 | -128 ~ 127 |
| `unsigned char` | 1 | 0 ~ 255 |
| `short` | 2 | -32768 ~ 32767 |
| `int` | 4（本机） | -21亿 ~ 21亿（见 [[L28 int的上限与溢出（为什么变负数）]]） |
| `long` | 4（Windows） / 8（Linux） | — |
| `long long` | 8 | 约 ±9.2×10^18 |

---

## 5. unsigned 的真正用途（**不是**扩大范围）

课件原话：

> **unsigned 的初衷并非扩展数能表达的范围，而是为了做纯二进制运算，主要是为了移位。**

**因为右移时两者行为不同**（实测）：

| 值 `10000000` 右移 1 位 | 结果 | 左边补什么 |
|---|---|---|
| **无符号** | `64`（`01000000`） | **补 0** |
| **有符号** | `-64`（`11000000`） | **补符号位 1**（保持负数身份） |

→ 做**位运算、掩码、寄存器操作**时，必须用 unsigned，否则符号位会"污染"结果。

---

## 6. 字面量后缀

| 后缀 | 含义 | 例子 |
|---|---|---|
| `u` / `U` | unsigned | `255U` |
| `l` / `L` | long | `255L` |
| `ll` / `LL` | long long | `255LL` |
| `ul` / `ULL` | 组合 | `255UL` |

---

## 7. 实测（源码 + 输出原样）

源码：

```c
#include <stdio.h>

int main(void)
{
    /* ---- ① 同一个 255，两种类型 ---- */
    char c = 255;             /* 有符号 char */
    unsigned char u = 255;    /* 无符号 char */
    int  i = 255;

    printf("char c = 255        -> c = %d\n", c);
    printf("unsigned char u=255 -> u = %u\n", u);
    printf("int i = 255         -> i = %d\n", i);

    /* ---- ② 同一个二进制串 11111111，两种解读 ---- */
    unsigned char bits = 0xFF;
    printf("\n0xFF 当无符号解读 = %u\n", bits);
    printf("0xFF 当有符号解读 = %d\n", (int)(signed char)bits);

    /* ---- ③ 移位：这才是 unsigned 存在的真正理由 ---- */
    unsigned char a = 0x80;                 /* 1000 0000 */
    signed char   b = (signed char)0x80;    /* 也是 1000 0000 */

    printf("\n无符号 10000000 >> 1 = %u  （左边补 0）\n", (unsigned)(a >> 1));
    printf("有符号 10000000 >> 1 = %d （左边补符号位 1）\n", (int)(b >> 1));

    /* ---- ④ 无符号 char 的边界 ---- */
    unsigned char u2 = 256;   /* 装不下，绕一圈 */
    unsigned char u3 = 0;
    u3 = u3 - 1;              /* 0 - 1 */

    printf("\nunsigned char 装 256 -> %u\n", u2);
    printf("unsigned char 0 - 1  -> %u\n", u3);

    /* ---- ⑤ 字面量后缀 U ---- */
    printf("\n255U 的输出（用 %%u）= %u\n", 255U);

    return 0;
}
```

编译（MSYS2 UCRT64，gcc 16.2，`-Wall -Wextra`）输出：

```
unsigned_demo.c:27:24: warning: unsigned conversion from 'int' to 'unsigned char'
                       changes value from '256' to '0' [-Woverflow]

char c = 255        -> c = -1
unsigned char u=255 -> u = 255
int i = 255         -> i = 255

0xFF 当无符号解读 = 255
0xFF 当有符号解读 = -1

无符号 10000000 >> 1 = 64  （左边补 0）
有符号 10000000 >> 1 = -64 （左边补符号位 1）

unsigned char 装 256 -> 0
unsigned char 0 - 1  -> 255

255U 的输出（用 %u）= 255
```

**注意编译器那句警告**：`changes value from '256' to '0'` —— **编译器自己就告诉你"装不下"了**，这种警告别忽略。

---

## 8. 三个坑

1. **`char c = 255;` 然后 `printf("%d", c)` 打出 `-1`** —— 不是编译器坏了，是 255 装进有符号 char 后按补码解读。
2. **`printf("%u", ...)` 配上有符号数是灾难**（实测，源码 + 输出）：

   ```c
   #include <stdio.h>
   int main(void)
   {
       int a = -1;
       printf("%%d 打印 -1 = %d\n", a);
       printf("%%u 打印 -1 = %u\n", a);
       return 0;
   }
   ```
   ```
   %d 打印 -1 = -1
   %u 打印 -1 = 4294967295
   ```
   同一份数据：**老实写 `%d` → `-1`；错写成 `%u` → `4294967295`**（把 32 位当纯二进制全读一遍，就是 `2^32 - 1`）。
3. **`unsigned` 做减法会"绕回去"**：`unsigned char` 的 `0 - 1` = `255`，不是 `-1`。循环里写 `for (i = n; i >= 0; i--)`，如果 `i` 是 unsigned → **死循环**。

---

## 9. 复习题（答完再看答案）

1. 8 位二进制 `11111110`，当作补码是多少？当作纯二进制是多少？
2. `unsigned char u = 0; u = u - 1;` 之后 `u` 是多少？为什么？
3. 为什么做"移位"运算时要用 unsigned，而不是 int？

<details>
<summary>答案</summary>

1. 补码：`-2`（`2^8 - 2 = 254`，所以是 `-2`）；纯二进制：`254`。
2. `255`。因为无符号数没有负数，`0 - 1` 会绕到最大值（8 位就是 `2^8 - 1 = 255`）。
3. 因为有符号右移**左边补符号位**（负数会一直补 1），无符号**左边补 0** —— 做掩码/寄存器运算时必须"纯二进制"，不能被符号位污染。

</details>
