# L19 const 常量是什么 + else 永远跟最近的 if

- 日期：2026-09-21
- 来源：我的两个提问 —— ①「`const int` 是什么意思」②「else 总是与最近的 if 匹配，除非有大括号」（我的理解对不对？）
- 素材：翁恺《C语言程序设计》"缩进"那节课件 + 我的两个新程序（三值最大值、`READY` 状态判断）
- 标签：`#C语言` `#基础语法` `#常量` `#const` `#分支` `#else`

> **一句话总结**：
> **`const` = 给盒子上一把锁**——`const int READY = 24;` 意思是"一个装着 24 的 int 盒子，**只许看、不许改**"。
> **`else` 永远配"最近的那个还没配对的 `if`"**——缩进、换行、对齐，编译器**统统不看**；给内层 `if` 加 `{}` 就等于告诉编译器"这个 if 已经配完了"，`else` 才轮到外层。

## 一、`const int` 是什么意思

### 1. 拆开读

| 部分 | 含义 |
|---|---|
| `int` | 类型：一个整数盒子 |
| `const` | **constant（常量）的缩写**：只读、不许改 |

合起来：**"一个不能修改的 int"**。

### 2. 打比方

之前学过：**变量 = 贴了标签的盒子**（`int a = 10;` 是盒子里装 10）。
现在 **`const` 就是给这个盒子加一把锁**：

- 里面**装的东西还在**，你照样能**读**（`printf("%d", READY)` 没问题）；
- 但你**不能再往里塞新东西**——`READY = 25;` 会被编译器当场拦下。

### 3. 实测：改它会发生什么

```c
int main(void)
{
    const int READY = 24;
    READY = 25;          /* 想改常量 */
    return 0;
}
```

**gcc 报**：

```
error: assignment of read-only variable 'READY'
```

**VS（MSVC）报**（我在本机用 VS2026 的 cl.exe 实测）：

```
d_const_err.c(6): error C2166: 左值指定 const 对象
```

> 记住 **`C2166`**：以后在 VS 里看到它，就是"你在给常量赋值"。

### 4. 还有个细节：`const` 必须**定义时就给值**

```c
const int READY;         /* 只声明不给值 */
READY = 24;              /* 想事后补上 → 不行 */
```

实测报同一个错：`error: assignment of read-only variable 'READY'`。
**原因**：加了锁的盒子，**只能在造它的时候一次装好**，之后就没机会了。所以写法一定是：

```c
const int READY = 24;    /* ✅ 一句话搞定：类型 + 名字 + 值 */
```

（`const int X = 24;` 和 `int const X = 24;` 完全等价，位置随便你，习惯上前者。）

### 5. 为什么要用 `const`（不只是"好看"）

| 好处 | 说明 |
|---|---|
| **名字代替魔数** | 24、8.25、40 这些"丢在代码里的数字"叫**魔数**，看代码的人猜不出意思。写成 `READY`、`RATE`、`STANDARD` 就一目了然 |
| **改一处、处处生效** | 常量的值只写在定义那一行，以后要调整只改这一处，不怕漏 |
| **防手滑** | 程序跑着跑着把 `READY` 改成别的值？编译器直接拦住（C2166） |
| **意图清楚** | 别人一看 `const` 就知道"这是个不该变的值" |

我自己的工资程序里**已经用过一次**了：

```c
const double RATE = 8.25;      /* 时薪，不会变 */
const int STANDARD = 40;       /* 标准工时，不会变 */
```

**命名习惯**：常量名习惯**全大写**（`READY`、`RATE`、`STANDARD`）。这不是语法要求，是"一眼看出它是常量"的行业惯例。

## 二、`else` 到底是跟哪个 `if` 配对

### 1. 我的理解 ✅ 正确，但规则要说准

> **C 的规则**：`else` 跟**最近的、还没有配过对的 `if`** 配对。
> **缩进、换行、对齐，编译器全都不看**——翁恺课件原话就是"**缩进格式不能暗示 else 的匹配**"。

![[L19-课件 缩进不能暗示else匹配.png]]

### 2. 拿课件的例子 + 我的代码实测

我的代码（照课件写的，没有大括号）：

```c
const int REAADY = 24;          /* ← 注意这里拼错了，见第 4 小节 */
int code = 0;
int count = 0;

scanf("%d %d", &code, &count);
if (code == REAADY)
    if (count < 20)
        printf("一切正常\n");
    else
        printf("继续等待\n");
```

**AI 实测结果**（gcc，用管道喂输入）：

| 输入 code / count | 无大括号版（我的写法） | 加了大括号给外层 if |
|---|---|---|
| 24 / 5 | `一切正常` | `一切正常` |
| 24 / 25 | `继续等待` | `继续等待` |
| **99 / 5** | **什么都不打印** ⚠️ | `状态码不对（else 归外层 if）` |

**看第 3 行**：状态码不是 24（不符合外层条件）时，**程序一声不吭**——因为那个 `else` **属于内层 `if (count < 20)`**，外层条件不成立时内层根本没被执行，`else` 自然也轮不到。

**gcc 还当场警告**：

```
warning: suggest explicit braces to avoid ambiguous 'else' [-Wdangling-else]
```

"建议加显式大括号，避免 `else` 归属不明"——就是这个坑。

### 3. 为什么加了大括号就能解决

把内层 `if` 用 `{}` 括起来：

```c
if (code == REAADY)
{                                   /* ← 内层 if 被包进一个块里 */
    if (count < 20)
        printf("一切正常\n");
    else
        printf("继续等待\n");
}                                   /* ← 到这里为止，内层那个 if 已经"配完了" */
else                                /* ← 现在没有"最近未配对的 if"了，只能配最外层 */
{
    printf("状态码不对\n");
}
```

**原理**：`{ ... }` 让里面那一整块变成**一条语句**。编译器读到内层 `if` 时，它已经在块里跟自己的 `else` 配好了；等到外层 `else` 出现，往回找"最近未配对的 `if`"——只有外层那个 → 配对成功。

> **所以一句话记牢**：
> **`else` 找"最近的、还没配过对的 `if`"；`{}` 用来提前把内层 `if` 的配对结束掉。**

### 4. 顺手抓到的拼写错（第 9 次）🔴

```c
const int REAADY = 24;      /* ❌ 多了一个 A */
```

`READY`（准备好）→ 我写成了 `REAADY`。**因为声明和使用处拼得一样**，程序照样编译、照样跑——**但它是错的英文**，而且以后在别处写 `READY` 就会报"未声明的标识符"。

对比课件：课件里是 **`READY`**（R-E-A-D-Y）。

**这个坑比报错更危险：编译不报错的拼写错，只有自己一个字一个字核对才发现。**

## 三、我写的新程序：三值最大值（AI 穷举验证过 ✅）

![[L19-三值最大值程序（穷举验证）.png]]

```c
int main() {
    int a, b, c;
    int max = 0;
    printf("这是一个比较a b c 三个值大小的工具！\n");
    printf("请输入a,b,c的值:\n");
    scanf("%d %d %d", &a, &b, &c);
    if (a > b) {
        if (a > c) {
            max = a;
        }
        else {
            max = c;
        }
    }
    else {
        if (b < c) {
            max = c;
        }
        else {
            max = b;
        }
    }
    printf("最大值是%d", max);
    return 0;
}
```

### AI 的验证方式：**穷举**（不是只看几组）

我把这段逻辑抽出来，**把 a、b、c 从 -3 到 3 的所有组合（343 组）全部跑一遍**，再跟"标准算法"对比：

```
穷举 343 组，错 0 组
```

**0 组错 → 逻辑完全正确** ✅（这比"输入几组试试"强得多）

### 四条路径逐条核对

| 分支 | 条件 | 赋值 | 为什么对 |
|---|---|---|---|
| ① | `a > b` 且 `a > c` | `max = a` | a 比 b 大又比 c 大 → a 最大 ✅ |
| ② | `a > b` 且 `a <= c` | `max = c` | a 比 b 大、c 又不小于 a → 顺序是 `b < a <= c`，c 最大 ✅ |
| ③ | `a <= b` 且 `b < c` | `max = c` | `a <= b < c` → c 最大 ✅ |
| ④ | `a <= b` 且 `b >= c` | `max = b` | `a <= b` 且 `b >= c` → b 最大 ✅ |

**顺便表扬一句**：这个程序**每一层 `if`/`else` 都老老实实写了 `{}`**——这正是上一课"悬空 `else`"那个坑的**正解写法**。要是这里省了花括号，就会出现"`else` 跑到内层去"的灾难。

### 可以改进的小地方（都不影响正确性）

| 小点 | 说明 |
|---|---|
| `printf("最大值是%d", max);` 结尾缺 `\n` | 加 `\n`，输出更整洁 |
| `int a, b, c;` 没给初值 | 后面紧跟着 `scanf` 赋值，**可以**；但养成 `= 0` 的习惯更稳（万一 `scanf` 读失败，a/b/c 就是垃圾值） |
| `int max = 0;` 初值 | 这里四条路径**每一条都会给 max 赋值**，所以初值用不上；留着也无害（保险） |

## 四、复习题（先自己答）

1. `const int READY = 24;` 里的 `const` 是什么意思？用一句话（打比方也行）说清楚。
2. 下面这句为什么报错？正确写法是什么？
   ```c
   const int READY;
   READY = 24;
   ```
3. `else` 到底跟哪个 `if` 配对？缩进能不能改变它？
4. 想让外层 `if` 拥有那个 `else`，要做什么？为什么这么做就有效？
5. 为什么"拼错的变量名"（`REAADY`）比"语法错的代码"更危险？

> [!question]- 参考答案（先自己答完再点开）
>
> 1. `const` 是 **constant（常量）** 的缩写，表示**只读、不能修改**。比方：**给盒子加一把锁**——内容可以读，但不许再往里塞新东西。
> 2. 因为 **`const` 变量必须在定义时一次给好值**，加了锁的盒子只能在造它的时候装东西。正确：`const int READY = 24;`（报错原文：`error: assignment of read-only variable 'READY'` / VS 是 `error C2166: 左值指定 const 对象`）。
> 3. 跟**最近的、还没配过对的 `if`** 配对。**缩进完全不能改变它**——编译器不看缩进（翁恺课件原话："缩进格式不能暗示 else 的匹配"）。
> 4. **给外层 `if`（或内层 `if`）加 `{}`**。原理：`{}` 让里面那一整块成为**一条语句**，内层 `if` 在块里已经和自己的 `else` 配完了，外层 `else` 往回找"最近未配对的 `if`"时就只剩外层那个。
> 5. 因为**拼错的变量名如果"声明和使用处错得一样"，编译器和运行都不会报错**——程序正常跑，你完全察觉不到；等哪天在别处写对了（`READY`）反而报"未声明的标识符"，那时更难查。**编译不报错的错，只能靠人一个字一个字核对**（这也是我"反复拼错"红警要一直盯的原因）。

## 五、嵌入式视角

- **`const` 在单片机上不只是"好习惯"，是省钱**：`const` 修饰的常量表（比如查表用的正弦表、状态码表）编译器会放进 **Flash/ROM**，而不是宝贵的 **RAM**。STM32 那种 RAM 只有几十 KB 的芯片上，**把大数组加 `const` 能直接省下几 KB 的 RAM**——这几 KB 常常就是"程序跑不跑得起来"的分界。
- **`const` 是寄存器配置的常见做法**：外设的地址、位掩码、时钟分频系数，写成 `const` 常量，改配置时只改一处（和我工资程序里的 `RATE`、`STANDARD` 一个道理）。
- **`else` 匹配规则在中断/状态机里必须靠 `{}` 兜底**：状态判断常常是 `if (状态A) if (条件B) ... else ...` 这种两层套，**省花括号就是埋雷**。嵌入式编码规范直接要求"`if` 一律带 `{}`"，原因就是今天这个坑。
