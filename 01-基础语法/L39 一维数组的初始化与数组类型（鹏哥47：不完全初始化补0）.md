## 2. AI 实测（gcc 13.1 `-Wall -Wextra` 0 警告；MSVC 专门验错误码）

### ① 不完全初始化 —— 剩余自动补 0

```c
int arr[5]  = {1, 2, 3, 4, 5};   /* 完全初始化 */
int arr2[6] = {1};               /* 不完全初始化 */
int arr4[]  = {1, 2, 3, 4};      /* 方括号不写数字，编译器自己数 */
```
```
arr  : 1 2 3 4 5
arr2 : 1 0 0 0 0 0        ← 命门：剩下的 5 格自动是 0
arr4 : 1 2 3 4
sizeof(arr)=20  sizeof(arr[0])=4  count=5
sizeof(int[10])=40   sizeof(arr2)=24   sizeof(arr4)=16
```

> [!important] 两种"没初始化"必须分清
> - 写了 `= {1}` 但格子没填满 → **剩下的补 0**（标准规定）
> - **完全没写** `= {...}` → **垃圾值**（L38 踩过：`int math[20];`）
>
> 这两件事不一样！他以前把"垃圾值"当成所有情况，今天这条是修正。

### ② 两种错误写法：VS 拦得住，gcc 只嘀咕

| 写法 | VS2026 `cl /W3` | gcc 13.1 |
|---|---|---|
| `int arr3[3] = {1,2,3,4};` | **error C2078: 初始值设定项太多** | 默认只 **warning** `excess elements in array initializer`；加 `-pedantic-errors` 才 error |
| `int arr5[] = (1,2,3,4);` | **error C2075: "arr5" 初始化需要带括号的初始化表达式列表** | **error** `invalid initializer`（外加 3 条逗号表达式无效果的警告） |

**教学点**：同一个错，**换个编译器命运不同**。gcc 会把第 4 个数**丢掉**照样编译成功 —— 这就是"编译过 ≠ 对"的又一个活例子。

### ③ 数组类型是真类型（不是玄学）

```c
printf("sizeof(int[10])=%zu\n", sizeof(int[10]));   /* → 40 */
```
`int[10]` 能直接塞进 `sizeof` 算出 40 = 10×4 → 编译器把它当**和 `int` 平级的完整类型**。
现在看着没用，**学"数组指针 `int (*p)[10]`"时是救命的**。

## 3. 讲评（2026-10-31，他答卷）

### Q1 `int a[10] = {5};` → `a[0]`、`a[9]`？
他答 **「5，0」** ✅ **满分**（补 0 规则吃透了）

### Q2 哪几行错
```c
int x[4] = {1,2,3,4,5};   /* 错 */
int y[4] = {1,2,3,4};     /* 对 */
int z[4] = (1,2,3,4);     /* 错 */
int w[]  = {1,2,3,4};     /* 对 */
```
他答 **「1，3行错了，1元素超了，3用了圆括号应该用花括号」** ✅ **满分**（两个错的都点了，理由都对）

### Q3 `char s[6] = {'h','i'};` → `s[2]`？
他答 **「0」** ✅ **正确**（是**数字 0**；当字符看是 `'\0'` → 顺带一句：这正是 C 字符串的结尾符，L57 字符串课会用到）

### 🔸 抽查 2（`sizeof` 求元素个数）—— **⚠️ 半对，且他随后自己修正了，但修正版仍差最后一步**

**第一版原话**：「一个 int 占用 4 个字节，**只要用 sizeof 测量这个数组，结果是几个字节，就有几个元素**」

- **对的一半 ✅**：知道 `sizeof(数组)` 给的是**总字节数**，也知道 `int` 是 4 字节。
- **错的一半 ❌**：**没除以"一个元素占几字节"**。`sizeof(a)` 是 20，元素数是 **20 ÷ 4 = 5**，不是 20。
- **他那套只在 `char` 数组上碰巧成立**（char 是 1 字节，字节数 == 个数）。

**他当场自我修正（2026-10-31 原话）**：「结果是 4 的多少倍数，就是几个元素」
→ **思路对了 ✅**（终于想到要除），**但除数写死成 4，等于只对 `int` 数组成立 ❌**：

```
sizeof(a)=20  a[0]=4  -> 5 个      int    a[5] : 20/4 = 5   ✅ 他这套对
sizeof(b)=24  b[0]=8  -> 3 个      double b[3] : 24/4 = 6   ❌ 他这套错（实际 3 个）
sizeof(c)=6   c[0]=1  -> 6 个      char   c[6] : 6/4  = 1.5 ❌ 他这套错
```

**结论口诀**：**`sizeof(a) / sizeof(a[0])`** —— 总字节 ÷ 一个元素的字节。分母必须是 `sizeof(a[0])`，**不能写死 4**，否则换类型立刻错。

### 🔸 他的追问（2026-10-31）：「`a[0]` 不是没有元素吗」—— 已讲透，记池 **C7**

**他的误解**：`sizeof(a[0])` 里的 `a[0]` 没赋过值 → 以为是个"空的东西"，空的东西怎么还能量出 4？

**真相两条**：

1. **C 的格子没有"空"这个状态。** 每个 `int` 格子永远是 32 个比特，要么装着**垃圾值**、要么装着 **0**、要么装着你放的值。不存在"还没装"的中间态。
2. **`sizeof` 量的是"格子多大"，不是"里面装什么"。** 它看的是**类型**，跟值完全无关。`a[0]` 的类型永远是 `int` → 永远 4 字节。

**打比方**：`sizeof` 是一把**量快递柜尺寸的卷尺**，它不打开柜门。空柜子、满柜子、装满垃圾的柜子，量出来尺寸一模一样。

**实测铁证（gcc 13.1，见下）**：

```
a[0] 里面装的值   = -1661165728   （一格都没初始化 = 垃圾值）
sizeof(a[0])      = 4             ← 量的是"格子多大"，不是"里面装什么"
arr[0]=5  arr[1]=0  sizeof(arr[0])=4  sizeof(arr[1])=4     ← 装了 5 的和装了 0 的，一样大
sizeof(a[1000])   = 4             ← 下标越界 1000 都不崩！
```

**最后一行是关键铁证**：`a` 只有 5 格，写 `a[1000]` 是越界的，可 `sizeof(a[1000])` **照样算得出 4、也不崩** —— 因为 `sizeof` 是**编译期**就把结果算好的，**根本不读内存**。（对照：真的去 `printf("%d", a[1000])` 就是读了野内存，行为不定。）

## 4. 一句话总结

> **`= {…}` 填不满 → 剩下自动 0；完全不给 `= {…}` → 垃圾值。求个数永远是 `sizeof(a)/sizeof(a[0])`，不能拿字节数当个数。**

## 6. 嵌入式钩子 🔌

```c
uint8_t buf[8];          /* 8 字节缓存：垃圾值，读出来什么都有 */
uint8_t buf2[8] = {0};   /* 全 0 —— 写串口接收/帧解析该用这个 */
```

`{0}` 的威力就是今天 ② 那条规则：**只写了 1 个 0，剩下 7 格自动补 0**。
写 UART 接收、环形缓冲、帧缓存时，**90% 的"数据莫名其妙"是忘了 `= {0}`**，读到了上一轮的残留。

另外 `uint8_t seg[] = {0x3F, 0x06, ...};`（七段数码管字形表）用**方括号留空**最省事 —— 改表不用自己数个数。
