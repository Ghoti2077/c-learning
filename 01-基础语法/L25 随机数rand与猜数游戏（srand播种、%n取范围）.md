# L25 随机数 `rand()` 与猜数游戏

- 日期：2026-09-21
- 来源：翁恺《C语言程序设计》随机数（课件 2 张）+ 我自己写的猜数游戏
- 我的理解（原话）：「要使用 rand 需要 `#include <stdlib.h>` `#include <time.h>`」
- 标签：`#C语言` `#基础语法` `#随机数` `#rand`

> **一句话总结**：
> **`rand()` 每次调用返回一个伪随机整数**（要 `#include <stdlib.h>`）；
> **`srand(种子)` 决定这串数的起点**——不播种，程序每次运行都是**同一串**；
> 想要"每次都不同"，用 **`srand(time(0))`**（`time` 要 `#include <time.h>`）。
> **范围要自己截**：`x % n` 得到 `[0, n-1]`，所以 **1~100 → `rand() % 100 + 1`**。

> **现在只要会"照着用"**：两个 `#include`、开头一句 `srand((unsigned)time(NULL));`、要 1~100 就写 `rand() % 100 + 1`。

## 1. 课件：rand 与 %n

![[L25-课件 随机数 rand.png]]

![[L25-课件 x%n 的结果范围.png]]

**`x % n` 的结果是 `[0, n-1]` 的一个整数** —— 这条 L23 已经学过，现在拿来"切"随机数的范围：

| 想要的范围 | 写法 | 说明 |
|---|---|---|
| 0 ~ 99 | `rand() % 100` | 100 个数：0…99 |
| **1 ~ 100** | `rand() % 100 + 1` | 整体加 1 ✅（**他写对了**） |
| 1 ~ 6（骰子） | `rand() % 6 + 1` | 经典写法 |

## 2. 我的理解核对：两个头文件到底谁管谁

| 我说的 | 判定 | 精确说法 |
|---|---|---|
| 用 `rand` 要 `#include <stdlib.h>` | ✅ 对 | **`rand()` / `srand()` 都声明在 `<stdlib.h>`**，必须包含 |
| 用 `rand` 要 `#include <time.h>` | ⚠️ **不完整** | **`<time.h>` 是给 `time()` 用的**——只在你用 `srand(time(0))` 播种时才需要。**不播种就只调 `rand()`，可以不写 `<time.h>`**（但不播种每次运行都是同一串数，见下） |

**记法**：**`stdlib` 管随机函数，`time` 管时间函数**；`srand(time(0))` 里两样都用上了，所以两个头文件都写。

## 3. 实测：不播种 vs 播种（最关键的一条）

| 程序 | 连续跑两次的结果 | 说明 |
|---|---|---|
| **不播种**，直接 `rand() % 100 + 1` | `42 68 35 1 70`<br>`42 68 35 1 70` | **一模一样！** 不播种时每次运行都是同一串"随机"数 |
| **`srand(time(0))` 后** | `79 67 56 58 45`（间隔 2 秒后再跑）<br>`86 64 16 17 74` | **不一样** ✅ 每次运行都不同 |

**为什么**：`rand()` 是**伪随机**——它其实是一个固定公式，`种子`是唯一的输入。种子不变，整串数就不变。

**打比方**：`rand()` 像一本**印好的厚书**，一页页往下翻；`srand(种子)` 是**决定从第几页开始翻**。
不给种子（= `srand(1)`），每次**都从第一页开始** → 你看到的永远是同一串；给个每次都不同的种子（当前时间），**起点就不同**。

### 顺带实测出的事实

- **这台机器（MSVC/Windows 环境）`RAND_MAX = 32767`** —— 即 `rand()` 最大就 32767。
  （所以 `rand() % 100` 是从 0~32767 里取余；不同平台的 `RAND_MAX` 可能不同，别硬编码这个数。）
- `rand() % 100 + 1` 的范围**实测 20 万次**：最小 **1**、最大 **100**、1~100 **无一个漏掉**（1 出现 2021 次、100 出现 1976 次）✅

## 4. ⚠️ 经典坑：`srand` 只能播一次，不能放循环里

```c
for (int i = 0; i < 5; i++) {
    srand(time(0));              /* ← 错：播种放循环里了 */
    printf("%d ", rand() % 100 + 1);
}
```

**实测输出**：`53 53 53 53 53` —— **五个数完全一样**。

**为什么**：`time(0)` 返回的是**秒**，一秒钟以内它不变 → 每一轮都播**同一个种子** → 每轮都从"同一页"开始 → 拿到的数当然一样。

**正确做法**：`srand(time(0));` **写在程序开头，只播一次**，之后随便调 `rand()`。

## 5. 我的猜数游戏核对

![[L25-我的猜数游戏代码.png]]

```c
int main() {
    srand(time(0));
    int number = rand() % 100 + 1;
    int count = 0;
    int a = 0;
    printf("我已经想好了一个1到100之间的数。");
    do {
        printf("猜猜这个1到100之间的数：");
        scanf("%d", &a);
        count++;
        if (a > number) {
            printf("你猜大了");
        } else if (a < number) {
            printf("你猜小了");
        }
    } while (a != number);
    printf("恭喜你猜对了。一共用了%d次\n", count);
    return 0;
}
```

### ✅ 写对的地方

| 点 | 判定 |
|---|---|
| `srand(time(0));` 写在开头、**只有一次**（没放进循环） | ✅ 完全正确，坑避开了 |
| `rand() % 100 + 1` → 1~100 | ✅ 范围对（第 1 节表） |
| **用 `do-while`**：先问一次再判断"猜中没有" | ✅ **L24 学的正好用上了**（"循环体至少做一次"） |
| `a > number` / `a < number` 分支提示 | ✅ 逻辑对 |
| `count++` 每轮计数 | ✅ 位置对（读入之后加，猜一次算一次） |
| 猜中的那次循环结束（`a != number` 不成立） | ✅ 结构对 |

```

```

→ **从 1 猜到 39 正好用 39 次**，计数与循环退出条件**完全正确** ✅（逻辑通得过实测）

### ⚠️ 需要改的地方

| 问题 | 说明 |
|---|---|
| **VS 报「警告 1」：`C4244 从 time_t 转换到 unsigned int 可能丢失数据`（行 232）** | 64 位 `time_t` 塞进 `srand` 要的 32 位参数。**不影响随机效果，但警告要消掉** |
| **修法（实测有效）**：`srand((unsigned)time(NULL));` | 加了显式转换 `(unsigned)` 后，MSVC **`/W3` `/W4` 都不再报 C4244**（我本机用 cl.exe 实测过） |
| **3 条提示语结尾都漏 `\n`**（`"…之间的数。"`、`"你猜大了"`、`"你猜小了"`） | → 第 **5** 次了（L17/L20/L21/L23/L25），已升红警。**正好最后一句又带了 `\n`** ——提示语和最后一句要分别盯 |
| `int a = 0;` 其实不必初始化 | `do-while` 里第一件事就是 `scanf`，`a` 一定会先被赋值。**但保留初始化是好习惯**，不用改 |
| 💡 提醒（先记住，不展开）：输入不是数字时（比如打了个字母），`scanf` 会失败并且**一直失败**；`a` 保持旧值 → 有可能变成死循环 | 以后学 `scanf` 返回值时再回来处理 |

1. 用 `rand()` 需要 `#include` 哪个头文件？用 `time()` 呢？
2. 为什么"不播种"的程序每次运行结果都一样？打个比方说明。
3. 要得到 **1~100** 的随机整数怎么写？为什么是 `% 100 + 1` 而不是 `% 100`？
4. `srand(time(0));` 为什么不能写在循环里面？
5. 我这版猜数游戏的 `do-while` 能不能改成 `while`？改了要注意什么？

> [!question]- 参考答案（先自己答完再点开）
>
> 1. `rand()`/`srand()` 要 **`<stdlib.h>`**；`time()` 要 **`<time.h>`**（不用 `time` 就不用写）。
> 2. 因为 `rand()` 是**伪随机**：一串固定公式算出来的数，公式的输入就是"种子"。不播种时种子固定（等于 `srand(1)`），所以每次运行都是从同一页开始翻的书。**打个比方：书是印好的，每次从头开始翻。**
> 3. `rand() % 100 + 1`。因为 `x % n` 得到的是 `[0, n-1]`，即 `% 100` 只给 **0~99**，整体加 1 才是 **1~100**。
> 4. 因为 `time(0)` 返回的是**秒**，一秒内不变；循环里反复播种，每次都播同一个种子 → 每轮都得到同一个数（实测 `53 53 53 53 53`）。**播种只在开头做一次。**
> 5. 能，但 `while` 是**先判断后执行**：第一遍进循环前 `a` 还没从键盘读到（只有初始化值 0），`a != number` 大概率成立所以能进——**但语义上就错了**（应该是"先猜一次，再判断"）。要改就得在循环前**先手动读一次**（跟 L23 那两行"先手动做一遍"一模一样的道理）。**所以这里用 `do-while` 才是正解。**

## 7. 嵌入式视角

- **单片机上一般没有 `rand()`**（它依赖标准库/操作系统环境）。嵌入式里要伪随机，常用 **LFSR（线性反馈移位寄存器）** 或者 CRC 表，几十行就能实现，占 RAM 极小。
- **`rand()` 是伪随机、可预测**：知道种子就能算出整串数 —— 所以**绝对不能用在密码、加密、抽奖这类场合**（这叫"安全随机"，需要硬件 RNG）。
- **真随机在嵌入式里怎么来**：芯片内置 **硬件 RNG 寄存器**（STM32/GD32 都有 TRNG/RNG 外设），或者用 **ADC 采噪声**、**未连接引脚的电平抖动**、**晶振启动时间抖动**当种子。
- **`srand(time(0))` 在嵌入式里常常不成立**：没有 RTC 就没有真实时间，种子只能取**上电计数器的值**或**硬件 RNG** —— 所以有些单片机每次上电的"随机数"其实都一样。
- **猜数游戏这类"交互 + 循环 + 分支"的结构**，在嵌入式里对应的是**状态机**：读输入 → 判断 → 给反馈 → 未完成就再来一轮。
